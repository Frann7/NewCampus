10. Tres herramientas del sitio de ejemplo

El sitio de ejemplo que la cátedra da con la práctica (site.zip) usa tres cosas que el apunte teórico no explica. Van acá, antes de que aparezcan en la práctica:

$_SERVER["REQUEST_METHOD"]: por qué método llegó

$_SERVER es otro arreglo superglobal: PHP lo llena con datos del servidor y de la solicitud. La clave "REQUEST_METHOD" tiene el método, en mayúsculas: "GET" si se pidió la URL (o se envió un formulario GET), "POST" si se envió un formulario POST. 

if ( $_SERVER["REQUEST_METHOD"] == "POST" ) {
    ... leer de $_POST ...
}

Ejemplo 1 — Responder según el método

<?php
if ( $_SERVER["REQUEST_METHOD"] == "POST" ) {
    echo "Llegó por POST";
} else {
    echo "Llegó por GET";
}
?>
CasoValor de $_SERVER["REQUEST_METHOD"]Qué rama ejecutaQué imprime
Se escribe la dirección en la barra (o se envía un formulario GET)"GET"el elseLlegó por GET
Se envía un formulario con method="post""POST"el ifLlegó por POST

Verificado pidiendo el script por GET y por POST al servidor de PHP. Sirve para que el script no intente leer $_POST cuando alguien lo abre directamente desde la barra.

htmlspecialchars(): mostrar lo que escribió el usuario

Si el script devuelve tal cual lo que el usuario escribió, y el usuario escribió etiquetas (<b>, o peor, <script>), el navegador las ejecuta como parte de la página. htmlspecialchars() recibe un string y devuelve otro en el que los caracteres especiales de HTML están reemplazados por su entidad: un código que el navegador muestra como el carácter, pero no interpreta como etiqueta.

Ejemplo 2 — ¿Cuál es la salida? (formato parcial)

Un formulario POST manda en el campo comentario el texto <b>Hola</b> & chau.

<?php
$comentario = $_POST['comentario'];
echo "Sin proteger: " . $comentario . "\n";
echo "Con htmlspecialchars: " . htmlspecialchars($comentario);
?>
LíneaQué haceCómo quedan las variables
2Guarda el dato recibido$comentario = "<b>Hola</b> & chau"
3Lo imprime tal cual, concatenado (.) con un rótulo y un salto de línea \n—
4Lo imprime pasado por htmlspecialchars()el string devuelto es &lt;b&gt;Hola&lt;/b&gt; &amp; chau

Qué imprime (el texto que manda PHP)

Sin proteger: <b>Hola</b> & chau
Con htmlspecialchars: &lt;b&gt;Hola&lt;/b&gt; &amp; chau

Qué se ve en el navegador

  • En el primer renglón, Hola sale en negrita: el navegador interpretó el <b> como etiqueta.
  • En el segundo se lee literalmente <b>Hola</b> & chau, con los signos a la vista: el navegador convirtió cada entidad en su carácter y no interpretó nada.

Salida verificada mandando ese POST al servidor de PHP.

require_once: la página armada con pedazos

En un sitio, todas las páginas comparten el mismo encabezado, menú y pie. En vez de copiarlos en cada archivo, se escriben una vez en archivos aparte y se incluyen. require_once 'archivo.php'; hace exactamente eso: pega el contenido de ese archivo en ese punto, como si estuviera escrito ahí (si tiene HTML, sale el HTML; si tiene PHP, se ejecuta).

  • require: si el archivo no existe, es un error fatal y el script se corta.
  • _once: si ese archivo ya se incluyó antes, no lo vuelve a incluir.

Ejemplo 3 — Una página con encabezado y pie

Dos archivos chicos en la carpeta includes:

<!-- includes/encabezado.php -->
<h1>Mi sitio</h1>

<!-- includes/pie.php -->
<p>Pie de pagina</p>

Y la página:

<?php require_once 'includes/encabezado.php'; ?>
<p>Contenido de esta página</p>
<?php require_once 'includes/pie.php'; ?>
<?php require_once 'includes/pie.php'; ?>

Verificado con php.exe: el pie sale una sola vez. Y si el archivo pedido no existe, PHP muestra "Failed opening required" como error fatal y no ejecuta nada de lo que sigue.

Errores y trampas

Lo que suele salir mal
  • "post" en minúsculas. $_SERVER["REQUEST_METHOD"] siempre viene en mayúsculas; compararlo con "post" da falso aunque el formulario diga method="post".
  • htmlspecialchars() no cambia la variable. Devuelve un string nuevo; hay que usar lo que devuelve (en el echo o guardándolo).
  • Las rutas de require_once se cuentan desde la carpeta del script que se pidió. Si la página está en otra carpeta, 'includes/head.php' ya no se encuentra.
