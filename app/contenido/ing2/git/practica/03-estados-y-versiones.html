Ejercicio 3 · Estados y versionado

En qué estado está y qué versión sigue

Parte A. En un proyecto con Git se ejecuta git status --short y responde: 

M  carrito.js
 M pagos.js
?? notas.txt

¿En qué estado está cada archivo? ¿Qué entraría en el commit si ahora se ejecuta git commit -m "Cambios"?

Parte B. Un sistema usa versionado semántico y está en la versión 1.7.3. Indique el número de versión después de cada cambio, en este orden: 1) se corrige un error de redondeo; 2) se agrega la exportación a PDF; 3) se corrige un error en esa exportación; 4) se rediseña la forma de conectarse y los sistemas que lo usaban tienen que modificarse.

Paso 1 — Parte A: leer las dos columnas

git status --short muestra dos columnas de letras antes del nombre. La primera es el área de preparación; la segunda, el directorio de trabajo (Teoría, sección 2).

LíneaDónde está la letraEstado¿Entra en el commit?
M  carrito.jsPrimera columnaPreparado: ya se le hizo git addSí
 M pagos.jsSegunda columnaModificado: se cambió, pero no se preparóNo
?? notas.txt—Sin seguimiento: es nuevo y Git no lo conoceNo

git commit guarda solo lo que está en el área de preparación. Para que entren los otros dos, antes hay que hacer git add pagos.js notas.txt (o git add .).

Paso 2 — Parte B: una pregunta por cambio

Para cada cambio: ¿rompe la compatibilidad? → MAYOR. Si no: ¿agrega funcionalidad? → MENOR. Si no: es una corrección → PARCHE. Y lo que está a la derecha del número que sube vuelve a 0.

—Punto de partida——1.7.3
1Se corrige un error de redondeoCorrección compatiblePARCHE1.7.4
2Se agrega la exportación a PDFFuncionalidad nueva, compatibleMENOR; el PARCHE vuelve a 01.8.0
3Se corrige un error en esa exportaciónCorrección compatiblePARCHE1.8.1
4Se rediseña la conexión y los sistemas que lo usaban deben modificarseCambio incompatibleMAYOR; MENOR y PARCHE vuelven a 02.0.0
Respuesta

A. carrito.js está preparado (en el área de preparación), pagos.js está modificado (solo en el directorio de trabajo) y notas.txt es un archivo nuevo sin seguimiento. El commit incluiría únicamente carrito.js.

B. 1.7.3 → 1.7.4 → 1.8.0 → 1.8.1 → 2.0.0.

El error de la parte B

Poner 1.8.4 en el paso 2 (sin reiniciar el parche) o 2.8.1 en el paso 4 (sin reiniciar los otros dos). Cada vez que sube un número, todo lo que está a su derecha vuelve a cero.
