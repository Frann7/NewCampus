3. Leer una clase en C++

Para qué sirve

En el parcial no hay que escribir C++: hay que leer un código y decir qué patrón implementa y qué elementos lo delatan. Para eso alcanza con reconocer las piezas de una clase. Esta sección muestra una clase completa y la desarma.

Sintaxis

class Nombre {
 private:
  Tipo atributo_;

 public:
  Nombre(Tipo parametro) : atributo_(parametro) {}

  TipoQueDevuelve metodo(Tipo parametro) {
    // código
  }
};

Ejemplo 1 — La clase Cuenta, del diagrama al código

Es la misma clase que se dibujó en la sección 1:

El programa, en 5 partes. Los números de la izquierda son los renglones del programa completo; los renglones resaltados son los que hay que mirar.

1Las bibliotecas

#include <iostream>
#include <string>

Lo que el programa trae de afuera: iostream para mostrar por pantalla y string para los textos.

2La clase y sus atributosprivado

class Cuenta {
 private:
  std::string titular_;
  double saldo_;

Empieza la clase. Debajo de private: van los dos datos que guarda cada cuenta: nadie de afuera los puede tocar.

3El constructorpúblico

 public:
  Cuenta(std::string titular, double saldo) : titular_(titular), saldo_(saldo) {}

Se llama igual que la clase. Recibe dos datos y los guarda en los dos atributos.

4Los métodospúblico

  void depositar(double monto) {
    saldo_ = saldo_ + monto;
  }

  double saldo() const {
    return saldo_;
  }
};

Lo que una cuenta sabe hacer: sumar un monto al saldo y decir cuánto saldo tiene. La llave con punto y coma del final cierra la clase.

5El programa

int main() {
  Cuenta c("Ana", 100);
  c.depositar(50);
  std::cout << c.saldo() << "\n";
  return 0;
}

Acá arranca la ejecución: crea una cuenta, le deposita y muestra el saldo.

Qué hace cada línea

LíneaQué haceCómo quedan los datos
class Cuenta {Empieza la definición de la clase. Todavía no existe ninguna cuenta.—
private: y los dos atributosCada cuenta va a guardar un texto (titular_) y un número (saldo_), y nadie de afuera los puede tocar.—

Qué imprime y por qué

150

La cuenta se creó con 100 y se le depositaron 50.

Ejemplo 2 — static: algo que es de la clase y no de cada objeto

Un atributo común tiene una copia por objeto: cada cuenta tiene su saldo. Un atributo static tiene una sola copia para toda la clase, compartida por todos los objetos. En el diagrama va subrayado. Es la pieza principal del patrón Singleton.

El programa, en 5 partes. Los números de la izquierda son los renglones del programa completo; los renglones resaltados son los que hay que mirar.

1Las bibliotecas

#include <iostream>
#include <string>

2Los atributos: uno común y uno estático

class Alumno {
 private:
  std::string nombre_;
  static int cantidad_;

nombre_ es de cada alumno. cantidad_ lleva static: hay uno solo para toda la clase.

3El constructor y el método estático

 public:
  Alumno(std::string nombre) : nombre_(nombre) {
    cantidad_ = cantidad_ + 1;
  }

  static int cantidad() {
    return cantidad_;
  }
};

Cada vez que se crea un alumno, el constructor suma 1 al contador compartido. cantidad() también es static: se puede llamar sin tener ningún alumno.

4El valor inicial del atributo estático

int Alumno::cantidad_ = 0;

Va afuera de la clase y afuera de main. No es una asignación: empieza con el tipo (int), así que es la línea que crea el contador, una sola vez, con su valor inicial. Alumno:: se lee "de la clase Alumno". Está explicada abajo, después de la salida.

5El programa

int main() {
  std::cout << Alumno::cantidad() << "\n";
  Alumno a("Ana");
  Alumno b("Luis");
  std::cout << Alumno::cantidad() << "\n";
  return 0;
}

Muestra el contador, crea dos alumnos y lo vuelve a mostrar.

Qué hace cada línea

LíneaQué haceCómo quedan los datos
static int cantidad_;Declara un atributo de la clase: un solo contador para todos los alumnos.—
Alumno(std::string nombre) : nombre_(nombre) { cantidad_ = cantidad_ + 1; }El constructor: guarda el nombre y, cada vez que se crea un alumno, suma 1 al contador compartido.—
static int cantidad() { ... }Un método de la clase: se puede llamar sin tener ningún objeto.—
int Alumno::cantidad_ = 0;Crea el atributo estático y le da su valor inicial, antes de que arranque main. Se escribe afuera de la clase; Alumno:: se lee "de la clase Alumno".cantidad_ = 0
std::cout << Alumno::cantidad() ...Llama al método estático con Clase::metodo(), sin objeto. Todavía no se creó ningún alumno.cantidad_ = 0
Alumno a("Ana");Crea un alumno: corre el constructor.cantidad_ = 1
Alumno b("Luis");Crea otro: corre el constructor de nuevo, sobre el mismo contador.cantidad_ = 2
std::cout << Alumno::cantidad() ...Muestra el contador.cantidad_ = 2

Qué imprime y por qué

0
2

Los dos alumnos sumaron sobre el mismo cantidad_ porque es de la clase. Si no fuera static, cada alumno tendría el suyo.

El punto y los dos puntos dobles: a quién se le pide

Se escribeA la izquierda vaQué quiere decirEjemplo
objeto.algoUn objeto"Pedile esto a este objeto": trabaja con los datos de ese objeto.c.depositar(50): deposita en la cuenta c, no en otra
Clase::algoEl nombre de una clase"El algo que está adentro de esa clase". No nombra ningún objeto.Alumno::cantidad(): el cantidad() de la clase Alumno

Un método común necesita saber sobre qué objeto trabaja: depositar(50) solo no alcanza, falta decir en cuál de todas las cuentas. Por eso va con un objeto y un punto. Un método static no usa los datos de ningún objeto (cantidad() devuelve el contador, que es de la clase), así que no hay objeto que nombrar: alcanza con decir de qué clase es. Eso son los ::.

Los :: no son algo exclusivo de static: siempre quieren decir "el que está adentro de". En std::string es lo mismo: "el string que está adentro de std", la biblioteca estándar.

C++ también deja llamar a un método estático con un objeto (a.cantidad() compila y da lo mismo), pero no se escribe así: hace creer que la cantidad es de Ana. Con un puntero a un objeto, en lugar del punto va una flecha, p->algo (sección 4).

Por qué int Alumno::cantidad_ = 0; puede tocar algo privado

Parece que desde afuera de la clase se le está cambiando el valor a un atributo privado. No es eso. Un atributo estático se escribe en dos lugares:

LíneaDónde vaQué hace
static int cantidad_;Adentro de la claseLa declaración: avisa que la clase tiene ese atributo. Todavía no existe ningún contador.
int Alumno::cantidad_ = 0;Afuera de la clase y de toda funciónLa definición: crea el contador, una sola vez y antes de que arranque main, y le pone su primer valor.

Hace falta porque un atributo común nace con cada objeto, y su valor inicial lo pone el constructor. El estático no es de ningún objeto: si no se lo crea con esta línea, no lo crea nadie. Como la línea está afuera de las llaves de la clase, hay que decir de qué clase es ese cantidad_: por eso el Alumno:: adelante. Si se la olvida, el programa no llega a armarse: 

undefined reference to `Alumno::cantidad_'

private controla quién usa el atributo. La definición no lo usa desde afuera: es la clase terminando de escribirse, como si esa línea siguiera adentro de las llaves. Usarlo desde afuera sigue prohibido. Las dos líneas se parecen, pero la primera empieza con el tipo y la segunda no:

LíneaDónde estáQué es¿Compila?
int Alumno::cantidad_ = 0;Suelta, afuera de toda funciónLa definición del atributoSí
Alumno::cantidad_ = 5;Adentro de mainUna asignación, desde afuera, a algo privadoNo 'int Alumno::cantidad_' is private within this context

Las dos cosas son propias de lo static: los atributos comunes no llevan esa línea de afuera, y los métodos comunes no se llaman con el nombre de la clase.

La misma notación en un código de la cátedra

El Singleton de la guía de patrones (Práctica de la Unidad 4A, ejercicio 1) tiene estas tres líneas. Son las que delatan al patrón:

LíneaCómo se lee
Inicio_Serie* Inicio_Serie::Inicio_Serie_ = nullptr;La definición de un atributo estático, igual que int Alumno::cantidad_ = 0;. El tipo es Inicio_Serie* (un puntero a un objeto de la clase), el atributo se llama Inicio_Serie_, es de la clase Inicio_Serie y arranca en nullptr (vacío: todavía no hay objeto).
Inicio_Serie *Inicio_Serie::GetInstance(const std::string& value) { ... }Un método escrito afuera de la clase: adentro solo está declarado, y acá va su código. Es el otro uso de Clase:: fuera de las llaves: "el GetInstance de la clase Inicio_Serie".
Inicio_Serie::GetInstance("FOO");La llamada a un método estático, con la clase y sin objeto, igual que Alumno::cantidad().

Errores y trampas

Punto y dos puntos dobles no son lo mismo

c.depositar(50): el punto le pide algo a un objeto.
Alumno::cantidad(): los dos puntos dobles le piden algo a la clase. Si en un código ves Clase::algo(), ese algo es estático.

Lo privado no se toca desde afuera

Si en main se escribe c.saldo_ = 1000; el programa ni siquiera compila:

error: 'double Cuenta::saldo_' is private within this context

Esto importa en los patrones: un constructor privado hace que nadie de afuera pueda crear objetos de esa clase. Es la otra mitad del Singleton.

Nombres con guion bajo y repetidos

En los códigos de los parciales los atributos terminan en guion bajo y a veces se llaman igual que su clase: Facturacion *Facturacion_; es un atributo llamado Facturacion_ cuyo tipo es Facturacion. El primero es el tipo; el segundo, el nombre.
