Ejercicio 1 · Singleton

Reconocer el patrón en un código C++

Guía N°1, ejercicio 2. Dado el siguiente código identifique qué tipo de patrón se implementa y realice el diagrama correspondiente. 

class Inicio_Serie
{
protected:
    Inicio_Serie(const std::string value): value_(value)
    {
    }
    static Inicio_Serie* Inicio_Serie_;
    std::string value_;
public:
    Inicio_Serie(Inicio_Serie &other) = delete;
    void operator=(const Inicio_Serie &) = delete;
    static Inicio_Serie *GetInstance(const std::string& value);
    void SomeBusinessLogic()
    {
    }
    std::string value() const{
        return value_;
    }
};
Inicio_Serie* Inicio_Serie::Inicio_Serie_= nullptr;;
Inicio_Serie *Inicio_Serie::GetInstance(const std::string& value)
{
    if(Inicio_Serie_==nullptr){
        Inicio_Serie_ = new Inicio_Serie(value);
    }
    return Inicio_Serie_;
}
void ThreadFoo(){
    std::this_thread::sleep_for(std::chrono::milliseconds(1000));
    Inicio_Serie* Inicio_Serie = Inicio_Serie::GetInstance("FOO");
    std::cout << Inicio_Serie->value() << "\n";
}
void ThreadBar(){
    std::this_thread::sleep_for(std::chrono::milliseconds(1000));
    Inicio_Serie* Inicio_Serie = Inicio_Serie::GetInstance("BAR");
    std::cout << Inicio_Serie->value() << "\n";
}
int main()
{
    std::cout <<"Si ves el mismo valor, entonces fue exitoso (¡genial!\n" <<
                " Si ves un valor diferente entonces esta incorrecto(booo!!)\n" <<
                "RESULT:\n";
    std::thread t1(ThreadFoo);
    std::thread t2(ThreadBar);
    t1.join();
    t2.join();
    return 0;
}
Paso 1 — No asustarse con el nombre ni con los hilos
  • La cátedra cambia los nombres para que no se reconozca el patrón por el nombre de la clase: acá se llama Inicio_Serie. Hay que mirar la forma.
  • std::thread, sleep_for y join son hilos: dos partes del programa que corren a la vez. Para reconocer el patrón alcanza con leerlo así: "ThreadFoo y ThreadBar son dos funciones que piden la instancia, una con el texto FOO y otra con BAR".
  • Dentro de la clase hay cosas definidas en dos partes: GetInstance está declarado adentro (sin código) y escrito afuera, como Inicio_Serie::GetInstance(...). Es el mismo método.

Paso 3 — Comprobarlo con lo que imprime

El propio programa avisa qué espera: "Si ves el mismo valor, entonces fue exitoso". Corriendo las dos llamadas una después de la otra (sin hilos), primero con "FOO" y después con "BAR", imprime: 

FOO
FOO

La segunda llamada pide la instancia con "BAR", pero como el objeto ya existía no entra al if y devuelve el mismo de antes, que se creó con "FOO". Dos pedidos, un solo objeto. Con los hilos el valor repetido puede ser FOO o BAR según cuál llegue primero, pero siempre es el mismo las dos veces.

Paso 4 — El diagrama

Lo que está debajo de protected: lleva #; lo de public:, +; lo static, subrayado.

Respuesta

Es el patrón Singleton (creacional). Lo delatan: el atributo estático Inicio_Serie_, que es un puntero a la propia clase; el constructor protegido, que impide crear objetos desde afuera; y el método estático GetInstance, que crea la instancia solo si no existe y devuelve siempre la misma. Además, la copia y la asignación están eliminadas con = delete.
