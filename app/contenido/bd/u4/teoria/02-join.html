2. JOIN: datos de varias tablas

Con la base en 3FN, los datos están repartidos: la especie tiene el código de la zona, pero el nombre de la zona está en otra tabla. Para mostrarlos juntos se unen las tablas por la FK con INNER JOIN.

La forma 
SELECT ...
FROM TablaA a
INNER JOIN TablaB b ON b.ClavePrimaria = a.ClaveForanea
  • ON dice qué columna tiene que coincidir: siempre la FK de una con la PK de la otra.
  • El resultado tiene una fila por cada par que coincide. Una fila sin pareja no aparece (por eso es "inner", de adentro).
  • a y b son alias de tabla: un nombre corto para no escribir el nombre entero cada vez. a.Nombre se lee "la columna Nombre de la tabla a".

El camino de las FK

Antes de escribir el JOIN se busca el camino entre las tablas que tienen las columnas pedidas, saltando de FK en FK:

Cuidador_Especie.Legajo  -> Empleado.Legajo
Cuidador_Especie.CodigoEspecie -> Especie.Codigo
Especie.CodigoZona -> Zona.Codigo

Cada flecha es un INNER JOIN ... ON. Si para ir de una tabla a otra hay que pasar por una tercera (una tabla intermedia), esa tercera también entra en el FROM aunque no se muestre nada de ella.

Ejemplo 1: dos tablas

Listar cada especie con el nombre de su zona. Tablas: Especie (Codigo (PK), Nombre, CodigoZona (FK)) y Zona (Codigo (PK), Nombre, Extension).

SELECT e.Nombre AS Especie, z.Nombre AS Zona
FROM Especie e
INNER JOIN Zona z ON z.Codigo = e.CodigoZona;

Ejemplo 2: pasar por una tabla intermedia

Nombre y teléfono de los cuidadores a cargo de la especie "León" (Guía 9, consulta 3). Tablas: Empleado (Legajo (PK), Nombre, Telefono), Cuidador_Especie (Legajo (PK)(FK), CodigoEspecie (PK)(FK), FechaDesde) y Especie (Codigo (PK), Nombre).

Camino: Empleado → Cuidador_Especie (por Legajo) → Especie (por el código de la especie).

SELECT emp.Nombre, emp.Telefono
FROM Empleado emp
INNER JOIN Cuidador_Especie ce ON ce.Legajo = emp.Legajo
INNER JOIN Especie esp ON esp.Codigo = ce.CodigoEspecie
WHERE esp.Nombre = 'León';
  • Cuidador_Especie no muestra nada, pero tiene que estar: es la única que sabe qué cuidador tiene qué especie.
  • No hace falta pasar por la tabla Cuidador: el Legajo de Cuidador_Especie ya es el del empleado.
Errores y trampas
  • Si dos tablas tienen una columna con el mismo nombre (las dos tienen Nombre), hay que decir de cuál: e.Nombre o z.Nombre. Si no, SQL Server da error de "nombre ambiguo".
  • Cada INNER JOIN lleva su ON. Un JOIN sin ON no es válido.
  • El ON une FK con PK. Unir por nombre (e.Nombre = z.Nombre) no tiene sentido.
  • Si un turno tiene dos servicios, el JOIN con los servicios da dos filas para ese turno: es lo esperado.
