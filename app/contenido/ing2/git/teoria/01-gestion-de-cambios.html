Conceptos

1. Gestión de cambios y control de versiones

Para qué sirve

Un software nunca queda quieto: el cliente pide cosas nuevas, aparecen errores, varias personas tocan el mismo código a la vez. Si esos cambios no se ordenan, se pisan unos a otros, nadie sabe qué versión es la buena y no se puede volver atrás. El apunte arranca separando cuatro conceptos que suenan parecido.

Los cuatro conceptos

ConceptoQué esObjetivoEjemplo del apunte
Gestión de cambiosEl proceso de identificar, documentar, evaluar y controlar los cambios propuestos en un proyecto. Incluye evaluar cómo afectan al proyecto en tiempo, recursos y riesgos.Que todo cambio en requisitos, diseño o implementación se gestione de manera eficiente, minimizando riesgos.Un cliente pide una funcionalidad nueva: se evalúa el impacto y se implementa de manera controlada.

Diferencias clave
  • Gestión de cambios: cambios a nivel de requisitos, diseño o funcionalidades. Mira el impacto en todo el proyecto.
  • Gestión de la configuración: la organización y el control de todos los componentes del software (código, documentación, etc.).
  • Control de cambios: el proceso formal, dentro de la gestión de la configuración, que asegura que los cambios aprobados se implementen bien.
  • Control de versiones: el proceso técnico que permite gestionar distintas versiones, facilitando la colaboración y la trazabilidad en el código fuente.

Van de lo más amplio (decidir si un cambio se hace) a lo más técnico (guardar cada versión del código).

Qué es el control de versiones

También llamado "control de código fuente": es la práctica de rastrear y gestionar los cambios en el código. Un sistema de control de versiones (VCS) es la herramienta que lo hace: registra todas las modificaciones en una base de datos especial. Si se comete un error, se puede ir hacia atrás en el tiempo y comparar versiones anteriores.

Sus tres ventajas principales, según el apunte:

  1. Un historial completo de cambios a largo plazo de cada archivo: quién, cuándo y para qué. Permite volver a versiones anteriores y analizar la causa de un error.
  2. Creación de ramas y fusiones: varios flujos de trabajo independientes que después se vuelven a unir.
  3. Trazabilidad: poder seguir cada cambio, conectarlo con la herramienta de gestión (Jira) y anotarlo con un mensaje que explique su propósito.

Beneficios del control de versiones

BeneficioQué permite
Colaboración y trabajo en equipoVarios desarrolladores trabajan en paralelo sin interferir entre sí. Las ramas permiten trabajar aislado y fusionar cuando está listo.
Seguimiento históricoUn historial de cada cambio con autor, fecha y motivo. Facilita la auditoría y encontrar cuándo se introdujo un error.
Revertir cambiosVolver a una versión anterior si un cambio causa problemas. Se pueden marcar "puntos de control" en versiones estables.

Problemas de no usar control de versiones

  1. Pérdida de código: es fácil sobrescribir o borrar el trabajo de otro.
  2. Dificultad para colaborar en equipo.
  3. Falta de historial de cambios.
  4. Imposibilidad de revertir cambios ante un error crítico.
  5. Problemas con el lanzamiento de versiones: cuesta manejar una versión en producción y otra en desarrollo.
  6. Complicaciones para resolver conflictos cuando dos editan el mismo archivo.
  7. Ausencia de trazabilidad y auditoría: no se sabe quién hizo qué ni cuándo.
  8. Falta de seguridad en el código: queda disperso en varias computadoras.
  9. Dificultad para implementar entornos de pruebas.

La evolución:

  • CVS (años 80): el primero que permitió trabajar en equipo, pero centralizado.
  • SVN (Subversion, 2000): mejoró a CVS (commits atómicos), pero siguió siendo centralizado.
  • Git (2005, Linus Torvalds): introdujo el modelo distribuido.

Errores y trampas

Gestión de cambios no es control de versiones

La unidad se llama "Gestión de cambios" y casi todo el apunte habla de Git, pero no son sinónimos. La gestión de cambios decide si un cambio se hace y con qué impacto; el control de versiones es la herramienta técnica que guarda cómo quedó el código.

Control de cambios está dentro de la gestión de la configuración

El apunte lo define como un subconjunto. Si preguntan cómo se relacionan, esa es la respuesta.
