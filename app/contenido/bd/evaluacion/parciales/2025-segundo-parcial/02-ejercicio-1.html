Unidad 1 · Transacción

Ejercicio 1: Defina Transacción en base de datos. Definición y propiedades.

✓ ResultadosSolo la respuesta

Una transacción es un conjunto de operaciones sobre la base de datos que se ejecutan como una sola unidad de trabajo: o se realizan todas, o no se realiza ninguna. Lleva a la base de un estado consistente a otro. Si todo sale bien se confirma (COMMIT) y los cambios quedan guardados; si algo falla se deshace (ROLLBACK) y la base vuelve a como estaba al empezar (BEGIN TRAN).

Propiedades (ACID):

  • Atomicidad: es indivisible; se ejecuta completa o no se ejecuta nada.
  • Consistencia: deja la base en un estado válido, cumpliendo las restricciones de integridad.
  • Aislamiento: las transacciones simultáneas no se interfieren; cada una trabaja como si estuviera sola.
  • Durabilidad: una vez confirmada, los cambios son permanentes aunque falle el sistema.

Qué evalúa

Dos cosas: la definición (qué es una transacción) y las propiedades (las cuatro de ACID, cada una explicada).

La idea, con un ejemplo

Algunas tareas necesitan varias sentencias. Cuando un turno de la clínica se atiende, hay que registrar la consulta y pasar el turno a "Atendido". Si se hace la primera y el sistema se cae antes de la segunda, queda una consulta para un turno que figura como pendiente. La transacción las convierte en una sola cosa: 

BEGIN TRAN;
INSERT INTO Consulta (Numero, Diagnostico, Observaciones, Fecha, NumeroTurno)
VALUES (501, 'Otitis', 'Control en 7 días', '2026-10-14', 3020);
UPDATE Turno SET Estado = 'Atendido' WHERE Numero = 3020;
COMMIT;

Las cuatro propiedades sobre ese ejemplo

PropiedadEn el ejemplo
AtomicidadSi el UPDATE falla, el INSERT se deshace: no queda la consulta suelta.
ConsistenciaLa consulta apunta a un turno que existe (la FK se cumple) y el turno queda en un estado válido.
AislamientoSi en ese momento alguien lista los turnos pendientes, no ve el turno "a medias".
DurabilidadDespués del COMMIT, aunque se corte la luz, la consulta y el estado nuevo quedan.

Para ampliar, se puede nombrar a los módulos del SGBD que las cumplen (apunte de la cátedra): el gestor de transacciones, el control de la integridad, el planificador (concurrencia) y el gestor de recuperación.
