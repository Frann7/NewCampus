10 puntos Unidad 6 · Control de versiones

4. Represente gráficamente la arquitectura de control de versiones de SVN y Git, indicando los servidores centrales, los repositorios y la ubicación de las copias de trabajo de los desarrolladores en cada caso.

✓ ResultadosSolo la respuesta

SVN (centralizado): un servidor central con el único repositorio; cada desarrollador tiene solo una copia de trabajo, sin el historial, y hace commit y update directo contra el servidor.

Git (distribuido): cada desarrollador tiene un repositorio local completo, con todo el historial, y su copia de trabajo; el commit se guarda en el repositorio local. Un servidor remoto (GitHub) guarda el repositorio que se comparte, y se sincroniza con push y pull.

Celeste: un repositorio (tiene el historial). Verde: una copia de trabajo.

✎ Explicación detalladaEl concepto desde cero, el desarme de la consigna, la respuesta y las trampas

Qué evalúa

La diferencia entre un control de versiones centralizado (SVN) y uno distribuido (Git), pero dibujada. La consigna dice qué tiene que aparecer: servidores, repositorios y copias de trabajo, en los dos.

Paso 1 — Las tres palabras
  • Servidor: la computadora a la que se conectan todos.
  • Repositorio: la base de datos con todo el historial de versiones.
  • Copia de trabajo: los archivos que el desarrollador edita en su computadora.
Paso 2 — La única diferencia: dónde está el repositorio
SVNGit
ServidorUno central, obligatorioUno remoto, para compartir (no es obligatorio)
RepositoriosUno solo, en el servidorUno en cada desarrollador, más el remoto
Copias de trabajoEn cada desarrollador, sin historialEn cada desarrollador, junto a su repositorio local
El commit va a...El servidor (hace falta conexión)El repositorio local (después, push)
Si se cae el servidorNadie puede confirmar cambiosTodos siguen trabajando con su repositorio local
Paso 3 — Cómo dibujarlo en la hoja
  1. Arriba, una caja para el servidor, con el repositorio adentro.
  2. Abajo, tres cajas de desarrolladores, unidas al servidor con flechas de ida y vuelta.
  3. En SVN, dentro de cada desarrollador, solo la copia de trabajo. En Git, el repositorio local y la copia de trabajo.
  4. Rotular las flechas: commit / update en SVN, push / pull en Git.

Trampas

  • En Git también hay servidor: GitHub o GitLab. La diferencia no es que no exista, sino que no es el único lugar con el historial.
  • En SVN el desarrollador no tiene repositorio, solo la copia de trabajo.
  • Git no es GitHub: Git es el sistema; GitHub es la plataforma que aloja el repositorio remoto.
