18. Git: conflictos de merge

Unidad 6 · Git

¿Cuándo se produce un conflicto de merge? Indique los tipos de conflicto y los pasos para resolverlo, con sus comandos.

✓ RespuestaPara aprender y escribir en la hoja

Cuándo: al hacer git merge, si las dos ramas cambiaron las mismas líneas del mismo archivo. Git no termina el merge hasta resolverlo.

Tipos: de contenido (las dos cambiaron la misma línea) y de eliminación (una borró un archivo que la otra modificó).

  1. git status: ver los archivos en conflicto.
  2. Editarlos: entre <<<<<<< HEAD y ======= está la rama actual; entre ======= y >>>>>>>, la otra. Se deja lo correcto y se borran las marcas.
  3. git add archivo: marcarlo como resuelto.
  4. git commit: terminar el merge.

git merge --abort cancela el merge; git mergetool abre una herramienta para resolverlo.

✎ Explicación desde ceroParte por parte

Un ejemplo

En main el título de index.html pasó a "Bienvenidos"; en la rama login, a "Iniciá sesión". Parado en main, git merge login no sabe con cuál quedarse: marca el título con las dos versiones y se frena. Uno elige (o arma un título nuevo), borra las marcas, y cierra con git add index.html y git commit.

El resumen para recordar

Merge integra ramas; si las dos cambiaron las mismas líneas, hay conflicto. Se resuelve abriendo el archivo, eligiendo qué conservar, pasándolo a staging con git add y cerrando con un git commit que registra el merge.

Trampas

  • HEAD es la rama en la que estás parado (la que recibe el merge), no la que se integra.
  • Editar el archivo no alcanza: sin git add y git commit, el merge sigue a medias.
  • Si dos ramas tocaron el mismo archivo pero en líneas distintas, no hay conflicto: Git lo une solo.
