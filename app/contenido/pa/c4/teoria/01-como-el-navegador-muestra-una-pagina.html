1. Cómo el navegador muestra una página

Para qué sirve

Todo lo que hace JavaScript en esta clase es tocar el DOM: leer lo que escribiste en un campo, cambiar un título, agregar un párrafo. Para entender qué es el DOM hay que ver primero qué hace el navegador desde que escribís una dirección hasta que ves la página pintada.

Sintaxis: las etiquetas que hacen pedir más archivos

El navegador primero pide el archivo índice del sitio (index.html, index.php, etc.), que trae el código HTML. Mientras lo lee, ciertas etiquetas le avisan que tiene que pedir otro archivo al servidor. Cada una es una petición nueva (en inglés, request): 

<link href="/css/styles.css" rel="stylesheet">   <!-- pide una hoja de estilos -->
<img src="imgs/logo.png">                          <!-- pide una imagen -->
<script src="js/pagina.js"></script>             <!-- pide un archivo de JavaScript -->

Recién cuando terminó de pedir todo lo necesario, empieza el renderizado: convertir ese texto en algo que se ve en la pantalla.

Qué es cada parte: los cinco pasos del renderizado

PasoQué entraQué haceQué sale
1. Construcción del DOMEl HTML (texto, con el encabezado Content-Type: text/html; charset=UTF-8)Por cada etiqueta crea un objeto de JavaScript llamado Node (nodo) y los acomoda en forma de árbol: cada etiqueta es hija de la que la contieneEl DOM
2. Construcción del CSSOMTodos los CSSArma otro árbol, donde cada nodo tiene la información de estilo que le corresponde a un elemento del DOMEl CSSOM (modelo de objetos CSS)
3. Árbol de renderizadoDOM + CSSOMRecorre el DOM desde la raíz, se queda solo con los nodos visibles y a cada uno le aplica su regla de CSSEl árbol de renderizado (render tree)
4. Fase de diseñoEl árbol de renderizadoCalcula la posición y el tamaño exactos de cada nodo respecto de la ventana. También se llama reflujo (layout)Un modelo de cajas con posiciones y tamaños
5. Fase de pinturaNodos visibles, su estilo y su geometríaConvierte todo eso en píxeles reales en la pantallaLa página que ves

CSS  --> [CSS parser]  --CSSOM--'

Parser es el programa que lee un texto y lo convierte en una estructura (acá, en un árbol).

Qué es el DOM, en una línea

El DOM (Document Object Model, modelo de objetos del documento) es la página convertida en un árbol de objetos que el navegador le presta a JavaScript para que pueda leerla y modificarla. No es el archivo HTML: es lo que el navegador armó a partir del archivo.

Ejemplo 1 — ¿Cuántas peticiones hace el navegador?

Enunciado

El navegador entra a un sitio cuyo index.html es este. ¿Cuántas peticiones al servidor hace en total, antes de empezar a renderizar?

<!DOCTYPE html>
<html lang="es">
<head>
    <title>Mi sitio</title>
    <link href="css/styles.css" rel="stylesheet">
</head>
<body>
    <h1>Hola</h1>
    <img src="imgs/logo.png">
    <img src="imgs/foto.jpg">
    <script src="js/pagina.js"></script>
</body>
</html>
LíneaQué hacePeticiones hasta acá
(escribir la dirección)Pide el archivo índice, index.html1
<title>, <h1>Son texto que ya vino adentro del HTML: no piden nada1
<link href="css/styles.css">Pide la hoja de estilos2
<img src="imgs/logo.png">Pide la primera imagen3
<img src="imgs/foto.jpg">Pide la segunda imagen4
<script src="js/pagina.js">Pide el archivo de JavaScript5
Respuesta

5 peticiones: el índice más una por cada link, img y script con archivo externo. Las etiquetas que solo tienen texto no piden nada.

Ejemplo 2 — Armar el árbol del DOM (diapositiva 10)

Enunciado

Para este HTML: a) dibujar el árbol del DOM; b) ¿quién es el padre de <a>?; c) ¿cuántos hijos tiene <body>? 

<html>
  <head>
    <title>Ejemplo</title>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width">
  </head>
  <body>
    <h1>Título</h1>
    <p>Un párrafo con un <a href="#">enlace</a></p>
    <ul>
      <li>Uno</li>
      <li>Dos</li>
      <li>Tres</li>
    </ul>
  </body>
</html>
a) El árbol

La regla es una sola: cada etiqueta es hija de la etiqueta que la contiene. <html> es la raíz, porque contiene a todas: 

html
├── head
│   ├── title
│   ├── meta
│   └── meta
└── body
    ├── h1
    ├── p
    │   └── a
    └── ul
        ├── li
        ├── li
        └── li

Es exactamente el árbol de la diapositiva 10.

b) El padre de <a>

El enlace está escrito adentro del <p>, así que su padre es <p> (no <body>).

c) Los hijos de <body>

Solo cuentan los que están directamente adentro: h1, p y ul. Son 3. El a y los tres li son nietos: están adentro de un hijo.

Respuesta

b) <p>. c) 3 hijos: h1, p y ul.

Errores y trampas

El DOM no es el archivo

Cuando JavaScript cambia un título, cambia el DOM, no el archivo .html del servidor. Si recargás la página, el navegador vuelve a pedir el archivo original y el cambio desaparece.

Cambiar el DOM cuesta

Cada cambio puede obligar al navegador a repetir los pasos 4 y 5 (recalcular posiciones y volver a pintar). Por eso la diapositiva 9 avisa que actualizar el DOM es costoso: cuantos más cambios, más lenta la página.

CSSOM no es CSS

El CSS es el archivo de texto; el CSSOM es el árbol que el navegador arma leyéndolo, igual que el DOM es el árbol que arma leyendo el HTML.
