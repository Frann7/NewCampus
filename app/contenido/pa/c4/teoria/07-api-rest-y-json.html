7. API REST y JSON

Para qué sirve

Hasta acá la página trabajaba con lo que ya tenía. Pero muchas veces los datos están en otro sistema: la lista de provincias del gobierno, fotos de perros, los usuarios de otra aplicación. Una API REST es la puerta que ese sistema deja abierta para que otros programas le pidan datos por internet. Y JSON es el formato de texto en que viajan esos datos.

API (Application Programming Interface) es un conjunto de reglas para que dos programas se comuniquen. REST (Transferencia de Estado Representacional) es un estilo de arquitectura para hacerlo sobre HTTP, el mismo protocolo con el que el navegador pide páginas.

Sintaxis: cómo se ve un pedido y una respuesta

El cliente pide una dirección (una URL), igual que una página:

https://apis.datos.gob.ar/georef/api/provincias

Y el servidor, en vez de HTML, contesta un texto en JSON (diapositiva 16):

{
  "id": 1024,
  "nombre": "Juan Pérez",
  "edad": 30,
  "empleado_activo": true,
  "puesto": "Desarrollador Web",
  "habilidades": [
    "JavaScript",
    "Python",
    "SQL"
  ]
}

Qué es cada parte

Las características de una API REST (diapositiva 15)

CaracterísticaQué significa
Cliente-ServidorSepara a quien pide la información (una página web, una app del celular) de quien la guarda y procesa (el servidor). Cada lado puede cambiar sin romper al otro mientras respeten las reglas
Sin estado (stateless)El servidor no recuerda nada del usuario entre un pedido y otro. Cada pedido viaja con toda la información necesaria para entenderse solo
Formato livianoLos datos viajan como texto, comúnmente en JSON, que cualquier lenguaje de programación puede leer

Las reglas de JSON

JSON (JavaScript Object Notation, notación de objetos de JavaScript) es un formato de texto liviano para guardar e intercambiar datos. Se parece a un objeto de JavaScript, pero es más estricto:

Pasar de texto a objeto y al revés

FunciónQué recibeQué devuelve
JSON.parse(texto)Un string con JSONEl objeto de JavaScript, para leerlo con punto y corchetes
JSON.stringify(objeto)Un objetoEl string JSON, todo en una línea
JSON.stringify(objeto, null, 2)Un objetoEl string JSON con saltos de línea y 2 espacios de sangría, para leerlo cómodo. El null del medio es un parámetro que no se usa

Los códigos de respuesta HTTP

Cada respuesta trae un número que dice cómo salió el pedido (diapositiva 17):

CódigoSignifica

Por qué: stringify escribe el JSON con todas sus reglas (comillas dobles en las claves). El tercer parámetro solo cambia la presentación. La práctica (ejemplo 6) usa esta forma para mostrar en pantalla la respuesta de una API.

Errores y trampas

JSON no es un objeto, es texto

Lo que llega por la red es un string. Hasta que no se convierte (con JSON.parse o, con fetch, con response.json()), no se puede leer con punto.

"Sin estado" no es "sin datos"

El servidor guarda datos (las provincias, los usuarios). Lo que no guarda es la conversación con cada cliente: cada pedido llega solo y tiene que traer todo lo necesario.
