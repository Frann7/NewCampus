#include <iostream>
#include <vector>
#include <algorithm>
class Graphic {
public:
    virtual ~Graphic() {}
    virtual void Move(int x, int y) = 0;
    virtual void Draw() const = 0; };
class Dot : public Graphic {
protected:
    int x_;
    int y_;
public:
    Dot(int x, int y) : x_(x), y_(y) {}
    void Move(int x, int y) override {
        x_ += x;
        y_ += y;      }
    void Draw() const override {
        std::cout << "Dibujando punto en ("
        << x_ << ", " << y_ << ")\n";     }};

class Circle : public Dot {
private:
    int radius_;
public:
    Circle(int x, int y, int radius)
      : Dot(x, y), radius_(radius) {}
    void Draw() const override {
        std::cout << "Dibujando circulo en ("
        << x_ << ", " << y_
        << ") con radio " << radius_ << "\n";
}};

class CompoundGraphic : public Graphic {
private:
    std::vector<Graphic*> children_;
public:
    void Add(Graphic* graphic) {
        children_.push_back(graphic);     }
    void Remove(Graphic* graphic) {
        auto it = std::find(
            children_.begin(),
            children_.end(),
            graphic          );
        if (it != children_.end()) {
            children_.erase(it);     }     }

    void Move(int x, int y) override {
        for (Graphic* graphic : children_) {
            graphic->Move(x, y);      }     }

    void Draw() const override {
        std::cout << "Dibujando grupo:\n";
        for (const Graphic* graphic : children_) {
            graphic->Draw();       }
        std::cout << "Fin del grupo\n";     }};

class ImageEditor {
private:
    CompoundGraphic* all_;
public:
    ImageEditor() : all_(nullptr) {}
    ~ImageEditor() {
        delete all_;     }
    void Load() {
        all_ = new CompoundGraphic();
        all_->Add(new Dot(1, 2));
        all_->Add(new Circle(5, 3, 10));
        std::cout << "Imagen cargada.\n";     }
    void DrawAll() {
        if (all_ != nullptr) {
            all_->Draw();     }     }

    void MoveAll(int x, int y) {
        if (all_ != nullptr) {
            all_->Move(x, y);     }     }};

int main() {
    ImageEditor editor;
    editor.Load();
    std::cout << "\nImagen original:\n";
    editor.DrawAll();
    std::cout << "\nMoviendo todos los elementos...\n";
    editor.MoveAll(10, 5);
    std::cout << "\nImagen después del movimiento:\n";
    editor.DrawAll();
    return 0;
}
✓ ResultadosSolo la respuesta
  1. Qué patrón y por qué: "Es Composite, un patrón estructural que se usa cuando los objetos forman un árbol, con elementos simples y contenedores que agrupan elementos simples u otros contenedores. Acá los gráficos se agrupan: un grupo (CompoundGraphic) contiene puntos, círculos u otros grupos."
  2. Los elementos que ayudaron a identificarlo:
    • Graphic solo declara Move() y Draw() (virtuales puros): es la interfaz común a todos.
    • CompoundGraphic hereda de Graphic y a la vez guarda una lista de Graphic (std::vector<Graphic*> children_): una clase que guarda una lista de su propio tipo.
    • Tiene Add() y Remove() para agregar y quitar hijos.
    • Su Move() y su Draw() recorren la lista y le pasan el pedido a cada hijo (graphic->Move(x, y)).
    • ImageEditor mueve y dibuja todo con una sola llamada al grupo (all_->Move(x, y)).
  3. Cómo está aplicado: "Graphic es el componente (la interfaz común a todos los gráficos, con Move y Draw). Dot y Circle son hojas (los elementos simples, que no contienen a nadie): se mueven y se dibujan solos; Circle hereda de Dot y le suma el radio. CompoundGraphic es el compuesto (el contenedor): guarda una lista de Graphic y resuelve cada pedido pasándoselo a lo que contiene. ImageEditor es el cliente."
  4. Qué se gana: "El editor trata igual a un punto solo que a un grupo entero: MoveAll(10, 5) mueve todos los elementos con una sola llamada, y se pueden armar grupos dentro de grupos sin modificar el editor."

Qué evalúa

Reconocer un patrón por la forma del código, decir qué lo delata y pasar el código a un diagrama de clases. Es la consigna de mayor puntaje: el UML vale tanto como reconocerlo. El código es el ejemplo de Composite del apunte (el editor de gráficos), escrito en C++.

Paso 2 — Las preguntas para reconocer un código
  1. ¿Hay algo static y un constructor que no es público? No. No es Singleton.
  2. ¿Alguna clase hereda de otra? Sí, varias. No es Facade.
  3. ¿Hay métodos cuyo trabajo es devolver un new de otra clase? No (Load() crea objetos, pero no los devuelve). No es Factory Method ni Abstract Factory.
  4. La clase que guarda a otras, ¿qué guarda? CompoundGraphic guarda una lista de su propio tipo: es un Graphic que contiene Graphic. → Composite.

Se confirma con el resto: Move() y Draw() del grupo no hacen el trabajo, se lo pasan a cada hijo con un for. Y como un hijo puede ser otro grupo, el pedido baja por todo el árbol.

Trampas

  • Circle no hereda de Graphic directo, sino de Dot: sigue siendo una hoja, porque no contiene a nadie. En el diagrama va colgada de Dot, con línea continua.
  • No es Observer: Observer también guarda una lista, pero de otra interfaz (los suscriptores) y con un método para avisarles. Acá la lista es del mismo tipo que la clase.
  • No olvidar la agregación: la flecha punteada de CompoundGraphic a Graphic sola no alcanza; lo que hace Composite es la segunda relación, el rombo con *.
  • El cliente no es parte del componente: ImageEditor no hereda de nadie.
