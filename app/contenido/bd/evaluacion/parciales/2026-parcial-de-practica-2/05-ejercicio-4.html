Unidad 3 · Cabecera y detalle

Ejercicio 4: Utilizando lenguaje SQL, crear las tablas de Facturas (cabecera y detalle), con sus atributos y claves correspondientes.

✓ ResultadosSolo la respuesta 
CREATE TABLE Factura (
  Numero         INT       NOT NULL,
  Tipo           CHAR(1)   NOT NULL,
  Fecha          DATE      NOT NULL,
  NumeroReserva  INT       NOT NULL,
  PRIMARY KEY (Numero),
  UNIQUE (NumeroReserva),
  FOREIGN KEY (NumeroReserva) REFERENCES Reserva(Numero)
);

CREATE TABLE Factura_Servicio (
  NumeroFactura   INT            NOT NULL,
  CodigoServicio  INT            NOT NULL,
  Importe         DECIMAL(10,2)  NOT NULL,
  PRIMARY KEY (NumeroFactura, CodigoServicio),
  FOREIGN KEY (NumeroFactura) REFERENCES Factura(Numero),
  FOREIGN KEY (CodigoServicio) REFERENCES Servicio(Codigo)
);

Reserva y Servicio tienen que estar creadas antes, y Factura antes que Factura_Servicio.

✎ Explicación detalladaLa cabecera, el detalle y las trampas

Qué evalúa

Es la forma del ejercicio 2 del final del 26/09/2025 (pedidos con cabecera y detalle): dos tablas, la segunda con PK compuesta (Unidad 3, práctica: la factura).

Factura (Numero (PK), Tipo, Fecha, NumeroReserva (FK))
Factura_Servicio (NumeroFactura (PK)(FK), CodigoServicio (PK)(FK), Importe)
Paso 1 — La cabecera
  • Tipo CHAR(1): A, B o C.
  • NumeroReserva: FK a Reserva, con UNIQUE porque la interrelación es 1:1 (una reserva genera una factura).
Paso 2 — El detalle
  • Un renglón por servicio facturado: PK compuesta (NumeroFactura, CodigoServicio).
  • Dos FK, una a la cabecera y otra a Servicio. Importe DECIMAL(10,2).
Resolución 
CREATE TABLE Factura (
  Numero         INT       NOT NULL,
  Tipo           CHAR(1)   NOT NULL,
  Fecha          DATE      NOT NULL,
  NumeroReserva  INT       NOT NULL,
  PRIMARY KEY (Numero),
  UNIQUE (NumeroReserva),
  FOREIGN KEY (NumeroReserva) REFERENCES Reserva(Numero)
);

CREATE TABLE Factura_Servicio (
  NumeroFactura   INT            NOT NULL,
  CodigoServicio  INT            NOT NULL,
  Importe         DECIMAL(10,2)  NOT NULL,
  PRIMARY KEY (NumeroFactura, CodigoServicio),
  FOREIGN KEY (NumeroFactura) REFERENCES Factura(Numero),
  FOREIGN KEY (CodigoServicio) REFERENCES Servicio(Codigo)
);

Trampas

  • El orden: la cabecera primero, porque el detalle apunta a ella.
  • Una sola PRIMARY KEY con las dos columnas, no dos.
