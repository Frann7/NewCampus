16. Git: qué es y sus características

Unidad 6 · Git

Defina Git y explique sus características principales. Defina commit, rama (branch), merge y pull request.

✓ RespuestaPara aprender y escribir en la hoja

Git es un sistema de control de versiones distribuido, libre y de código abierto, creado por Linus Torvalds en 2005, para rastrear los cambios del código y que varias personas trabajen en el mismo proyecto sin sobrescribir el trabajo de los demás.

Características:

  • Distribuido: cada copia del proyecto es un repositorio completo, con todo el historial: se trabaja sin conexión y se hacen commits en local.
  • Copias instantáneas, no diferencias: en cada commit guarda una foto de todos los archivos (los que no cambiaron, como un enlace al anterior). Los otros sistemas guardan la lista de cambios de cada archivo.
  • Casi todas las operaciones son locales: el historial está en el disco, así que ver la historia o comparar versiones es casi inmediato.
  • Integridad: todo se verifica con una suma de comprobación (hash SHA-1, 40 caracteres hexadecimales) antes de guardarse: no se puede cambiar un archivo sin que Git lo sepa.
  • Generalmente solo añade información: una vez confirmado un cambio, es muy difícil perderlo.

ConceptoQué es
CommitUna captura de los cambios del proyecto en un momento, con un mensaje que explica su propósito. Los commits forman el historial que permite revertir o revisar versiones anteriores.
Rama (branch)Una versión paralela del proyecto, para trabajar en algo nuevo o en una corrección sin afectar la rama principal (main o master).
MergeCombinar los cambios de una rama en otra. Es automático si no hay conflictos; si las dos ramas cambiaron la misma línea, se resuelve a mano.
Pull requestUna solicitud para que los cambios de una rama se revisen, se discutan, se aprueben y se integren en otra, en plataformas como GitHub, GitLab o Bitbucket.

Las cinco características, en una línea cada una

  • Distribuido: todos tienen todo.
  • Instantáneas: guarda fotos, no diferencias.
  • Local: no necesita el servidor para casi nada.
  • Integridad: cada cosa tiene su hash; si cambia, Git se entera.
  • Solo añade: lo confirmado no se pierde.

Trampas

  • Git no es GitHub: Git es el sistema; GitHub, la plataforma que aloja el repositorio remoto y donde se hacen los pull requests.
  • El pull request no es un comando de Git: es un pedido en la plataforma.
  • Lo que Git puede perder son los cambios sin confirmar; lo confirmado, no.
