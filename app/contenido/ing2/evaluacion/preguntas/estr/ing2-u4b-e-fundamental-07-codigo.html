A partir del siguiente código identifique el patrón que se implementa en el mismo y explique qué elementos ayudaron a identificarlo. 

#include <iostream>
#include <list>

class Trabajo {
 public:
  virtual ~Trabajo() {}
  virtual void Add(Trabajo *trabajo) {}
  virtual void Remove(Trabajo *trabajo) {}
  virtual int Operation() const = 0;
};

class Tarea : public Trabajo {
 private:
  int costo_;
 public:
  Tarea(int costo) : costo_(costo) {}
  int Operation() const override {
    return this->costo_;
  }
};

class Etapa : public Trabajo {
 private:
  std::list<Trabajo *> partes_;
 public:
  void Add(Trabajo *trabajo) override {
    this->partes_.push_back(trabajo);
  }
  void Remove(Trabajo *trabajo) override {
    this->partes_.remove(trabajo);
  }
  int Operation() const override {
    int total = 0;
    for (const Trabajo *parte : this->partes_) {
      total += parte->Operation();
    }
    return total;
  }
};

void Presupuestar(const Trabajo *trabajo) {
  std::cout << "Costo: " << trabajo->Operation() << "\n";
}

int main() {
  Trabajo *pintura = new Tarea(300);
  Presupuestar(pintura);

  Trabajo *excavacion = new Tarea(500);
  Trabajo *hormigon = new Tarea(1200);
  Trabajo *cimientos = new Etapa;
  cimientos->Add(excavacion);
  cimientos->Add(hormigon);
  Trabajo *obra = new Etapa;
  obra->Add(cimientos);
  obra->Add(pintura);
  Presupuestar(obra);

  delete pintura;
  delete excavacion;
  delete hormigon;
  delete cimientos;
  delete obra;
  return 0;
}

Lo que se ve, en el orden en que conviene leerlo:

  • Herencia: dos, Tarea y Etapa heredan de Trabajo, que declara Operation() sin código.
  • Qué guarda la clase del medio: Etapa guarda una lista de punteros a Trabajo, su misma clase base, y la llena con Add().
  • El cliente: Presupuestar solo conoce a Trabajo y llama a Operation().
  • Qué hace por dentro: Tarea devuelve su costo; Etapa, en su Operation(), recorre la lista, llama al Operation() de cada parte y devuelve la suma.

Composite. La respuesta, como se escribe en la hoja:

  1. Qué patrón y por qué: “Es Composite, un patrón estructural que se usa cuando los objetos forman un árbol, con elementos simples y contenedores que agrupan elementos simples u otros contenedores. Se reconoce porque Tarea y Etapa heredan las dos de Trabajo, Etapa guarda una lista de punteros a Trabajo (su misma clase base, así que adentro puede haber tareas u otras etapas) y en su Operation() recorre la lista, llama al Operation() de cada parte y devuelve la suma.”
  2. Cómo está aplicado: “Trabajo es el componente (la interfaz que cumplen todos: cualquier trabajo sabe decir su costo con Operation()). Tarea es la hoja (el elemento simple: no contiene nada y devuelve su propio costo). Etapa es el compuesto (el contenedor): guarda una lista de Trabajo y resuelve cada pedido pasándoselo a lo que contiene.”
  3. Qué se gana: “Presupuestar trata igual a una tarea sola que a una etapa entera: recibe un Trabajo y llama a Operation(), sin preguntar qué es.”

    • Dos: Tarea y Etapa heredan las dos de Trabajo, que es la clase base
    • Una sola: Etapa hereda de Trabajo, y Tarea es una clase suelta
    • Ninguna: las tres clases están sueltas y no se relacionan por herencia
    • Dos en cadena: Etapa hereda de Tarea, y Tarea hereda de Trabajo

    Buscá los renglones class ... : public ....

    Hay dos : public Trabajo: el de Tarea y el de Etapa. Trabajo es la base de las dos, y su Operation() termina en = 0: no tiene código, lo escribe cada subclase. Que haya herencia ya descarta Facade, donde no hay ninguna.

  2. Segundo, la clase del medio: la que guarda a otros objetos. De las tres clases, ¿cuál tiene un atributo que guarda otros objetos? Escribí solo el nombre de la clase.

    Mirá la parte private: de cada clase: una guarda un número; la otra, una lista.

    Etapa. Trabajo no tiene atributos, Tarea guarda solo un número (int costo_) y Etapa guarda partes_, una lista de punteros a otros objetos. Esa es la clase que hay que mirar con más cuidado.

  3. ¿Qué guarda Etapa en su atributo partes_?

    • Una lista de punteros a Trabajo, que es su misma clase base
    • Un solo puntero a Tarea, que recibe por el constructor
    • Un puntero estático a Etapa, es decir, a ella misma
    • Un solo puntero a Trabajo, y un método para cambiarlo por otro

    Leé el tipo completo: std::list<Trabajo *>. ¿De quién hereda Etapa?

    std::list<Trabajo *> partes_;: una lista de punteros a Trabajo, la misma base de la que Etapa hereda. Por eso adentro de una etapa puede haber tareas y también otras etapas. Un solo puntero a una clase suelta sería Adapter; un puntero estático a sí misma, Singleton; uno solo que se puede cambiar, Strategy.

  4. La función Presupuestar es la que usa los objetos. ¿De qué clase es el puntero que recibe? Escribí solo el nombre de la clase.

    Mirá el parámetro, entre los paréntesis de void Presupuestar(...).

    Trabajo. Presupuestar es el cliente: recibe un Trabajo* y llama a Operation(). En main se la llama dos veces, una con pintura (una Tarea) y otra con obra (una Etapa), y la función no nota la diferencia.

  5. ¿Qué hace Etapa dentro de su Operation()?

    • Recorre partes_, llama al Operation() de cada parte y devuelve la suma de lo que le devolvieron
    • Recorre partes_ y le avisa a cada parte que hubo un cambio, sin esperar ni devolver ningún resultado
    • Llama a un método con otro nombre de una clase suelta y convierte lo que le devuelve a otra unidad
    • Crea una Tarea nueva con new y se la devuelve al cliente para que la use

    Hay un for, una variable total que va acumulando y un return.

    El for pasa por cada elemento de partes_, total += parte->Operation(); le hace a cada uno el mismo pedido que recibió la etapa, y return total; devuelve todo junto. La etapa no calcula nada propio: le pasa el pedido a lo que contiene y junta las respuestas.

  6. En main, obra es una Etapa que tiene adentro a cimientos (otra Etapa) y a pintura (una Tarea). ¿Qué pasa cuando se llama a Presupuestar(obra)?

    • obra le pide el costo a cimientos y a pintura, y cimientos se lo pide a su vez a sus dos tareas. Imprime Costo: 2000
    • obra suma solo las tareas que tiene directamente y saltea a cimientos por ser una etapa. Imprime Costo: 300
    • obra pregunta con un if si cada parte es una tarea o una etapa, y a cada una la trata distinto. Imprime Costo: 2000
    • obra suma solo lo que hay dentro de cimientos, porque pintura ya se había presupuestado antes. Imprime Costo: 1700

    obra no sabe qué es cada parte: a todas les llama Operation(). Hacé la cuenta con 500, 1200 y 300.

    El pedido baja por el árbol: obra llama al Operation() de cimientos, que suma sus dos tareas (500 + 1200 = 1700), y al de pintura, que devuelve 300. Total, 2000. En ningún lado hay un if que pregunte qué es cada parte. La salida del programa es Costo: 300 y Costo: 2000.

  7. Con todo eso: ¿qué patrón implementa el código?

    • Composite
    • Observer
    • Strategy
    • Adapter

    Una clase que hereda de una base y guarda una lista de esa misma base; su operación es un bucle sobre lo que contiene, y hay Add y Remove.

    Composite: se usa cuando los objetos forman un árbol, con elementos simples y contenedores que agrupan elementos simples u otros contenedores. Los nombres Add, Remove y Operation lo confirman (son los del ejemplo original), pero la respuesta se justifica con la forma.

  8. Los patrones se reparten en tres grupos: creacionales, estructurales y de comportamiento. ¿A cuál pertenece Composite? Escribí una sola palabra.

    No se ocupa de crear objetos ni de cómo se avisan entre ellos: se ocupa de cómo se arman objetos más grandes a partir de otros.

    Estructural, igual que Adapter y Facade. Es lo primero que se escribe en la hoja: “Es Composite, un patrón estructural que se usa cuando...”.

  9. La descripción de Composite dice que se usa “cuando los objetos forman un ...”. ¿Qué palabra falta? Escribí una sola palabra.

    Una obra tiene etapas, y una etapa tiene tareas u otras etapas. Dibujado, tiene una raíz, ramas y hojas.

    Árbol: “con elementos simples y contenedores que agrupan elementos simples u otros contenedores”. En el código, obra es la raíz, cimientos es una rama, y excavacion, hormigon y pintura son las hojas.

  10. En Composite, el elemento simple, el que no contiene nada, se llama hoja. ¿Qué clase del código es la hoja? Escribí solo el nombre de la clase.

    Es la que en su Operation() no le pregunta a nadie: devuelve lo que tiene guardado.

    Tarea es la hoja (Leaf): no tiene lista y su Operation() es un solo renglón, return this->costo_;. No redefine Add() ni Remove(): se queda con los de Trabajo, que están vacíos, porque a una tarea no se le agrega nada.

  11. ¿Cómo se llama la parte del patrón que cumple Etapa, la clase que guarda la lista? Escribí una sola palabra.

    Es la parte que le da el nombre al patrón, dicha en castellano.

    Etapa es el compuesto (Composite), el contenedor: guarda una lista de Trabajo y resuelve cada pedido pasándoselo a lo que contiene.

  12. ¿Y la parte que cumple Trabajo, la clase base de la que heredan las otras dos? Escribí una sola palabra.

    Las partes de Composite son tres: componente, hoja y compuesto. Dos ya están ubicadas.

    Trabajo es el componente (Component): la interfaz que cumplen todos, hojas y compuestos. Es lo que permite que la lista de Etapa y el parámetro de Presupuestar acepten cualquiera de los dos.

  13. Observer también tiene una lista de punteros, un método para agregar, otro para quitar y un bucle que la recorre. ¿Por qué esto no es Observer?

    • Porque la lista es de la misma base de la que hereda Etapa, y el bucle junta un resultado y lo devuelve; en Observer la lista es de otra interfaz y solo se avisa
    • Porque en Observer la lista se guarda siempre en un std::vector, y en este código las partes están en un std::list
    • Porque en Observer la clase que tiene la lista no puede heredar de ninguna otra ni tener métodos virtual
    • Porque Observer es un patrón creacional, y en este código los objetos se crean todos en main

    Dos cosas: ¿la lista es del mismo tipo que la clase que la tiene, o de otro? ¿El bucle devuelve algo, o solo avisa?

    La pregunta que los separa: ¿la lista es del mismo tipo que la clase que la tiene y el resultado vuelve (Composite), o es de otra interfaz y solo se avisa (Observer)? Acá Etapa es un Trabajo y guarda Trabajo, y el bucle suma y devuelve el total. En Observer el notificador guarda suscriptores, que son otra cosa, y les avisa sin esperar nada de vuelta.

  14. En Facade también hay una clase que guarda a otras y las llama desde un método, que en el ejemplo original hasta se llama Operation. ¿Por qué esto no es Facade?

    • Porque acá hay herencia y Etapa guarda una lista de su misma base; una fachada no hereda de nadie y guarda un objeto de cada clase del subsistema, todas distintas
    • Porque una fachada tiene que tener el constructor privado y un método estático para pedirla, y Etapa no tiene ninguna de las dos cosas
    • Porque una fachada nunca recibe objetos desde afuera: los crea siempre ella misma, y acá las partes llegan por Add()
    • Porque Facade es un patrón de comportamiento, y este código lo que hace es armar una estructura de objetos

    ¿Hay herencia? ¿Lo que guarda Etapa son objetos de clases distintas, o todos del mismo tipo?

    En Facade no hay ninguna herencia: son varias clases sueltas y una que guarda una de cada una y las llama en orden. Acá las tres clases están unidas por herencia y lo que Etapa guarda es una lista de un solo tipo, el suyo. El nombre Operation aparece en los dos ejemplos originales: por eso no alcanza con los nombres.

  15. La consigna pide explicar qué elementos ayudaron a identificarlo. ¿Cuál es la respuesta completa?

    • Tarea y Etapa heredan las dos de Trabajo; Etapa guarda una lista de punteros a Trabajo, su misma base; y en su Operation() recorre la lista, llama al Operation() de cada parte y devuelve la suma
    • Los métodos se llaman Add(), Remove() y Operation(), que son los nombres que usa el patrón, y hay tres clases
    • En main los objetos se crean con new, se guardan en punteros a Trabajo y al final se borran con delete
    • Trabajo tiene métodos virtual y un destructor virtual, y las otras dos clases usan override

    Tres elementos: quién hereda de quién, qué guarda la clase del medio y qué hace en su método.

    Los elementos son los de la forma: la herencia, la lista de la misma base y el bucle que pasa el pedido y junta el resultado. Los nombres de los métodos sirven de confirmación, pero en un parcial pueden venir cambiados. new, delete, virtual y override aparecen en cualquier programa con herencia: no identifican a ningún patrón.

  16. Para cerrar la respuesta: ¿qué se gana con el patrón en este código?

    • Presupuestar trata igual a una tarea sola que a una etapa entera: recibe un Trabajo y llama a Operation(), sin preguntar qué es
    • Presupuestar puede cambiar la forma de calcular el costo mientras el programa corre, sin tocar las tareas ni las etapas
    • Todo el programa usa la misma obra, a través de un único punto de acceso, y no se puede crear una segunda
    • Presupuestar puede usar una clase que tenía otra interfaz, sin modificar ni esa clase ni la función

    Es la tercera oración de la descripción de Composite: “Así el cliente trata igual a...”.

    La tercera oración de Composite: “Así el cliente trata igual a un elemento solo que a un grupo entero”, dicha con el caso. Se ve en main: la misma función presupuesta pintura, que es una tarea, y obra, que es una etapa con otra etapa adentro, y si mañana se agrega una etapa más, Presupuestar no cambia.
