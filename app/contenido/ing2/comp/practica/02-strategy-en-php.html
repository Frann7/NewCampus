Ejercicio 2 · Strategy

Reconocer el patrón en un código PHP

Guía N°3, ejercicio 3. Identifique el patrón que aparece en el siguiente código en PHP. Realice el diagrama del mismo. Mencione ventajas y desventajas. 

<?php
namespace RefactoringGuru\123\Conceptual;
class Context
{
    private $dispositivo;
    public function __construct(dispositivo $dispositivo)
    {
        $this->dispositivo = $dispositivo;
    }
    public function setdispositivo(dispositivo $dispositivo)
    {
        $this->dispositivo = $dispositivo;
    }
    public function doSomeBusinessLogic(): void
    {
        echo "Context: Sorting data using the dispositivo (not sure how it'll do it)\n";
        $result = $this->dispositivo->doAlgorithm(["a", "b", "c", "d", "e"]);
        echo implode(",", $result) . "\n";
    }
}
interface dispositivo
{
    public function doAlgorithm(array $data): array;
}
class ConcretedispositivoA implements dispositivo
{
    public function doAlgorithm(array $data): array
    {
        sort($data);
        return $data;
    }
}
class ConcretedispositivoB implements dispositivo
{
    public function doAlgorithm(array $data): array
    {
        rsort($data);
        return $data;
    }
}
$context = new Context(new ConcretedispositivoA());
echo "Client: dispositivo is set to normal sorting.\n";
$context->doSomeBusinessLogic();
echo "\n";
echo "Client: dispositivo is set to reverse sorting.\n";
$context->setdispositivo(new ConcretedispositivoB());
$context->doSomeBusinessLogic();

3. ¿Hay métodos que devuelven un new?No. Los new están en el código cliente, al finalNo es Factory Method ni Abstract Factory
4. La clase que guarda a otras, ¿qué guarda?Context guarda un $dispositivo, de tipo interfaz, y tiene setdispositivo() para cambiarloStrategy
Paso 2 — Qué clase es cada parte
Parte del patrónEn el códigoQué lo confirma
ContextoContextRecibe la estrategia en el constructor, la puede cambiar con setdispositivo() y en doSomeBusinessLogic() le delega: $this->dispositivo->doAlgorithm(...)
Estrategiadispositivo (interfaz)Un solo método: doAlgorithm()
Estrategias ConcretasConcretedispositivoA, ConcretedispositivoBHacen lo mismo de distinta forma: sort ordena de menor a mayor y rsort al revés

dispositivo es el nombre que la cátedra puso en lugar de Strategy. El propio texto que imprime lo delata: "Sorting data using the dispositivo (not sure how it'll do it)", es decir, "ordenando con la estrategia; no sé cómo lo va a hacer". Esa es la idea del patrón: el contexto no sabe cuál tiene.

Paso 3 — Comprobarlo con lo que imprime 
Client: dispositivo is set to normal sorting.
Context: Sorting data using the dispositivo (not sure how it'll do it)
a,b,c,d,e

Client: dispositivo is set to reverse sorting.
Context: Sorting data using the dispositivo (not sure how it'll do it)
e,d,c,b,a

El mismo objeto $context, con la misma llamada doSomeBusinessLogic() y los mismos datos, dio dos resultados. Lo único que cambió en el medio fue setdispositivo(...). Esa es la señal 5 de la teoría.

Paso 4 — El diagrama
Respuesta

Es el patrón Strategy (de comportamiento). Context es el contexto: guarda una referencia a la interfaz dispositivo (la estrategia), la recibe en el constructor, la puede cambiar con setdispositivo() y le delega el trabajo en doSomeBusinessLogic(). ConcretedispositivoA y ConcretedispositivoB son las estrategias concretas, que ordenan de dos formas.

Ventajas:

  • Se puede cambiar el algoritmo de un objeto en tiempo de ejecución.
  • Los detalles del algoritmo quedan aislados del código que lo usa.
  • Se sustituye la herencia por composición.
  • Principio de abierto/cerrado: se agregan estrategias sin cambiar el contexto.

Desventajas:

  • Si hay pocos algoritmos y casi no cambian, complica el programa sin necesidad.
  • El cliente tiene que conocer las diferencias entre estrategias para elegir la adecuada.
