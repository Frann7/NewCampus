Ejercicio 2 · Validación

Validar primero el captcha y después los datos

2) Validación del formulario. Modifique el script que agrega los datos al formulario de manera tal que se valide primero el código verificador y luego, haciendo uso de las funciones ctype_, que valide los datos recibidos desde el form antes de ser guardados en la base de datos.

Paso 1 — Qué pide
  • "El script que agrega los datos" es procesoForm.php, el action del formulario del ejercicio 1.
  • Primero el código verificador (el captcha). Si no coincide, los datos vienen de un origen desconocido y ni se miran.
  • Después, los datos, con las funciones ctype_ (teoría, sección 7).
  • Recién si todo está bien se guardaría en la base de datos. Guardar es tema de la Clase 6: acá queda marcado con un comentario y se muestra un mensaje.
Paso 2 — Qué se valida en cada campo
CampoQué tiene que tenerCómo se prueba

Asuntoletras y números (con espacios)ctype_alnum después de sacar los espacios

Comentarioalgo escrito (es texto libre: lleva comas, puntos, signos)empty; ninguna ctype_ sirve para texto libre

Las herramientas de la Clase 2 que se usan: trim($x) saca los espacios del principio y del final; str_replace($buscar, $reemplazo, $texto) reemplaza, y $buscar puede ser un arreglo (reemplaza cada uno); strpos($texto, '@') da la posición de la @ o false si no está, y por eso se compara con === false (una @ en la posición 0 daría 0, que con == se confundiría con false).

Paso 3 — procesoForm.php 
<?php
session_start();

$errores = array();

// 1) Primero, el código verificador
if (empty($_POST['rand_code']) || empty($_SESSION['rand_code'])
    || $_POST['rand_code'] != $_SESSION['rand_code']) {

    $errores[] = 'El código verificador no coincide con el de la imagen.';

} else {

    // 2) Después, los datos
    $nombre     = trim($_POST['nombre']);
    $asunto     = trim($_POST['asunto']);
    $correo     = trim($_POST['correo']);
    $comentario = trim($_POST['comentario']);

    if (!ctype_alpha(str_replace(' ', '', $nombre))) {
        $errores[] = 'El nombre solo puede tener letras.';
    }

    if (!ctype_alnum(str_replace(' ', '', $asunto))) {
        $errores[] = 'El asunto solo puede tener letras y números.';
    }

    $sinSimbolos = str_replace(array('@', '.', '_', '-'), '', $correo);
    if (strpos($correo, '@') === false || !ctype_alnum($sinSimbolos)) {
        $errores[] = 'El correo no es válido.';
    }

    if (empty($comentario)) {
        $errores[] = 'El comentario está vacío.';
    }
}

// El código sirve para un solo envío
unset($_SESSION['rand_code']);

if (count($errores) > 0) {
    foreach ($errores as $error) {
        echo $error . '<br>';
    }
} else {
    // Acá se guardan los datos en la base de datos (Clase 6)
    echo 'Gracias, ' . $nombre . ': recibimos tu comentario.';
}
?>

El límite de ctype_alpha: el caso 5

José Muñoz se rechaza porque para ctype_alpha la é y la ñ no son letras (teoría, sección 7). Es lo que da la herramienta que pide la guía. Si en el formulario se aclara "sin tildes", el mensaje de error tiene que decirlo también, para que la persona entienda por qué se rechazó.

Resultado

procesoForm.php rechaza todo si el captcha no coincide; si coincide, valida nombre, asunto y correo con ctype_alpha / ctype_alnum y el comentario con empty, junta los errores en $errores y borra el código para que no se reuse. La guía no trae resolución de la cátedra para comparar.
