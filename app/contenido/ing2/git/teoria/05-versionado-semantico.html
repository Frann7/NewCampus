Versiones

5. Versionado semántico

Para qué sirve

Ponerle un número de versión al software se llama versionado. Si cada uno numera como quiere, el número no dice nada. El estándar más usado es SemVer (Semantic Versioning, Versionado Semántico), escrito por Tom Preston-Werner, cofundador de GitHub. Con SemVer el número avisa qué tipo de cambio hubo: quien usa el software sabe, mirando la versión, si puede actualizar tranquilo o si algo se le puede romper.

Sintaxis

MAYOR.MENOR.PARCHE

Qué es cada parte

ParteSe incrementa cuando...Ejemplo
MAYORse hace un cambio incompatible con lo anterior: lo que funcionaba con la versión vieja puede dejar de funcionar.1.4.2 → 2.0.0
MENORse agrega funcionalidad compatible con las versiones anteriores.1.4.2 → 1.5.0
PARCHEse corrigen errores, de forma compatible.1.4.2 → 1.4.3
La regla del reinicio

Cuando sube un número, los que están a su derecha vuelven a 0:

  • al subir el MENOR, el PARCHE se reinicia a 0;
  • al subir el MAYOR, el MENOR y el PARCHE se reinician a 0.

El apunte habla de "el API público": es la parte del software que usan otros programas. Un cambio "incompatible en el API" es el que obliga a quienes lo usan a modificar su propio código.

Otras reglas de la especificación

  • Una versión publicada no se modifica: cualquier cambio se publica como una versión nueva.
  • La versión mayor en cero (0.y.z) es para el desarrollo inicial: todo puede cambiar en cualquier momento. La 1.0.0 es la primera versión estable.
  • Precedencia (cuál es más nueva): se comparan los números de izquierda a derecha. 1.0.0 < 2.0.0 < 2.1.0 < 2.1.1.
  • Una versión de prelanzamiento (con una etiqueta después de un guion) es anterior a la versión normal: 1.0.0-alpha < 1.0.0.

Las etiquetas

EtiquetaQué esPara quién
AlphaVersión inicial en desarrollo. No está completa ni estable; puede tener muchos errores y le faltan funcionalidades principales.Un grupo reducido de testers o desarrolladores, para probar ideas
BetaMás avanzada: ya tiene la mayoría de las funcionalidades, pero puede tener fallos o problemas de rendimiento.Un público más amplio (beta testers), para detectar errores y validar la usabilidad
Pre-releaseVersión candidata, cercana a la final (Release Candidate). Prácticamente terminada: solo se esperan errores menores.Usuarios avanzados o testers, como "vista previa"

Errores y trampas

Olvidarse de reiniciar

De 2.3.4, agregar una función da 2.4.0, no 2.4.4. Y un cambio incompatible da 3.0.0, no 3.3.4.

No son decimales

Cada parte es un número entero aparte: después de 1.9.0 viene 1.10.0, no 2.0.0. Y 1.10.0 es más nueva que 1.9.0.

El tamaño del cambio no importa

Lo que decide es la compatibilidad, no cuánto código se tocó. Un cambio de una línea que rompe a quienes usan el software sube el MAYOR; mil líneas de arreglos internos suben el PARCHE.
