Ejercicio 4 · CMMI · Nivel 2

El caso típico de nivel 2: el sistema para la universidad

Práctica 2 de CMMI, ejercicio 2.

Una empresa de software trabaja desde hace varios años desarrollando sistemas para universidades. Los proyectos cuentan con responsables asignados, cronogramas, presupuestos y mecanismos para realizar el seguimiento de las actividades. En cada proyecto se registran los requisitos solicitados por el cliente, los cambios realizados y los problemas encontrados. El jefe de proyecto revisa periódicamente el avance y compara las horas trabajadas con las horas estimadas. Cuando se detecta un desvío importante, se toman acciones correctivas.

La empresa también exige que los equipos realicen reuniones de seguimiento y documenten determinados resu ltados. Gracias a estas prácticas, los responsables pueden conocer el estado de los proyectos y detectar anticipadamente algunos problemas.

Sin embargo, al analizar varios proyectos se observa que cada equipo utiliza sus propios procedimientos. Algunos reg istran los requisitos utilizando una herramienta, mientras que otros utilizan documentos diferentes. Los criterios para realizar las pruebas también varían de un proyecto a otro.

La dirección considera que sería conveniente establecer una forma común de trabajar. Para ello, está analizando la posibilidad de crear procedimientos organizacionales que puedan ser utilizados como referencia por todos los proyectos, permitiendo realizar adaptaciones cuando las características particulares de un proyecto lo requieran.

Consignas:

  • Determine en qué situación de madurez se encuentra actualmente la organización.
  • ¿Qué característica principal permite identificar dicha situación?
  • ¿Qué debería implementar la organización para avanzar al siguiente nivel?
  • Explique cómo cambiaría la forma de trabajar de los proyectos después de implementar esa mejora.

Respuesta

Situación de madurez: Nivel 2 (Gestionado).

Característica principal: los proyectos están planificados y controlados (responsables, cronogramas, presupuestos, seguimiento y acciones correctivas), pero la gestión es proyecto por proyecto: cada equipo usa sus propios procedimientos.

Qué debería implementar: procedimientos organizacionales, es decir un proceso estándar documentado que todos los proyectos tomen como referencia, con reglas para adaptarlo cuando un proyecto lo necesite. Eso es el Nivel 3 (Definido).

Cómo cambiaría la forma de trabajar: todos los proyectos arrancarían del mismo proceso; los requisitos se registrarían de la misma manera y con la misma herramienta; las pruebas tendrían los mismos criterios; las adaptaciones se justificarían; los integrantes serían capacitados en la metodología y podrían pasar de un equipo a otro; y los proyectos se podrían comparar entre sí.

Comparar horas no es gestión cuantitativa

Es la confusión que busca este caso. Mirar si un proyecto va atrasado contra su propio plan es control de proyecto (nivel 2). El nivel 4 usa datos históricos de muchos proyectos para saber cómo se comporta el proceso y predecir.
