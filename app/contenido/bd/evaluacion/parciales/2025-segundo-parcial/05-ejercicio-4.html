Qué pide

Escribir, en el lenguaje SQL, la orden que le dice a la base de datos "creá esta tabla, con estas columnas y estas claves". Sale de la tabla Animal del ejercicio 3: 

Animal (NumeroHC (PK), Nombre, Raza, Sexo, FechaNac, Peso, Documento (FK))
Propietario (Documento (PK), Nombre, Direccion, IdCiudad (FK))

Las palabras que se usan, una por una

Una orden de SQL se llama sentencia. Se escribe con palabras fijas del lenguaje (en mayúscula, por costumbre) y los nombres que uno inventa (la tabla, las columnas).

Pieza 3 — La clave primaria 
CONSTRAINT PK_Animal PRIMARY KEY (NumeroHC)

Se lee: "una regla llamada PK_Animal: la clave primaria es NumeroHC". El nombre (PK_ + la tabla) lo elige uno; los profes piden ponérselo.

Pieza 4 — La clave foránea 
CONSTRAINT FK_Animal_Propietario FOREIGN KEY (Documento) REFERENCES Propietario(Documento)

Se lee: "una regla llamada FK_Animal_Propietario: la columna Documento de esta tabla apunta a la columna Documento de la tabla Propietario". Desde ahí, la base no deja cargar un animal con un documento que no exista entre los propietarios. Por eso Propietario tiene que estar creada antes.

Resolución 
CREATE TABLE Animal (
  NumeroHC   INT           NOT NULL,
  Nombre     VARCHAR(50)   NOT NULL,
  Raza       VARCHAR(50),
  Sexo       CHAR(1),
  FechaNac   DATE,
  Peso       DECIMAL(5,2),
  Documento  VARCHAR(13)   NOT NULL,
  CONSTRAINT PK_Animal PRIMARY KEY (NumeroHC),
  CONSTRAINT FK_Animal_Propietario FOREIGN KEY (Documento) REFERENCES Propietario(Documento)
);

Una coma al final de cada línea, menos la última; y el ; después del paréntesis de cierre.

Trampas

  • "Con sus claves correspondientes": sin la FOREIGN KEY la respuesta queda incompleta.
  • El tipo de Documento tiene que ser el mismo que el de la PK de Propietario.
  • Una coma de más antes del ) final es el error de sintaxis más común.
  • El peso en INT pierde los decimales; el sexo como VARCHAR(20) no está mal, pero CHAR(1) es lo justo.
