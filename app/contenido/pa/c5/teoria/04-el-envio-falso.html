Asegurar formularios

4. El problema: un programa que se hace pasar por tu formulario

Para qué sirve entender esto

Cuando un formulario se envía, el script del action recibe los datos en $_GET, $_POST o $_REQUEST (Clase 3). Uno da por hecho que esos datos vienen de su formulario. La cátedra pregunta: ¿es siempre así?

No. Lo que le llega al servidor es solo un pedido (en inglés, request): "mandame procesoFormulario.php con estos campos por POST". El servidor no puede ver si detrás hubo una persona que tocó "Enviar" en tu página o un programa que armó el mismo pedido. Y un programa lo puede repetir miles de veces por minuto.

El formulario y el script de la cátedra

El formulario manda nombre y apellido por POST:

<form action="http://ejemplo.com/procesoFormulario.php" method="post">
    <input type="text" name="nombre">
    <input type="text" name="apellido">
    <input type="submit" value="Enviar el formulario">
</form>

Y procesoFormulario.php los toma de $_POST y los inserta en la tabla personas de una base de datos (las dos últimas líneas son de la Clase 6; acá alcanza con saber que guardan un registro cada vez que el script corre): 

<?php
$nombre = $_POST['nombre'];
$apellido = $_POST['apellido'];
$sql = "INSERT INTO personas VALUES (null, '$nombre', '$apellido')";
$mysqli = new mysqli("localhost", "root", "toto", "basedatos");
$mysqli->query($sql);
?>

Sintaxis del ataque: las funciones de cURL

cURL es una herramienta que trae PHP para mandar pedidos a otra página desde un script, como si fuera un navegador. El ataque de la cátedra la usa así:

Mandar un POST desde PHP 
$campos_string = http_build_query($fields);        // arma "campo=valor&campo=valor"
$ch = curl_init();                                  // prepara un pedido nuevo
curl_setopt($ch, CURLOPT_URL, $url);                // a qué dirección
curl_setopt($ch, CURLOPT_POST, true);               // por el método POST
curl_setopt($ch, CURLOPT_POSTFIELDS, $campos_string); // con estos campos
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);     // la respuesta, devolvémela
$result = curl_exec($ch);                           // lo manda
curl_close($ch);                                    // lo cierra

Qué es cada parte

ParteQué hace
http_build_query($arreglo)Convierte un array asociativo en el texto que manda un formulario: clave=valor unidos con &. Los espacios y símbolos los codifica (+, %26...).
curl_init()Crea un pedido vacío y lo devuelve; se guarda en $ch (de cURL handle, "el manejador").
curl_setopt($ch, OPCIÓN, valor)Configura una opción del pedido. Una llamada por opción.
CURLOPT_URLLa dirección del script que va a recibir el pedido.
CURLOPT_POSTCon true, el pedido va por POST (llena $_POST del otro lado).
CURLOPT_POSTFIELDSLos campos que se mandan, como los armó http_build_query.
CURLOPT_RETURNTRANSFERCon true, curl_exec devuelve lo que contestó el servidor en vez de imprimirlo.
curl_exec($ch)Manda el pedido. Devuelve la respuesta (lo que el otro script imprimió).
curl_close($ch)Libera el pedido.

Ejemplo 1 — Qué arma http_build_query

Enunciado

¿Cuál es la salida del siguiente script PHP?

<?php
$fields = ['nombre' => 'Federico', 'apellido' => 'Bonnet'];
echo http_build_query($fields);
echo '<br>';
echo http_build_query(['usuario' => 'Juan Perez', 'clave' => 'a&b']);
?>

Qué hace cada línea

LíneaQué haceCómo quedan las variables
$fields = [...]Array asociativo con dos campos. Los corchetes [ ] son otra forma de escribir array( ).$fields: nombre => Federico, apellido => Bonnet
echo http_build_query($fields);Une cada clave con su valor por = y los pares por &.imprime nombre=Federico&apellido=Bonnet
echo '<br>';Salto de línea en el navegador.—
echo http_build_query([...]);El espacio de Juan Perez se codifica como + y el & de a&b como %26, para que no se confunda con el separador.imprime usuario=Juan+Perez&clave=a%26b

Qué imprime y por qué

En el navegador (el <br> es el salto de línea):

nombre=Federico&apellido=Bonnet
usuario=Juan+Perez&clave=a%26b

Es exactamente el texto que manda el navegador cuando alguien completa el formulario y toca "Enviar". Del otro lado, PHP lo desarma y llena $_POST['nombre'], $_POST['apellido']: no hay forma de distinguirlo.

Ejemplo 2 — El ataque del ejemplo ataqueForm (formato del parcial)

Enunciado

procesoForm.php imprime lo que recibe por POST: echo "USUARIO: ".$_POST['usuario']; echo "==>"; echo "CONTRASEÑA: ".$_POST['contrasenia']; echo "<br>";. ¿Qué imprime el siguiente script, y cuántas veces corrió procesoForm.php? 

<?php
$url = "http://localhost/clase5/ataqueForm/procesoForm.php";
for ($i = 1; $i <= 10; $i++) {
    $usuario = 'Federico';
    $contrasenia = 'Bonnet';
    $fields = ['usuario' => $usuario, 'contrasenia' => $contrasenia];
    $campos_string = http_build_query($fields);
    $ch = curl_init();
    curl_setopt($ch, CURLOPT_URL, $url);
    curl_setopt($ch, CURLOPT_POST, true);
    curl_setopt($ch, CURLOPT_POSTFIELDS, $campos_string);
    curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
    $result = curl_exec($ch);
    print_r($result);
    curl_close($ch);
}
?>

procesoForm.php corrió 10 veces y las diez creyó que alguien había completado el formulario. Si en vez de imprimir guardara en la base, serían 10 registros falsos. El ejemplo del PDF hace lo mismo con el for hasta 1000000000000 (un billón): un billón de registros.

Conclusión de la cátedra: procesoForm.php tiene que poder reconocer solamente los datos que provengan de nuestro formulario y descartar los demás. Las dos formas que da la clase son el token (sección 5) y el captcha (sección 6).

Errores y trampas

Lo que más se confunde
  • Lo que pone el HTML no protege nada. El required del campo usuario, un maxlength o una validación en JavaScript los respeta el navegador; cURL ni siquiera abre la página del formulario. El control tiene que estar en el script PHP que recibe.
  • Erratas del PDF. El formulario usa comillas tipográficas (method=”post”): el navegador no las reconoce y el formulario termina mandando por GET. Van comillas rectas, "post". Y la consulta dice 'apellido' sin el $: se probó y guarda la palabra apellido en vez del apellido (... VALUES (null,'Ana','apellido')).
