4. Git: las tres secciones y los tres estados

Nombre las tres secciones de un proyecto Git y los tres estados en los que puede estar un archivo. Luego indique en qué estado y en qué sección queda un archivo después de cada una de estas acciones, hechas en este orden:

  1. Se edita el archivo y se guarda.

Qué es un repositorio

Es la carpeta del proyecto más su historial. Git guarda, en una subcarpeta llamada .git, una foto de todos los archivos cada vez que confirmás un cambio; con esas fotos se puede volver a cualquier versión anterior. Ese historial está completo en tu computadora (repositorio local) y hay otra copia en un servidor, como GitHub, que comparte el equipo (repositorio remoto).

El remoto es un cuarto lugar, fuera de tu computadora: la copia del álbum que ve todo el equipo. No es una de las tres secciones.

Qué mueve cada comando
ComandoDe dónde a dónde mueve el archivoEstado en que queda
(editar y guardar)No lo mueve: el cambio está solo en el directorio de trabajoModificado
git add archivoDirectorio de trabajo → área de preparaciónPreparado
git commit -m "mensaje"Área de preparación → directorio de Git (repositorio local)Confirmado
git push origin ramaRepositorio local → repositorio remotoConfirmado, y ahora lo ve el equipo

git commit guarda solo lo que está preparado: por eso el add va siempre antes. Y git push sube commits: por eso va después del commit.

Trampas

  • Guardar no es confirmar: guardar en el editor deja el archivo modificado; faltan add y commit.
  • Confirmar no es subir: el commit queda en el repositorio local y nadie más lo ve hasta el push.
  • Los estados son tres, no cuatro: el push no crea un estado nuevo; el archivo sigue confirmado, y además está en el remoto.
