Validar los datos

7. Validar los datos: ctype_digit, ctype_alpha y ctype_alnum

Para qué sirve

El token y el captcha dicen de dónde vienen los datos. Falta revisar qué vienen: que en "edad" haya un número, que en "nombre" haya letras. La guía pide hacerlo con tres funciones que miran todos los caracteres de un texto y devuelven true solo si todos son del tipo pedido. Así se evita guardar en la base datos que no corresponden (o que podrían dañarla).

Sintaxis

Las tres funciones 
ctype_digit($texto)   // true si son todos dígitos (0 a 9)
ctype_alpha($texto)   // true si son todas letras (a-z, A-Z)
ctype_alnum($texto)   // true si son todas letras o dígitos

Qué es cada parte

FunciónAceptaRechaza
ctype_digit0123456789signo -, punto o coma decimal, espacios, letras

El nombre viene de character type (tipo de carácter); digit es dígito, alpha es alfabético y alnum es alfanumérico. Las tres dan false con el texto vacío "".

Ejemplo 1 — Validar una edad

Enunciado

Un formulario manda la edad en $_POST['edad']. ¿Qué imprime este script si llega "25"? ¿Y si llega "25 años"? 

<?php
$edad = $_POST['edad'];
if (ctype_digit($edad)) {
    echo 'Edad válida: ' . $edad;
} else {
    echo 'La edad tiene que ser un número.';
}
?>

Ejemplo 2 — ¿Qué valores devuelve? (formato del parcial)

Enunciado

¿Cuál es la salida del siguiente script PHP?

<?php
var_dump(ctype_alpha('Juan Perez'));
var_dump(ctype_alpha(str_replace(' ', '', 'Juan Perez')));
var_dump(ctype_alnum('abc123'));
var_dump(ctype_digit('12.5'));

La segunda línea es el truco para validar un nombre con espacios: se sacan los espacios solo para la prueba, y se guarda el nombre original.

Errores y trampas

Lo que más se confunde
  • Tildes y ñ no son letras para ctype_alpha. 'José' y 'Muñoz' dan false. Es una limitación real: un formulario que valida el nombre así rechaza a José Muñoz.
  • Un campo vacío no pasa ninguna. ctype_digit('') da false, así que la validación ya rechaza los campos en blanco.
  • Números negativos y con decimales no pasan ctype_digit: el - y el . no son dígitos.
  • Siempre con texto. Lo que llega de un formulario ya es texto, así que no hay problema. Pero si le pasás un número entero sin comillas la respuesta sorprende: ctype_digit(5) da false y ctype_digit(53) da true, porque con enteros chicos PHP mira el carácter de ese código (el 53 es el carácter '5'). Desde PHP 8.1 además avisa que está en desuso.
  • Un correo no se valida con una sola ctype_: tiene @ y .. En el ejercicio 2 de la práctica se resuelve sacando esos símbolos con str_replace y buscando la @ con strpos.
