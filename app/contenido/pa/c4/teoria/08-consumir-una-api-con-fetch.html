8. Consumir una API con fetch

Para qué sirve

Consumir una API es pedirle datos y usarlos. En JavaScript se hace con la función fetch ("ir a buscar"): pide una URL por HTTP, sin recargar la página, y cuando llega la respuesta ejecuta el código que le digas. Así una página puede, por ejemplo, llenar una lista de provincias con los datos oficiales.

Sintaxis (diapositiva 17)

fetch(url)
    .then(response => response.json())
    .then(data => console.log(data))
    .catch(error => console.error("Error:", error));

Qué es cada parte

Un pedido por internet tarda. Si JavaScript se quedara esperando, la página se congelaría. Por eso fetch no devuelve los datos: devuelve una promesa, un objeto que dice "la respuesta va a llegar más adelante". El código sigue de largo, y cuando la respuesta llega se ejecutan, en orden, las funciones de los .then.

PiezaQué hace
fetch(url)Hace el pedido (por defecto, un GET: "dame esto"). Devuelve una promesa
.then(response => response.json())Cuando llega la respuesta, recibe un objeto Response (todavía no son los datos). response.json() lee el cuerpo y lo convierte de texto JSON a objeto. Como leerlo también tarda, devuelve otra promesa
.then(data => ...)Recibe lo que devolvió el then anterior, ya convertido: el objeto con los datos. Acá se usan
.catch(error => ...)Se ejecuta si algo de la cadena falló (no hay conexión, el servidor no existe, el JSON vino roto)
console.errorComo console.log, pero lo marca en rojo como error

Lo que trae el objeto Response

Propiedad o métodoQué da
response.oktrue si la petición fue exitosa (código entre 200 y 299), false si no
response.statusEl código HTTP: 200, 404, 500...
response.json()El cuerpo convertido de JSON a objeto
response.text()El cuerpo como texto crudo, sin convertir
response.blob()El cuerpo como archivo binario (una imagen, un PDF)

Ejemplo 1 — Pedir un usuario

Enunciado

¿Qué muestra la consola?

fetch("https://jsonplaceholder.typicode.com/users/1")
    .then(response => {
        console.log(response.status, response.ok);
        return response.json();
    })
    .then(data => {
        console.log(data.name);
        console.log(data.address.city);
    })
    .catch(error => console.error("Error:", error));
LíneaQué haceCómo quedan las variables
fetch("...users/1")Pide el usuario número 1 a la API de prueba—
1er thenLlega la respuesta. Imprime su código y si salió bien. Como esta flecha tiene llaves, hace falta return para pasarle algo al siguiente thenresponse.status = 200, response.ok = true
return response.json();Convierte el cuerpo a objeto y se lo pasa al siguiente then—
2do thenRecibe el objeto. Lee name y, dentro de address, citydata = objeto con id, name, username, email, address, phone, website, company
.catchNo se ejecuta: no hubo error—

Qué muestra (verificado con Node.js contra la API real; son datos de prueba fijos):

200 true
Leanne Graham
Gwenborough

Por qué: la respuesta es un JSON con objetos adentro de objetos; data.address.city encadena dos puntos para entrar dos niveles, como datos.habilidades[0] en la sección 7.

Ejemplo 2 — ¿En qué orden se imprime?

Enunciado

¿En qué orden aparecen los tres mensajes?

console.log("1");
fetch("https://jsonplaceholder.typicode.com/users/1")
    .then(response => response.json())
    .then(data => console.log("3"));
console.log("2");
MomentoQué pasaConsola
console.log("1");Se ejecuta enseguida1
fetch(...)Lanza el pedido y registra los then para cuando llegue. No espera1
console.log("2");Se ejecuta enseguida, mientras el pedido todavía viaja1, 2
(llega la respuesta)Recién ahora corren los then1, 2, 3

Qué muestra (verificado con Node.js):

1
2
3

Por qué: lo de adentro de un then no corre en el orden en que está escrito, sino cuando llega la respuesta. Es la trampa típica: el "3" está escrito antes que el "2" y sale después.

Ejemplo 3 — Un 404 no va al catch

Enunciado

El usuario 999 no existe. ¿Qué muestra la consola? ¿Se ejecuta el catch?

fetch("https://jsonplaceholder.typicode.com/users/999")
    .then(response => {
        console.log(response.status, response.ok);
        return response.json();
    })
    .then(data => console.log(JSON.stringify(data)))
    .catch(error => console.log("catch:", error.message));
LíneaQué haceCómo quedan las variables
fetch(".../users/999")Pide un usuario inexistente. El servidor contesta, con un 404—
1er thenSe ejecuta igual: hubo respuestastatus = 404, ok = false
2do thenEsta API contesta el 404 con un objeto vacíodata = {}
.catchNo se ejecuta—

Qué muestra (verificado con Node.js contra la API real):

404 false
{}

Por qué: para fetch, un 404 o un 500 no son errores: el servidor respondió. El catch solo atrapa cuando no hubo respuesta (sin conexión, dominio que no existe) o cuando algo falla adentro de un then. Para distinguir un 404 hay que mirar response.ok. Los ejemplos de la cátedra no lo miran: si la API contestara un error, el código intentaría usar datos que no están.

Errores y trampas

Usar los datos afuera del then

let datos; fetch(url).then(r => r.json()).then(d => { datos = d; }); console.log(datos); muestra undefined: el console.log corre antes de que llegue la respuesta (ejemplo 2). Todo lo que use los datos va adentro del último then, o en un método que se llame desde ahí.

Llaves sin return

.then(response => response.json()) devuelve solo, porque es una flecha sin llaves. Si le ponés llaves, .then(response => { response.json(); }), no devuelve nada y el siguiente then recibe undefined. Con llaves, hace falta return (ejemplo 1).

response no son los datos

.then(response => console.log(response.nombre)) da undefined: el objeto Response no tiene las claves del JSON. Primero response.json(), y los datos llegan en el then siguiente.

Una API externa puede cambiar

Los datos y hasta el formato de la respuesta los decide quien mantiene la API. Si cambia o se cae, la página deja de andar sin que hayas tocado tu código.
