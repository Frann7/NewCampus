✓ ResultadosSolo la respuesta

Es el patrón Facade (estructural). YouTubeDownloader es la fachada: guarda un objeto de cada clase del subsistema (YouTube y FFMpeg), los crea en su constructor y ofrece un único método simple, downloadVideo(), que por dentro coordina todos los pasos. El cliente usa solo la fachada. Las clases del subsistema no heredan de nada en común ni conocen a la fachada.

Qué evalúa

Reconocer un patrón por la forma del código, sin depender de los nombres, y decir qué elementos lo delatan. Fue en PHP; en 2024 fue el mismo patrón en C++, y este año el código es en C++. Abajo está este mismo código pasado a C++.

Paso 3 — Las preguntas para reconocer un código
  1. ¿Hay algo static y un constructor que no es público? FFMpeg::create() es estático, pero los constructores son públicos y no hay un atributo estático que guarde la instancia. No es Singleton.
  2. ¿Alguna clase hereda de otra? Ninguna. → Facade.

Se confirma con el resto:

  • YouTubeDownloader guarda un objeto de cada una de dos clases sueltas y distintas, y las crea ella misma.
  • Su único método, downloadVideo(), hace en orden toda una secuencia: traer los datos del video, guardarlo, procesarlo, redimensionarlo, capturar una imagen y guardarlo en tres formatos.
  • El cliente (clientCode) hace una sola llamada y no conoce ni a YouTube ni a FFMpeg.

Paso 5 — El mismo código en C++

Como lo tomarían este año. Está compilado y corrido.

#include <iostream>
#include <string>

class YouTube {
 public:
  YouTube(std::string apiKey) {}
  std::string fetchVideo(std::string url) const {
    return "video";
  }
  void saveAs(std::string url, std::string path) const {}
};

class FFMpegVideo {
 public:
  void filters() {}
  void resize() {}
  void synchronize() {}
  void frame() {}
  void save(std::string path) {}
};

class FFMpeg {
 public:
  FFMpegVideo* open(std::string video) const {
    return new FFMpegVideo;
  }
};

class YouTubeDownloader {
 protected:
  YouTube* youtube_;
  FFMpeg* ffmpeg_;

 public:
  YouTubeDownloader(std::string youtubeApiKey) {
    youtube_ = new YouTube(youtubeApiKey);
    ffmpeg_ = new FFMpeg;
  }

  ~YouTubeDownloader() {
    delete youtube_;
    delete ffmpeg_;
  }

  void downloadVideo(std::string url) {
    std::cout << "Fetching video metadata from youtube...\n";
    std::string title = youtube_->fetchVideo(url);
    std::cout << "Saving video file to a temporary file...\n";
    youtube_->saveAs(url, "video.mpg");

    std::cout << "Processing source video...\n";
    FFMpegVideo* video = ffmpeg_->open("video.mpg");
    std::cout << "Normalizing and resizing the video to smaller dimensions...\n";
    video->filters();
    video->resize();
    video->synchronize();
    std::cout << "Capturing preview image...\n";
    video->frame();
    video->save(title + "frame.jpg");
    std::cout << "Saving video in target formats...\n";
    video->save(title + ".mp4");
    video->save(title + ".wmv");
    video->save(title + ".webm");
    std::cout << "Done!\n";
    delete video;
  }
};

void clientCode(YouTubeDownloader* api) {
  api->downloadVideo("https://www.youtube.com/watch?v=QH2-TGUlwu4");
}

int main() {
  YouTubeDownloader* api = new YouTubeDownloader("APIKEY-XXXXXXXXX");
  clientCode(api);
  delete api;
  return 0;
}

Las señales son las mismas: ninguna clase tiene : public ...; YouTubeDownloader guarda YouTube* youtube_ y FFMpeg* ffmpeg_ y los crea con new en su constructor; y downloadVideo() llama en orden a los métodos del subsistema. main escribió una sola línea de trabajo y salieron siete pasos.

Trampas

  • El static function create() puede hacer pensar en Singleton o en una fábrica, pero es un método suelto de una clase del subsistema; no hay instancia única ni método fábrica sobrescrito.
  • No es Adapter: la fachada no hereda de ninguna interfaz y envuelve varias clases, no una.
  • La consigna pide "qué elementos ayudaron a identificarlo": hay que nombrarlos (los atributos del subsistema, el constructor que los crea, el método único, el cliente).
