17. Git: claves SSH, repositorio y ramas

Unidad 6 · Git

Explique qué es un par de claves SSH y para qué se usa con GitHub o GitLab. Indique los comandos para configurar Git por primera vez, obtener un repositorio de las dos formas posibles y manejar ramas. ¿Para qué sirve el archivo .gitignore?

✓ RespuestaPara aprender y escribir en la hoja

Claves SSH: un par de claves para autenticarse en GitHub o GitLab sin escribir usuario y contraseña. La pública se sube a la plataforma; la privada queda secreta en la computadora. Se generan con ssh-keygen.

  • Configurar: git config --global user.name "..." y git config --global user.email ...
  • Obtener el repositorio: git init (crea uno nuevo en la carpeta) o git clone [url] (copia uno que ya existe).
  • Ramas: git checkout -b rama (crear y cambiarse), git branch (ver), git checkout rama (cambiarse), git push -u origin rama (subir), git branch -d rama (borrar).
  • .gitignore: lista los archivos que Git no tiene que seguir (generados, de compilación).

Con más detalle

Claves SSH: un par de claves, una pública y una privada, para autenticarse de forma segura en servidores y plataformas de control de versiones (GitHub, GitLab, Bitbucket) sin escribir usuario y contraseña en cada acción.

  • Pública: se puede compartir; se sube a la plataforma (en GitHub, Configuración → Claves SSH y GPG).
  • Privada: secreta, queda en la computadora de uno; con ella se autentica al conectarse.
  • Se generan con ssh-keygen -b 2048 -t rsa -C "usuario" (Linux o Mac; en Windows, con PuTTYgen), de al menos 2048 bits, idealmente 4096. Quedan dos archivos: id_rsa (privada) e id_rsa.pub (pública).

Configurar Git por primera vez (la identidad que firma los commits):

git config --global user.name "John Doe"
git config --global user.email johndoe@example.com

Obtener un repositorio:

ComandoCuándoQué hace

git clone [url]Un repositorio que ya existe en un servidorCrea la carpeta, inicializa su .git, descarga toda la información y saca una copia de trabajo de la última versión

.gitignore: un archivo con patrones de los archivos que Git no tiene que seguir ni mostrar como no rastreados, como los que se generan solos (trazas, archivos de compilación). Por ejemplo, *.[oa] ignora los .o y los .a, y *~ los que terminan en ~.

La clave SSH, con una imagen

La pública es como un candado que le dejás a GitHub; la privada, la única llave que lo abre, y nunca sale de tu computadora. Cuando te conectás, GitHub comprueba que tenés la llave de ese candado y te deja pasar sin pedir contraseña.

El orden en que se usa todo

  1. Generar las claves y subir la pública a GitHub (una vez).
  2. Configurar nombre y email con git config (una vez).
  3. Obtener el repositorio: git init si el proyecto es tuyo y nuevo, git clone si ya existe.
  4. Trabajar en una rama: git checkout -b, git add, git commit, git push -u origin.

Trampas

  • La clave que se sube es la pública (.pub). La privada no se comparte nunca.
  • git init no descarga nada: arranca un repositorio vacío. El que descarga es git clone.
  • git checkout -b crea la rama y se cambia a ella; git checkout solo se cambia a una que ya existe.
  • Borrar la rama remota no borra la local, ni al revés.
