Ejercicio 3 · Pantalla de error

Una página que muestre el error y deje volver al formulario

3) Pantalla de error. En caso de que alguna de las pruebas de validación no sea pasada, diseñe una página que muestre el error que ha ocurrido y que permita volver al formulario para cargar los datos nuevamente.

Paso 1 — Qué pide
  • En el ejercicio 2, los errores se mostraban con echo sueltos. Ahora tienen que salir en una página propia, error.php.
  • Esa página muestra qué falló (los mensajes de $errores).
  • Y tiene un enlace de vuelta a formContacto.php.

La forma más simple es la de la teoría, sección 8: procesoForm.php arma $errores y, si hay alguno, hace require 'error.php'. Como el archivo traído ve las variables del que lo trae, error.php puede recorrer $errores directamente.

Paso 2 — error.php 
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>Error en el formulario</title>
</head>
<body>
    <h3>No se pudo enviar el comentario</h3>

    <ul>
    <?php
        foreach ($errores as $error) {
            echo '<li>' . $error . '</li>';
        }
    ?>
    </ul>

    <a href="formContacto.php">Volver al formulario</a>
</body>
</html>

Qué hace cada línea

LíneaQué hace
<!DOCTYPE html> ... <body>Una página HTML completa, con su título.
<h3>No se pudo enviar el comentario</h3>Dice qué pasó, en general.
<ul>Una lista con viñetas.
foreach ($errores as $error)Recorre los mensajes que dejó procesoForm.php.
echo '<li>' . $error . '</li>';Cada mensaje es un ítem de la lista.
<a href="formContacto.php">Vuelve al formulario. Al abrirse, el formulario borra el código viejo y la imagen trae uno nuevo: se puede cargar todo otra vez.
Paso 3 — El cambio en procesoForm.php

Todo queda igual que en el ejercicio 2 salvo el final. En vez de imprimir los errores, trae la pantalla de error: 

if (count($errores) > 0) {
    require 'error.php';
} else {
    // Acá se guardan los datos en la base de datos (Clase 6)
    echo 'Gracias, ' . $nombre . ': recibimos tu comentario.';
}
LíneaQué hace
if (count($errores) > 0)Si alguna prueba falló (el captcha o un dato).
require 'error.php';Ejecuta error.php en ese punto. Su HTML es lo que recibe el navegador, y su foreach usa el $errores de procesoForm.php.
elseSin errores: el mensaje de gracias (y el guardado, en la Clase 6).
Paso 4 — Qué se ve

Se probaron los mismos casos del ejercicio 2. Con todos los datos mal, el navegador recibe:

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>Error en el formulario</title>
</head>
<body>
    <h3>No se pudo enviar el comentario</h3>

    <ul>
    <li>El nombre solo puede tener letras.</li><li>El asunto solo puede tener letras y números.</li><li>El correo no es válido.</li><li>El comentario está vacío.</li>    </ul>

    <a href="formContacto.php">Volver al formulario</a>
</body>
</html>

Y en pantalla:

No se pudo enviar el comentario

  • El nombre solo puede tener letras.
  • El asunto solo puede tener letras y números.
  • El correo no es válido.
  • El comentario está vacío.

Volver al formulario
  • Con el captcha equivocado, la lista tiene un solo ítem: El código verificador no coincide con el de la imagen.
  • Con todo bien, no aparece la pantalla de error: sale Gracias, Juan Perez: recibimos tu comentario.
Trampas
  • error.php no se abre solo. Si alguien entra directo a error.php, no hay $errores: sale Warning: Undefined variable $errores y Warning: foreach() argument must be of type array|object, null given (se probó con la misma estructura en la teoría, sección 8). Es una página para ser traída con require.
  • Los datos escritos se pierden al volver: el enlace abre el formulario vacío. La guía pide "cargar los datos nuevamente", así que alcanza; conservarlos llevaría guardarlos en la sesión y escribirlos en los value del formulario.
Resultado

error.php lista los errores de $errores y enlaza a formContacto.php; procesoForm.php la trae con require 'error.php' cuando alguna validación falla. La guía no trae resolución de la cátedra para comparar.
