Armar páginas por partes

8. require y require_once: pegar un archivo dentro de otro

Para qué sirve

En los ejemplos de la cátedra todas las páginas tienen el mismo encabezado, el mismo menú y el mismo pie. Copiar ese HTML en cada archivo es un problema: si cambia el menú, hay que cambiarlo en todos. En la carpeta formularios la cátedra lo escribe una sola vez, en includes/head.php y includes/footer.php, y cada página los trae con require_once.

Sintaxis

Traer otro archivo 
require 'ruta/archivo.php';        // lo pega cada vez que aparece
require_once 'ruta/archivo.php';   // lo pega solo la primera vez

Qué es cada parte

ParteQué hace
requireEjecuta el otro archivo en ese punto, como si su contenido estuviera escrito ahí. Si el archivo tiene HTML, el HTML sale ahí; si tiene PHP, se ejecuta ahí.
require_onceLo mismo, pero si ese archivo ya se trajo antes en el mismo pedido, no lo vuelve a traer.
'ruta/archivo.php'La ruta, relativa a la carpeta del script que se abrió ('includes/head.php').
Las variablesSon compartidas: el archivo traído ve las variables que ya existían, y las que él crea siguen existiendo después.
Si el archivo no existeFatal error: el script se corta ahí ("require" = requerido).

Ejemplo 1 — require contra require_once

Enunciado

includes/cabecera.php tiene una sola línea de HTML: <h1>Mi sitio</h1>. ¿Qué devuelve cada uno de estos dos scripts?

a.php:

<?php
require_once 'includes/cabecera.php';
require_once 'includes/cabecera.php';
echo '<p>Contenido</p>';
?>

b.php:

<?php
require 'includes/cabecera.php';
require 'includes/cabecera.php';
echo '<p>Contenido</p>';
?>

Qué hace cada línea

LíneaEn a.phpEn b.php
primer require...Trae la cabecera: sale <h1>Mi sitio</h1>.Igual.
segundo require...require_once ve que ya la trajo: no hace nada.require la trae otra vez: sale de nuevo.
echo '<p>Contenido</p>';Sale el párrafo.Igual.

Qué devuelve y por qué

a.php:

<h1>Mi sitio</h1>
<p>Contenido</p>

b.php:

<h1>Mi sitio</h1>
<h1>Mi sitio</h1>
<p>Contenido</p>

Para un encabezado o una clase, que tienen que estar una sola vez, conviene require_once: por eso lo usan los ejemplos de la cátedra.

Ejemplo 2 — ¿Cuál es la salida? (las variables se comparten)

Enunciado

includes/lista.php recorre un arreglo $errores que no crea él. ¿Qué imprime v.php? ¿Y si se abre includes/lista.php solo?

includes/lista.php:

<?php
foreach ($errores as $error) {
    echo $error;
}
?>

v.php:

<?php
$errores = array('Falta el nombre.');
require 'includes/lista.php';
?>

Qué hace cada línea

LíneaQué haceCómo quedan las variables
$errores = array('Falta el nombre.');Crea el arreglo con un mensaje.$errores = ['Falta el nombre.']
require 'includes/lista.php';Ejecuta lista.php ahí mismo, así que el foreach ve el $errores de v.php.—
foreach ... echo $error;Una vuelta: imprime el mensaje.$error = 'Falta el nombre.'

Qué imprime y por qué

Falta el nombre.

Abierto solo, includes/lista.php no tiene ningún $errores: se probó y da Warning: Undefined variable $errores y Warning: foreach() argument must be of type array|object, null given. El archivo traído depende de lo que preparó el que lo trae. Así se arma la pantalla de error del ejercicio 3 de la práctica.

Errores y trampas

Lo que más se confunde
  • La ruta se busca primero desde la carpeta del script que se abrió en el navegador. formCaptcha.php trae 'includes/head.php' porque está un nivel arriba de includes/.
  • Si falta el archivo, se corta todo. Se probó con un archivo inexistente: Warning: require_once(...): Failed to open stream y después Fatal error: Uncaught Error: Failed opening required; lo que seguía no se ejecutó.
  • session_start() va antes del require_once del encabezado, porque el encabezado ya manda HTML (sección 1). Así lo hacen formToken.php y formCaptcha.php.
