DML

5. INSERT, UPDATE y DELETE

Las otras tres sentencias del DML (Unidad 1, sección 2). En el parcial no las pidieron como ejercicio, pero sí como parte de la pregunta de DML, y aparecen en las transacciones.

Las tres formas 
INSERT INTO Tabla (Columna1, Columna2) VALUES (valor1, valor2);

UPDATE Tabla SET Columna = nuevo_valor WHERE condición;

DELETE FROM Tabla WHERE condición;
  • INSERT: los valores van en el mismo orden que las columnas de la lista.
  • UPDATE: cambia las columnas del SET en las filas que cumplen el WHERE.
  • DELETE: borra las filas que cumplen el WHERE. La tabla sigue existiendo.

Ejemplo 1: cargar y corregir una especie

Tabla Especie (Codigo (PK), Nombre, NombreCientifico, Descripcion, CodigoZona (FK)). Cargar el ñandú en la zona 2 y después pasarlo a la zona 1.

INSERT INTO Especie (Codigo, Nombre, NombreCientifico, CodigoZona)
VALUES (14, 'Ñandú', 'Rhea americana', 2);

UPDATE Especie SET CodigoZona = 1 WHERE Codigo = 14;
  • Descripcion no está en la lista: queda vacía (puede, porque no es NOT NULL).
  • El INSERT funciona solo si la zona 2 existe: es la FK haciendo su trabajo.

Ejemplo 2: el WHERE que falta

¿Qué hacen estas dos sentencias?

UPDATE Turno SET Estado = 'Cancelado';
DELETE FROM Turno WHERE Estado = 'Cancelado';

El UPDATE no tiene WHERE: cancela todos los turnos. Y el DELETE después los borra todos. Por eso los cambios grandes se hacen dentro de una transacción (BEGIN TRAN): si el resultado no es el esperado, ROLLBACK y no pasó nada.

Errores y trampas
  • UPDATE y DELETE sin WHERE afectan a toda la tabla.
  • No se puede borrar una fila a la que otra apunta con una FK (una zona con especies): SQL Server lo rechaza.
  • DELETE FROM Turno deja la tabla vacía; DROP TABLE Turno (DDL) la hace desaparecer.
