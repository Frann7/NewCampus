3. Abstract Factory

También llamado Fábrica Abstracta.

Para qué sirve

El problema, con el ejemplo del apunte: una tienda de muebles.

  • Vende varios productos: silla, sofá, mesilla.
  • Cada producto viene en varias variantes (estilos): moderna, victoriana, art déco.
  • El cliente quiere muebles que combinen: si pide un juego moderno, no puede llegarle una silla moderna con un sofá victoriano.
  • Los catálogos cambian seguido: hay que poder agregar variantes sin tocar el código que ya funciona.

Un conjunto de productos que van juntos (silla moderna + sofá moderno + mesilla moderna) es una familia. Abstract Factory pone la creación de toda una familia en un solo objeto, la fábrica: quien usa la fábrica moderna recibe siempre muebles modernos.

Propósito

Abstract Factory es un patrón creacional que permite producir familias de objetos relacionados sin especificar sus clases concretas.

La idea de la solución

Conviene armar primero la tabla de productos y variantes:

SillaSofá
ModernaSillaModernaSofaModerno
VictorianaSillaVictorianaSofaVictoriano
  1. Cada columna es una interfaz de producto (Silla, Sofa): todas las sillas se usan igual, sean del estilo que sean.
  2. Cada fila es una fábrica concreta (FabricaModerna, FabricaVictoriana): crea todos los productos de esa variante.
  3. Todas las fábricas cumplen una misma interfaz, la fábrica abstracta, que tiene un método de creación por cada columna: crearSilla() y crearSofa().
  4. El cliente recibe una fábrica y le pide los muebles. No sabe cuál fábrica es ni qué clases concretas le devuelve.

Estructura

ParteQué esEn el ejemplo de los muebles
Productos AbstractosUna interfaz por cada tipo de producto de la familia.Silla, Sofa
Productos ConcretosLas implementaciones de cada producto, una por variante.SillaModerna, SillaVictoriana, SofaModerno, SofaVictoriano
Fábrica Abstracta (Abstract Factory)La interfaz con un método de creación por cada producto abstracto.FabricaDeMuebles, con crearSilla() y crearSofa()
Fábricas ConcretasUna por variante. Cada una crea solo los productos de su variante.FabricaModerna, FabricaVictoriana
ClienteUsa la fábrica y los productos solo a través de las interfaces.El código que amuebla

Cómo dibujarlo de memoria:

  • A la izquierda, las fábricas: la interfaz arriba y una fábrica concreta por variante abajo.
  • A la derecha, los productos: una interfaz por producto, cada una con sus concretos abajo.
  • Las flechas punteadas "crea" salen de la fábrica hacia cada interfaz de producto: los métodos de la fábrica devuelven el producto abstracto, aunque por dentro cada fábrica concreta haga el new del concreto de su variante (FabricaConcreta1 crea ProductoA1 y ProductoB1).
  • El Cliente guarda una fábrica (flecha continua hacia la interfaz).

Ejemplo 1 — En C++: la mueblería

#include <iostream>
#include <string>

class Silla {
 public:
  virtual ~Silla() {}
  virtual std::string describir() const = 0;
};

class Sofa {
 public:
  virtual ~Sofa() {}
  virtual std::string describir() const = 0;
};

class SillaModerna : public Silla {
 public:
  std::string describir() const override { return "silla moderna"; }
};

class SofaModerno : public Sofa {
 public:
  std::string describir() const override { return "sofa moderno"; }
};

class SillaVictoriana : public Silla {
 public:
  std::string describir() const override { return "silla victoriana"; }
};

class SofaVictoriano : public Sofa {
 public:
  std::string describir() const override { return "sofa victoriano"; }
};

class FabricaDeMuebles {
 public:
  virtual ~FabricaDeMuebles() {}
  virtual Silla* crearSilla() const = 0;
  virtual Sofa* crearSofa() const = 0;
};

class FabricaModerna : public FabricaDeMuebles {
 public:
  Silla* crearSilla() const override { return new SillaModerna; }
  Sofa* crearSofa() const override { return new SofaModerno; }
};

class FabricaVictoriana : public FabricaDeMuebles {
 public:
  Silla* crearSilla() const override { return new SillaVictoriana; }
  Sofa* crearSofa() const override { return new SofaVictoriano; }
};

void amoblar(FabricaDeMuebles* fabrica) {
  Silla* silla = fabrica->crearSilla();
  Sofa* sofa = fabrica->crearSofa();
  std::cout << "Juego: " << silla->describir() << " + " << sofa->describir() << "\n";
  delete silla;
  delete sofa;
}

int main() {
  FabricaDeMuebles* f = new FabricaModerna;
  amoblar(f);
  delete f;

  f = new FabricaVictoriana;
  amoblar(f);
  delete f;
  return 0;
}

Qué imprime y por qué

Juego: silla moderna + sofa moderno
Juego: silla victoriana + sofa victoriano

Nunca sale "silla moderna + sofa victoriano": es imposible, porque cada fábrica solo sabe crear los productos de su variante. Para agregar el estilo art déco se suman tres clases (SillaArtDeco, SofaArtDeco, FabricaArtDeco) y amoblar no se toca.

Cómo reconocerlo

DóndeQué lo delata
En un enunciadoLa palabra "familias": "la creación flexible de familias de objetos", "diferentes familias de productos". O varios productos que tienen que ajustarse todos a una misma variante: "crear diferentes tipos de elementos de interfaz de usuario, como botones y cuadros de texto, de manera que se ajusten a la plataforma específica (escritorio o web)".
En un código
  1. una interfaz con varios métodos de creación (CreateProductA, CreateProductB...) que devuelven punteros a distintas clases base;
  2. dos o más jerarquías de productos (una clase base por producto);
  3. varias clases que cumplen la interfaz fábrica y cuyos métodos son return new ...; de productos de la misma variante;
  4. un cliente que recibe la fábrica por parámetro y le pide los productos.

Ventajas y desventajas

VentajasDesventajas
  • Se tiene la certeza de que los productos que salen de una fábrica son compatibles entre sí.
  • Evita un acoplamiento fuerte entre los productos concretos y el código cliente.
  • Principio de responsabilidad única: el código de creación queda en un solo lugar.
  • Principio de abierto/cerrado: se agregan variantes nuevas sin romper el código cliente.
  • El código se puede complicar más de lo necesario: aparecen muchas interfaces y clases nuevas.

Dónde se usa

  • Interfaces de usuario multiplataforma (el otro ejemplo del apunte): botones y casillas que se ven distinto en Windows y en Mac, con una fábrica por sistema operativo.
  • Catálogos por estilo o por línea: los muebles del ejemplo.
  • Cualquier sistema que deba funcionar con varias familias de productos relacionados sin depender de sus clases concretas, porque no se conocen de antemano o porque se quiere poder agregar más.

Errores y trampas

Una sola jerarquía de productos no es Abstract Factory

Si la fábrica tiene un solo método de creación y hay un solo tipo de producto, es Factory Method. Abstract Factory necesita al menos dos productos distintos que formen familia.

Cuidado con qué se cuenta como fábrica

Hay una fábrica concreta por variante (moderna, victoriana), no por producto (silla, sofá). Si te encontrás dibujando FabricaDeSillas y FabricaDeSofas, las familias están al revés.

Agregar un producto nuevo sí obliga a tocar todo

Agregar una variante (art déco) es fácil: una fábrica más. Agregar un producto (mesilla) obliga a sumar un método a la fábrica abstracta y a todas las concretas.
