19. Patrones: reconocerlo en un código

Unidad 4B · Facade en un código

Dado el siguiente código identificar cual es el patrón que se está implementando, mencionar cuales fueron los elementos que te ayudaron a identificar el mismo y armar el diagrama en UML del mismo. 

#include <iostream>
#include <string>
class Sala {
public:
    bool HayLugar(const std::string& asiento) const {
        std::cout << "Sala: el asiento " << asiento << " esta libre\n";
        return true;   }
    void Reservar(const std::string& asiento) {
        std::cout << "Sala: asiento " << asiento << " reservado\n";   }};

class Boleteria {
public:
    void Cobrar(double monto) {
        std::cout << "Boleteria: se cobraron $" << monto << "\n";   }};

class Impresora {
public:
    void Imprimir(const std::string& pelicula,
                  const std::string& asiento) {
        std::cout << "Impresora: entrada de " << pelicula
                  << ", asiento " << asiento << "\n";   }};

class Cine {
private:
    Sala* sala_;
    Boleteria* boleteria_;
    Impresora* impresora_;
public:
    Cine() {
        sala_ = new Sala();
        boleteria_ = new Boleteria();
        impresora_ = new Impresora();   }
    ~Cine() {
        delete sala_;
        delete boleteria_;
        delete impresora_;   }
    void ComprarEntrada(const std::string& pelicula,
                        const std::string& asiento) {
        std::cout << "Comprando entrada...\n";
        if (sala_->HayLugar(asiento)) {
            sala_->Reservar(asiento);
            boleteria_->Cobrar(4500);
            impresora_->Imprimir(pelicula, asiento);   }   }};

int main() {
    Cine* cine = new Cine();
    cine->ComprarEntrada("Toy Story 5", "F7");
    delete cine;
    return 0;
}
✓ RespuestaPara aprender y escribir en la hoja
  1. Qué patrón y por qué: "Es Facade, un patrón estructural que se usa cuando para hacer una tarea hay que coordinar varias clases de un subsistema. Acá comprar una entrada obliga a usar tres clases en orden: ver si hay lugar y reservar (Sala), cobrar (Boleteria) e imprimir (Impresora)."
  2. Los elementos que ayudaron a identificarlo:
    • Ninguna clase hereda de otra: no hay interfaz común, así que no puede ser Composite, Adapter, Observer ni Strategy.
    • Cine guarda un objeto de cada una de las otras tres clases (sala_, boleteria_, impresora_), y las crea en su constructor.
    • Cine tiene un solo método, ComprarEntrada(), que llama a las tres en el orden correcto.
    • main hace una sola llamada y no conoce ni a Sala, ni a Boleteria, ni a Impresora.
  3. Cómo está aplicado: "Sala, Boleteria e Impresora son el subsistema (las clases que ya existían y hacen el trabajo). Cine es la fachada (la que da una entrada simple): guarda un objeto de cada una y ofrece ComprarEntrada(), que por dentro las llama en orden. main es el cliente."
  4. Qué se gana: "El cliente depende solo de la fachada: compra la entrada con una llamada y no necesita conocer el subsistema."

Cómo se responde esta consigna

Es la Práctica 1 del parcial 2026 con otro patrón. Tiene tres pedidos y la respuesta los cubre en orden: qué patrón (con su definición), qué elementos lo delatan (cosas que se ven en el código: herencias, atributos, métodos, quién llama a quién) y el UML. Se cierra con cómo está aplicado y qué se gana.

Paso 2 — Las cuatro preguntas para reconocer un código
  1. ¿Hay algo static y un constructor que no es público? No: no es Singleton.
  2. ¿Alguna clase hereda de otra? Ninguna → Facade.

Se confirma con el resto: una clase que guarda a varias clases sueltas y distintas, y un método que las coordina. Si hubiera herencia, se seguiría con las otras dos preguntas (¿hay métodos que devuelven un new?, ¿qué guarda la clase que guarda a otras?).

Trampas

  • No es Adapter: el adaptador hereda de la interfaz que usa el cliente y guarda una clase; la fachada no hereda de nadie y guarda varias.
  • "Los elementos" son cosas del código, no la definición del patrón: herencias, atributos, métodos y quién llama a quién.
