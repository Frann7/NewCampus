¿Qué patrón de diseño aplica este código?

#include <iostream>
#include <string>

class Documento {
public:
    virtual ~Documento() {}
    virtual std::string abrir() const = 0;
};

class Pdf : public Documento {
public:
    std::string abrir() const override { return "Abriendo PDF"; }
};

class Planilla : public Documento {
public:
    std::string abrir() const override { return "Abriendo planilla"; }
};

class Aplicacion {
public:
    virtual ~Aplicacion() {}
    virtual Documento* crearDocumento() const = 0;
    void nuevo() const {
        Documento* d = crearDocumento();
        std::cout << d->abrir() << "\n";
        delete d;
    }
};

class AppPdf : public Aplicacion {
public:
    Documento* crearDocumento() const override { return new Pdf(); }
};

class AppPlanilla : public Aplicacion {
public:
    Documento* crearDocumento() const override { return new Planilla(); }
};

int main() {
    Aplicacion* app = new AppPlanilla();
    app->nuevo();
    delete app;
    return 0;
}

Inventada · estilo Parcial 2025, Práctica 2

  • Abstract Factory
  • Factory Method
  • Strategy
  • Adapter

Hay dos jerarquías en paralelo: los productos (Documento, con Pdf y Planilla) y los creadores (Aplicacion, con AppPdf y AppPlanilla). Aplicacion declara el método fábrica crearDocumento() como virtual puro y lo usa en nuevo() sin saber qué documento recibe; cada subclase decide cuál crear. Es Factory Method. No es Abstract Factory porque hay un solo método de creación y un solo tipo de producto, no una familia.
