A partir del siguiente código identifique el patrón que se implementa en el mismo y explique qué elementos ayudaron a identificarlo. 

#include <iostream>

class Balanza {
 public:
  virtual ~Balanza() {}
  virtual int Request() const {
    return 12;
  }
};

class BalanzaImportada {
 public:
  int SpecificRequest() const {
    return 100;
  }
};

class BalanzaMuelle : public Balanza {
 private:
  BalanzaImportada *importada_;

 public:
  BalanzaMuelle(BalanzaImportada *importada) : importada_(importada) {}
  int Request() const override {
    int libras = this->importada_->SpecificRequest();
    return libras * 454 / 1000;
  }
};

void Despachar(const Balanza *balanza) {
  std::cout << "Peso: " << balanza->Request() << " kg\n";
}

int main() {
  Balanza *comun = new Balanza;
  Despachar(comun);

  BalanzaImportada *importada = new BalanzaImportada;
  Balanza *muelle = new BalanzaMuelle(importada);
  Despachar(muelle);

  delete comun;
  delete importada;
  delete muelle;
  return 0;
}

Lo que se ve, en el orden en que conviene leerlo:

  • Herencia: una sola, BalanzaMuelle hereda de Balanza. BalanzaImportada está suelta.
  • Qué guarda la clase del medio: BalanzaMuelle guarda un puntero a BalanzaImportada.
  • El cliente: Despachar solo conoce a Balanza y llama a Request().
  • Qué hace por dentro: en su Request(), BalanzaMuelle llama a SpecificRequest() y convierte el resultado de libras a kilos.

Adapter. La respuesta, como se escribe en la hoja:

  1. Qué patrón y por qué: "Es Adapter, un patrón estructural que se usa cuando hay que hacer trabajar juntas dos clases con interfaces incompatibles, sin modificar ninguna. Se reconoce porque BalanzaMuelle hereda de Balanza (la clase que usa el cliente), guarda un puntero a BalanzaImportada (una clase suelta, con otro método) y en su Request() llama a SpecificRequest() y convierte el resultado."
  2. Cómo está aplicado: "Balanza es la interfaz con el cliente (la que Despachar ya usa). BalanzaImportada es el servicio (la clase útil con la interfaz incompatible: su método se llama distinto y devuelve libras). BalanzaMuelle es el adaptador (la clase del medio): cumple la interfaz de Balanza y por dentro traduce cada llamada a la balanza importada, pasando las libras a kilos."
  3. Qué se gana: "Despachar usa la balanza importada igual que a las que ya conocía, sin modificar ni Despachar ni BalanzaImportada."

  1. Un código se lee siempre en el mismo orden. Primero, quién hereda de quién. ¿Qué herencia hay acá?

    • Una sola: BalanzaMuelle hereda de Balanza. BalanzaImportada no hereda de nadie
    • Ninguna: las tres clases están sueltas y no se relacionan por herencia
    • Dos: BalanzaImportada y BalanzaMuelle heredan las dos de Balanza
    • Una sola: Balanza hereda de BalanzaImportada

    Buscá los renglones class ... : public ....

    El único : public está en class BalanzaMuelle : public Balanza. BalanzaImportada es una clase suelta: no hereda de nadie y nadie hereda de ella. Que haya una herencia ya descarta Facade, donde no hay ninguna.

  2. Segundo, qué guarda la clase del medio. ¿Qué atributo tiene BalanzaMuelle?

    • Un puntero a BalanzaImportada, que recibe por el constructor
    • Una lista de punteros a Balanza, a la que se le agregan elementos
    • Un puntero estático a BalanzaMuelle, es decir, a ella misma
    • Un puntero a cada una de las otras dos clases del programa

    Mirá la parte private: de BalanzaMuelle.

    BalanzaImportada *importada_;: un puntero a la clase suelta. Una lista de su misma base sería Composite; un puntero estático a sí misma, Singleton; un puntero a cada clase, Facade.

  3. ¿Con qué tipo trabaja la función Despachar, que es la que usa las balanzas?

    • Solo con Balanza: llama a Request() y no conoce a BalanzaImportada
    • Con BalanzaImportada: llama directamente a SpecificRequest()
    • Con BalanzaMuelle: necesita saber que la balanza es la del muelle
    • Con las tres clases: elige con un if a cuál llamar

    Mirá el parámetro: void Despachar(const Balanza *balanza).

    Despachar es el cliente: recibe un Balanza* y llama a Request(). En main se la llama dos veces, una con una Balanza común y otra con una BalanzaMuelle, y la función no nota la diferencia.

  4. ¿Por qué no se le puede pasar una BalanzaImportada directamente a Despachar?

    • Porque tiene otra interfaz: no hereda de Balanza, su método se llama SpecificRequest() y devuelve el peso en otra unidad
    • Porque su constructor es privado y no se pueden crear objetos de esa clase desde afuera
    • Porque es una clase abstracta, con un método virtual sin código
    • Porque ya existe un objeto de esa clase y no se puede crear otro

    Compará el método de Balanza con el de BalanzaImportada: cómo se llaman, y en qué variable se guarda lo que devuelve el segundo (libras).

    Las dos clases tienen interfaces incompatibles: Despachar espera un Balanza* con Request() en kilos, y BalanzaImportada no es una Balanza, su método tiene otro nombre y devuelve libras. Es exactamente el problema que resuelve el patrón.

  5. ¿Qué hace BalanzaMuelle dentro de su Request()?

    • Llama a SpecificRequest() de la balanza importada que guarda y convierte el resultado de libras a kilos
    • Recorre una lista de balanzas, le pide el peso a cada una y devuelve la suma
    • Crea una balanza nueva con new y la devuelve para que la use el cliente
    • Les avisa a todas las balanzas registradas que hay un peso nuevo

    Son dos renglones: uno llama a la otra clase, el otro hace una cuenta con lo que le devolvió.

    int libras = this->importada_->SpecificRequest(); le pide el dato a la clase suelta, y return libras * 454 / 1000; lo pasa a kilos. Eso es traducir la llamada: recibe un Request(), lo convierte en un SpecificRequest() y adapta la respuesta. La salida del programa es Peso: 12 kg y Peso: 45 kg.

  6. Con todo eso: ¿qué patrón implementa el código?

    • Adapter
    • Facade
    • Strategy
    • Composite

    Una clase que hereda de la interfaz del cliente y guarda un puntero a una clase suelta, a la que le traduce las llamadas.

    Adapter, un patrón estructural: se usa cuando hay que hacer trabajar juntas dos clases con interfaces incompatibles, sin modificar ninguna. Los nombres Request y SpecificRequest lo confirman (son los del ejemplo original), pero la respuesta se justifica con la forma.

  7. ¿Qué parte del patrón es cada clase?

    • Balanza es la interfaz con el cliente, BalanzaImportada es el servicio y BalanzaMuelle es el adaptador
    • BalanzaImportada es la interfaz con el cliente, Balanza es el servicio y BalanzaMuelle es el adaptador
    • Balanza es el componente, BalanzaImportada es la hoja y BalanzaMuelle es el compuesto
    • BalanzaMuelle es la fachada, y Balanza y BalanzaImportada son las clases del subsistema

    La interfaz con el cliente es la que el cliente ya usa. El servicio es la clase útil que no encaja. El adaptador es la del medio.

    Balanza es la interfaz con el cliente (Target): la que Despachar ya usa. BalanzaImportada es el servicio (Adaptee): la clase útil con la interfaz incompatible. BalanzaMuelle es el adaptador: cumple la primera y por dentro llama a la segunda.

  8. Facade también es una clase que guarda a otra y la llama. ¿Por qué esto no es Facade?

    • Porque envuelve una sola clase y le da una interfaz que ya existía, la de Balanza; una fachada guarda varias clases, no hereda de nadie y ofrece una interfaz nueva
    • Porque en una fachada las clases del subsistema tienen que heredar todas de la fachada, y acá no heredan
    • Porque una fachada no puede tener atributos privados ni recibir objetos por el constructor
    • Porque Facade es un patrón de comportamiento, y este código es estructural

    ¿Cuántas clases envuelve? ¿La interfaz que ofrece es nueva, o ya la usaba el cliente?

    La pregunta que los separa: ¿se envuelve una clase para darle una interfaz que ya existía (Adapter) o varias para dar una interfaz nueva y simple (Facade)? Acá es una sola (BalanzaImportada) y la interfaz ya existía (Balanza, de la que el adaptador hereda). En Facade no hay ninguna herencia.

  9. En Strategy también hay una clase que guarda un puntero y le delega. ¿Por qué esto no es Strategy?

    • Porque lo que guarda es una clase suelta con otra interfaz, y hay que traducir; en Strategy se guarda un puntero a una interfaz con varias implementaciones, y hay un método para cambiarla
    • Porque en Strategy la clase que delega no puede heredar de ninguna otra
    • Porque en Strategy el puntero se guarda en un atributo público, y acá es privado
    • Porque Strategy necesita al menos tres clases que hereden de la misma base

    En Strategy lo que se guarda es intercambiable. ¿Acá hay algún método para cambiar la balanza importada por otra cosa?

    En Strategy el contexto guarda un puntero a una interfaz (con varias estrategias concretas detrás) y tiene un método para cambiarla. Acá el puntero es a una clase concreta y suelta, no hay nada intercambiable ni método para cambiarla, y el trabajo de BalanzaMuelle es convertir una interfaz en otra.

  10. La consigna pide explicar qué elementos ayudaron a identificarlo. ¿Cuál es la respuesta completa?

    • BalanzaMuelle hereda de Balanza, que es la clase que usa el cliente; guarda un puntero a BalanzaImportada, una clase suelta con otro método; y en su Request() llama a SpecificRequest() y convierte el resultado
    • Los métodos se llaman Request() y SpecificRequest(), que son los nombres que usa el patrón, y hay tres clases
    • En main los objetos se crean con new, se pasan por puntero y al final se borran con delete
    • Balanza tiene un método virtual y un destructor virtual, y BalanzaMuelle usa override

    Tres elementos, los tres de la clase del medio: de quién hereda, qué guarda y qué hace en su método.

    Los elementos son los de la forma: de quién hereda el adaptador, qué guarda y qué hace con eso. Los nombres de los métodos sirven de confirmación, pero en un parcial pueden venir cambiados. new, delete, virtual y override aparecen en cualquier programa con herencia: no identifican a ningún patrón.

  11. Para cerrar la respuesta: ¿qué se gana con el patrón en este código?

    • Despachar usa la balanza importada igual que a las que ya conocía, sin modificar ni Despachar ni BalanzaImportada
    • Despachar depende solo de BalanzaMuelle y deja de conocer a Balanza
    • Todo el programa usa la misma balanza, a través de un único punto de acceso
    • Se puede cambiar la forma de pesar mientras el programa corre

    Es la tercera oración de la descripción de Adapter: “Así el cliente usa la clase nueva igual que...”.

    La tercera oración de Adapter: “Así el cliente usa la clase nueva igual que a las que ya conocía”, dicha con el caso. Ninguna de las dos clases que no encajaban se modificó: todo el cambio está en la clase nueva del medio.
