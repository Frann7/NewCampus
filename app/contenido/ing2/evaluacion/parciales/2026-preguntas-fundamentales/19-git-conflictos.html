18. Git: conflictos de merge

Unidad 6 · Git

¿Cuándo se produce un conflicto de merge? Indique los tipos de conflicto y los pasos para resolverlo, con sus comandos.

✓ RespuestaPara aprender y escribir en la hoja

Al hacer un merge (parado en la rama de destino, git merge otra-rama), si los cambios de las dos ramas no se superponen, Git lo hace solo. Hay conflicto cuando las dos ramas modificaron las mismas líneas de los mismos archivos: Git avisa en la terminal y no completa el merge hasta que se resuelva.

Tipos:

  • De contenido (en el mismo archivo): las dos ramas modificaron la misma línea.
  • De eliminación: una rama borró un archivo que la otra modificó.

Pasos para resolverlo:

  1. Ver los archivos en conflicto: git status.
  2. Editarlos a mano: Git marca cada conflicto así: 
    <<<<<<< HEAD
Cambios en la rama actual
=======
Cambios en la rama "feature-nueva-funcion"
>>>>>>> feature-nueva-funcion
    Entre <<<<<<< HEAD y ======= están los cambios de la rama actual; entre ======= y >>>>>>>, los de la otra. Se deja una versión, o se combinan las dos, y se borran las marcas.
  3. Marcar el conflicto como resuelto: guardar y pasar el archivo al área de preparación, git add nombre_archivo.
  4. Terminar el merge: git commit, con un mensaje que documente el merge y su resolución.

Comandos útiles:

  • git merge --abort: descarta el merge y deja la rama como estaba.
  • git mergetool: abre una herramienta de merge configurada (KDiff3, P4Merge) para resolverlo.

Un ejemplo

En main el título de index.html pasó a "Bienvenidos"; en la rama login, a "Iniciá sesión". Parado en main, git merge login no sabe con cuál quedarse: marca el título con las dos versiones y se frena. Uno elige (o arma un título nuevo), borra las marcas, y cierra con git add index.html y git commit.

El resumen para recordar

Merge integra ramas; si las dos cambiaron las mismas líneas, hay conflicto. Se resuelve abriendo el archivo, eligiendo qué conservar, pasándolo a staging con git add y cerrando con un git commit que registra el merge.

Trampas

  • HEAD es la rama en la que estás parado (la que recibe el merge), no la que se integra.
  • Editar el archivo no alcanza: sin git add y git commit, el merge sigue a medias.
  • Si dos ramas tocaron el mismo archivo pero en líneas distintas, no hay conflicto: Git lo une solo.
