4. Herencia, virtual y punteros en C++

Para qué sirve

Todos los patrones se apoyan en la misma idea: una parte del programa trabaja con una clase general (o una interfaz) sin saber cuál de las clases concretas tiene adelante. Eso se llama polimorfismo: la misma orden, hablar(), hace cosas distintas según el objeto que la recibe. En C++ se escribe con cuatro piezas: herencia, virtual, override y punteros.

Sintaxis

class Madre {
 public:
  virtual ~Madre() {}
  virtual Tipo metodo() const = 0;
};

class Hija : public Madre {
 public:
  Tipo metodo() const override {
    // código propio de la hija
  }
};

Madre* p = new Hija;
p->metodo();
delete p;

Qué es cada parte

ParteQué es
class Hija : public MadreHerencia. Los dos puntos se leen "hereda de". Hija tiene todo lo de Madre.
virtualMarca un método que las hijas pueden volver a escribir. Sin virtual no hay polimorfismo.
= 0El método no tiene código en la madre: es abstracto (virtual puro). Las hijas están obligadas a escribirlo. Una clase con algún = 0 es abstracta: no se pueden crear objetos de ella.
overrideVa en la hija: "este método reemplaza al de la madre".
virtual ~Madre() {}El destructor: lo que se ejecuta cuando el objeto se destruye. Se llama como la clase con ~ adelante. Aparece en casi toda clase base; para leer un patrón se puede saltear.
Madre* pUn puntero: una variable que no guarda un objeto sino dónde está un objeto. El asterisco pegado al tipo se lee "puntero a". Un puntero a Madre puede apuntar a cualquiera de sus hijas.
new HijaCrea un objeto de la clase Hija y devuelve dónde quedó.
p->metodo()La flecha es el punto de los punteros: "pedile esto al objeto al que apunta p".
delete p;Destruye el objeto creado con new. Para leer un patrón no importa.
nullptrUn puntero que no apunta a nada todavía.
C++ no tiene la palabra interface

Una interfaz en C++ es una clase en la que todos los métodos son virtual ... = 0 y no hay atributos. Cuando en un código veas una clase así (muchas veces su nombre empieza con I, como ISubject), en el diagrama es una «interface» y las que heredan de ella van con línea punteada.

Ejemplo 1 — La misma orden, dos respuestas

#include <iostream>
#include <string>

class Animal {
 public:
  virtual ~Animal() {}
  virtual std::string hablar() const = 0;
};

class Perro : public Animal {
 public:
  std::string hablar() const override {
    return "Guau";
  }
};

class Gato : public Animal {
 public:
  std::string hablar() const override {
    return "Miau";
  }
};

int main() {
  Animal* a = new Perro;
  std::cout << a->hablar() << "\n";
  delete a;

  a = new Gato;
  std::cout << a->hablar() << "\n";
  delete a;
  return 0;
}

Qué hace cada línea

LíneaQué haceCómo quedan los datos
class Animal { ... virtual std::string hablar() const = 0; };Define la clase general. Dice que todo animal sabe hablar() y devuelve un texto, pero no dice cómo: es abstracta.—
class Perro : public Animal { ... override ... }Un Perro es un Animal, y escribe su propio hablar().—
class Gato : public Animal { ... }Lo mismo para el Gato.—
Animal* a = new Perro;Crea un Perro y guarda dónde está en a, que es un puntero a Animal.a → un Perro
std::cout << a->hablar() ...Le pide hablar() al objeto apuntado. Como es un Perro, corre el hablar() de Perro.sin cambios
delete a;Destruye el Perro.a ya no sirve
a = new Gato;El mismo puntero ahora apunta a un Gato.a → un Gato
std::cout << a->hablar() ...La línea es idéntica a la de antes, pero ahora corre el hablar() de Gato.sin cambios

Qué imprime y por qué

Guau
Miau

a->hablar() está escrito dos veces igual y dio dos resultados. El que decide qué código corre no es el tipo del puntero (Animal) sino el objeto al que apunta. Eso es polimorfismo.

Ejemplo 2 — Con formato de parcial: una clase que guarda un puntero a otra

Este es el esqueleto que más se repite en los códigos de los parciales: una clase que tiene como atributo un puntero a una clase general y le pasa el trabajo. Las clases Animal, Perro y Gato son las del ejemplo 1. 

#include <iostream>
#include <string>
#include <vector>

// ... Animal, Perro y Gato, como en el ejemplo 1 ...

class Duenio {
 private:
  Animal* mascota_;

 public:
  Duenio(Animal* mascota) : mascota_(mascota) {}

  void cambiarMascota(Animal* mascota) {
    mascota_ = mascota;
  }

  void saludar() const {
    std::cout << "Mi mascota dice: " << mascota_->hablar() << "\n";
  }
};

int main() {
  Animal* perro = new Perro;
  Animal* gato = new Gato;

  Duenio d(perro);
  d.saludar();
  d.cambiarMascota(gato);
  d.saludar();

  std::vector<Animal*> todos;
  todos.push_back(perro);
  todos.push_back(gato);
  for (Animal* x : todos) {
    std::cout << x->hablar() << "\n";
  }

  delete perro;
  delete gato;
  return 0;
}

Qué hace cada línea

LíneaQué haceCómo quedan los datos
Animal* mascota_;El Dueño guarda un puntero a un Animal. No sabe (ni le importa) si es Perro o Gato.—
Duenio(Animal* mascota) : mascota_(mascota) {}El constructor recibe el animal desde afuera y lo guarda.—
void cambiarMascota(Animal* mascota)Permite cambiar el animal guardado mientras el programa corre.—
mascota_->hablar() (en saludar)El Dueño no habla: le pasa el trabajo a su mascota. A eso se le dice delegar.—
Animal* perro = new Perro;
Animal* gato = new Gato;		Crea los dos animales.perro → un Perro; gato → un Gato
Duenio d(perro);Crea el Dueño pasándole el Perro.d: mascota_ → el Perro
d.saludar();El Dueño delega en su mascota, que es el Perro.sin cambios
d.cambiarMascota(gato);Le cambia la mascota.d: mascota_ → el Gato
d.saludar();La misma llamada, ahora delega en el Gato.sin cambios
std::vector<Animal*> todos;Crea una lista de punteros a Animal, vacía. vector es la lista de C++; entre < > va qué guarda.todos: vacía
todos.push_back(perro);
todos.push_back(gato);		push_back agrega al final.todos: [el Perro, el Gato]
for (Animal* x : todos) { ... }Recorre la lista: en cada vuelta x es el elemento siguiente. Se lee "para cada x en todos".vuelta 1: x → el Perro; vuelta 2: x → el Gato

Qué imprime y por qué

Mi mascota dice: Guau
Mi mascota dice: Miau
Guau
Miau

Las dos primeras líneas salen de d.saludar(), antes y después de cambiarle la mascota. Las dos últimas, del recorrido de la lista.

El mismo código, en diagrama

El atributo Animal* mascota_ es la flecha de asociación de Duenio a Animal; los dos : public Animal son los triángulos de herencia.

Errores y trampas

De una clase abstracta no se pueden crear objetos

Escribir Animal a; no compila:

error: cannot declare variable 'a' to be of abstract type 'Animal'

Sí se puede tener un puntero a Animal, que apunte a un Perro o a un Gato. Por eso los patrones trabajan siempre con punteros a la clase general.

Punto para objetos, flecha para punteros

d.saludar(): d es un objeto. perro->hablar(): perro es un puntero. Hacen lo mismo. También vas a ver this->atributo_: this es un puntero al propio objeto, así que this->mascota_ es lo mismo que escribir mascota_ a secas.

La misma vuelta, escrita a la antigua

En los códigos de la cátedra las listas se recorren con un iterador, que es más largo pero hace lo mismo que el for de arriba: 

std::list<std::string> nombres;
nombres.push_back("Ana");
nombres.push_back("Luis");
std::list<std::string>::iterator it = nombres.begin();
while (it != nombres.end()) {
  std::cout << *it << "\n";
  ++it;
}
Ana
Luis

it arranca en el primer elemento (begin()), *it es el elemento donde está parado, ++it pasa al siguiente y end() es "ya no hay más". Cuando veas esto, leelo como "para cada elemento de la lista".
