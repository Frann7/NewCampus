3. Crear la conexión

Para qué sirve

Para hablar con el servidor de datos, primero hay que abrir una conexión. Toda la comunicación entre PHP y la base pasa por ella: sin conexión no hay consulta. Y como cada script arranca de cero, la conexión se abre en cada script que use la base.

Sintaxis

Se crea un objeto de la clase mysqli pasándole cuatro datos, y se revisa si salió bien:

$mysqli = new mysqli('Host', 'usuarioDB', 'contraseñaDB', 'BasedeDatos');

if ($mysqli->connect_errno)
{
    echo "No se pudo establecer la conexión.";
    echo "Error número: " . $mysqli->connect_errno;
    echo "Error descripción: " . $mysqli->connect_error;
    exit;
}

En estilo procedural, lo mismo es mysqli_connect():

$conexion = mysqli_connect('Host', 'usuarioDB', 'contraseñaDB', 'BasedeDatos');

if (!$conexion)
{
    echo "Error: " . mysqli_connect_error();
    exit;
}

Qué es cada parte

ParteQué esEn XAMPP
HostLa dirección IP o el nombre del servidor donde está la base. Un fqdn (fully qualified domain name) es el nombre completo de una máquina en internet, como db.miempresa.com'localhost' o '127.0.0.1': las dos quieren decir "esta misma PC"
usuarioDBEl usuario del SGBD (no el de Windows ni el del sitio)'root'
contraseñaDBLa contraseña de ese usuario'': dos comillas sin nada, porque root viene sin contraseña
BasedeDatosEl nombre de la base a la que se quiere entrarla que creaste en phpMyAdmin
$mysqliEl objeto que queda guardando la conexión. La cátedra dice que "se crea un socket" y que esta variable lo direcciona: por ella se mandan las consultas y se reciben los resultados
connect_errnoUna propiedad (un dato del objeto, sin paréntesis) con el número del error de conexión. Vale 0 si conectó bien
connect_errorLa descripción del error, en texto. Vale null si conectó bien
exitCorta el script ahí mismo. Sin conexión no tiene sentido seguir

El if funciona porque 0 cuenta como falso: si conectó, connect_errno es 0 y no entra; si falló, es un número como 2002 y entra.

Un paso más: set_charset

El sitio de ejemplo de la cátedra agrega, después de conectar: 

$mysqli->set_charset("utf8");

Le avisa a la base que el texto va y viene en UTF-8. Sin eso, las tildes y las eñes pueden llegar como Garc�a. Se escribe "utf8", sin guion: es el nombre que usa MySQL, no el de HTML.

Ejemplo 1 — Conectarse a la base de la teoría

Enunciado

Conectarse a la base Personal del XAMPP de tu PC, con el usuario root, y mostrar un mensaje si la conexión falla. 

<?php
$mysqli = new mysqli('127.0.0.1', 'root', '', 'Personal');

if ($mysqli->connect_errno)
{
    echo "No se pudo establecer la conexión.";
    exit;
}

$mysqli->set_charset('utf8');
?>

Ejemplo 2 — ¿Qué muestra si MySQL está apagado?

Enunciado

Con el código del ejemplo 1, alguien se olvida de prender MySQL en el panel de XAMPP y abre la página. ¿Qué se ve? ¿Llega a mostrarse "No se pudo establecer la conexión."?

Lo esperable, leyendo el código de la cátedra, sería que entre al if. Pero no llega. Lo corrimos con el PHP 8.2 de XAMPP contra un puerto donde no hay ningún servidor (que es lo mismo que tener MySQL apagado), y se ve esto: 

Fatal error: Uncaught mysqli_sql_exception: No se puede establecer una conexión ya que el equipo de destino denegó expresamente dicha conexión in C:\xampp\htdocs\conexion.php:2

Por qué: desde PHP 8.1, cuando mysqli falla no deja el error guardado en connect_errno para que lo mires después: lanza una excepción. Una excepción es un error que corta el script en el acto, salvo que alguien la atrape. Como nadie la atrapa, el script muere en la línea 2 y el if nunca se ejecuta. Debajo de esa línea vienen unas líneas de Stack trace que dicen dónde pasó. La ruta del archivo depende de dónde lo tengas, y el texto del error lo pone Windows, en el idioma de la PC.

Cómo atraparla: try / catch

<?php
try {
    $mysqli = new mysqli('127.0.0.1', 'root', '', 'Personal');
} catch (mysqli_sql_exception $e) {
    echo "No se pudo establecer la conexión.<br>";
    echo "Error número: " . $e->getCode() . "<br>";
    echo "Error descripción: " . $e->getMessage();
    exit;
}
?>
LíneaQué haceCómo quedan las variables
2try: "intentá esto". Si adentro se lanza una excepción, en vez de morir salta al catch
3Intenta conectar; falla y lanza la excepción$mysqli no llega a existir
4catch atrapa las excepciones de tipo mysqli_sql_exception y guarda la excepción en $e$e = la excepción
5Muestra el mensaje propio
6getCode() devuelve el número del error (lo mismo que connect_errno)2002
7getMessage() devuelve la descripción (lo mismo que connect_error)el texto del error
8Corta el script

Qué imprime (verificado con el mismo servidor apagado):

No se pudo establecer la conexión.<br>Error número: 2002<br>Error descripción: No se puede establecer una conexión ya que el equipo de destino denegó expresamente dicha conexión

En el navegador, cada <br> es un salto de línea: se ven tres renglones. El 2002 es el código de "no hay servidor en esa dirección". Otro muy común es el 1045, usuario o contraseña incorrectos.

Errores y trampas
  • El código de la cátedra es de antes de PHP 8.1. En el XAMPP actual, el if ($mysqli->connect_errno) no alcanza: o se usa try/catch, o se pone mysqli_report(MYSQLI_REPORT_OFF); antes de conectar, que vuelve al comportamiento viejo: mysqli no lanza nada y deja el error en connect_errno (igual PHP muestra arriba un Warning con el error; lo verificamos).
  • La contraseña vacía se escribe ''. No se puede saltear el parámetro: si falta, el cuarto dato (la base) pasaría a ser la contraseña.
  • Copiar del PDF trae comillas tipográficas (“ ” o ‘ ’). PHP no las reconoce como comillas y da error de sintaxis. Siempre ' o " del teclado.
  • Usuario de la base ≠ usuario del sitio. root es el usuario de MariaDB; nada que ver con quien navega la página.
