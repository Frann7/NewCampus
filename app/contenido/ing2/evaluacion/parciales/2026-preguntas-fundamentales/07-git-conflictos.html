6. Git: conflictos de merge

Unidad 6 · Git

Explique qué es un conflicto de merge y en qué situación aparece. Muestre cómo lo marca Git dentro del archivo e indique los pasos para resolverlo.

✓ RespuestaPara aprender y escribir en la hoja

Qué es: un conflicto de merge es lo que pasa cuando Git no puede combinar solo los cambios de dos ramas: no sabe cuál vale, se detiene y pide que lo decida una persona.

Cuándo aparece: al fusionar dos ramas que modificaron las mismas líneas del mismo archivo (o cuando una eliminó un archivo que la otra modificó).

Cómo lo marca Git dentro del archivo:

<<<<<<< HEAD
versión de la rama actual
=======
versión de la otra rama
>>>>>>> nombre-de-la-otra-rama

Pasos para resolverlo:

  1. Ver qué archivos están en conflicto: git status
  2. Editar cada archivo: elegir una versión o combinar las dos, y borrar las marcas.
  3. Marcarlo como resuelto: git add archivo
  4. Finalizar el merge: git commit

Para cancelar el merge: git merge --abort.

Qué es un merge y cuándo falla

Una rama es una versión paralela del proyecto. Un merge (fusión) combina los cambios de dos ramas en una. Si cada rama tocó partes distintas, Git las junta solo. Si se superponen, no puede adivinar cuál vale.

Tipo de conflictoCuándo ocurre
De contenidoLas dos ramas modificaron la misma línea de un archivo.
De eliminaciónUna rama eliminó un archivo que la otra modificó.
Cómo leer las marcas

El título de index.html se cambió en master y también en la rama feature-registro. Parado en master, git merge feature-registro avisa el conflicto y deja el archivo así: 

<<<<<<< HEAD
<h1>Bienvenido</h1>
=======
<h1>Ingresar al sistema</h1>
>>>>>>> feature-registro
ParteQué es
<<<<<<< HEADEmpieza la versión de la rama actual, en la que estoy parado (acá, master). HEAD es "donde estoy".
=======La separación entre las dos versiones.
>>>>>>> feature-registroTermina la versión de la otra rama, la que se está fusionando.
Los cuatro pasos, en este caso
  1. git status muestra que index.html está en conflicto.
  2. Se edita el archivo y se deja una sola línea, sin las tres marcas: <h1>Bienvenido: ingresar al sistema</h1>
  3. git add index.html lo marca como resuelto: pasa al área de preparación.
  4. git commit -m "Resuelve el conflicto del título" finaliza el merge.

git merge --abort descarta el merge y deja la rama como estaba antes de intentarlo.

Trampas

  • Las marcas no se borran solas: si hacés git add sin editar, quedan confirmadas dentro del código. Git no lo revisa.
  • Un conflicto no es un error: es Git negándose a elegir por vos. Sin control de versiones, el último que guarda pisa al otro sin que nadie se entere.
  • No toda fusión da conflicto: si se tocaron archivos distintos, o líneas distintas del mismo archivo, el merge es automático.
