14. Git: ramas y merge

Unidad 6 · Git

Un desarrollador está en la rama principal, main, y tiene que programar el inicio de sesión en una rama nueva, login. Represente gráficamente la rama y su integración, e indique los comandos para crearla, confirmar en ella todos los cambios del directorio de trabajo, integrarla en main y dejar main actualizada en el remoto.

La rama login sale de la base común, suma sus commits (hasta su punta) y el merge la junta con main en un commit nuevo.

  1. Crear la rama y pasarse a ella: git checkout -b login
  2. Preparar todos los cambios: git add .
  3. Confirmarlos: git commit -m "Agrega el inicio de sesión"
  4. Volver a la principal: git checkout main
  5. Integrar la rama: git merge login
  6. Subir main al remoto: git push origin main

Qué es cada cosa

  • Rama: una versión paralela del proyecto, para trabajar sin afectar la principal.
  • Merge: combinar los cambios de una rama en otra. Se hace parado en la rama que recibe: por eso primero git checkout main.
  • Pull request: el pedido, en GitHub, para que revisen e integren una rama; no es un comando.

Si aparece un conflicto

Pasa cuando las dos ramas cambiaron las mismas líneas: Git marca el archivo con <<<<<<<, ======= y >>>>>>>. Se edita dejando la versión correcta, se borra lo marcado y se cierra con git add y git commit.

Trampa

El orden importa: si se hace git merge login estando en login, no pasa nada en main.
