Ejercicio 8 · Facade

Aplicar el patrón sobre un diagrama: la tienda

Patrones de Diseño Parte 1, ejercicio 4. Actualmente se desean implementar mejoras en un sistema de gestión para una tienda que vende distintos tipos de productos (revistas, cds, libros), se desea implementar una interface fácil y de simple acceso para que una clase Cliente pueda interactuar de forma fácil para realizar compras y reclamos, adjuntamos parte de un diagrama de clases:

Paso 1 — Desarme del enunciado
Frase del enunciadoQué significaParte del patrón
"una interface fácil y de simple acceso"Es el propósito de Facade: una interfaz simplificada. La frase que decide.Fachada
"para que una clase Cliente pueda interactuar de forma fácil"Quién va a usar esa interfaz. En el diagrama está suelto, sin ninguna líneaCliente
"para realizar compras y reclamos"Las operaciones simples que tiene que ofrecerMétodos de la fachada: comprar() y reclamar()
"un sistema de gestión para una tienda que vende distintos tipos de productos"Lo complicado que queda detrásSubsistema: los productos y lo que maneja compras y reclamos
La trampa: Producto con tres hijas

En el ejercicio 3 de esta misma guía, una clase con varias hijas era la pista de Factory Method. Acá no: el enunciado no habla de crear productos, habla de darle al cliente un acceso simple. El diagrama acompaña; el patrón lo decide la necesidad.

Paso 2 — Qué se agrega
  1. Una clase FachadaTienda con los métodos comprar() y reclamar().
  2. Una flecha de Cliente a FachadaTienda: es lo único que el cliente conoce.
  3. Flechas de la fachada hacia las clases del sistema que hacen el trabajo. El enunciado solo muestra los productos; para las compras y los reclamos se suponen dos clases del sistema, GestorCompras y GestorReclamos.

Producto, Revista, CD y Libro quedan como estaban.

Paso 3 — El diagrama
Respuesta

Se aplica Facade, porque se pide una interfaz fácil y de simple acceso para que el Cliente realice compras y reclamos. Se agrega FachadaTienda, con comprar() y reclamar(), que por dentro coordina a las clases del sistema (productos, compras, reclamos). El Cliente interactúa solo con la fachada, sin conocer la complejidad del sistema de gestión, y si el sistema cambia por dentro el Cliente no se modifica.

Práctica 03, ejercicio 2: el mismo, con los subsistemas dichos

"Un sistema de una tienda en línea con múltiples subsistemas como el de gestión de inventario, el de procesamiento de pedidos y el de envío. Crea una fachada para simplificar la interacción del cliente con estos subsistemas." Es el ejemplo 1 de la teoría: la fachada guarda los tres subsistemas y ofrece un método simple.
