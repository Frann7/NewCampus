10. Gestión de cambios y control de versiones

Unidad 6 · Gestión de cambios

Responda sobre el control de versiones:

  1. ¿Qué es?
  2. Mencione tres beneficios de usarlo.
  3. Mencione cuatro problemas de no usarlo.
  4. Diferencie un sistema centralizado de uno distribuido y dé un ejemplo de cada uno.
✓ RespuestaPara aprender y escribir en la hoja
  1. Es la práctica de rastrear y gestionar los cambios en el código. Un sistema de control de versiones registra todas las modificaciones en una base de datos especial y permite volver a versiones anteriores.
  2. Beneficios: colaboración y trabajo en equipo, seguimiento histórico de cada cambio (autor, fecha y motivo) y poder revertir cambios.
  3. Sin él: pérdida de código, dificultad para colaborar en equipo, falta de historial de cambios e imposibilidad de revertir ante un error.
  4. Centralizado: un único servidor guarda el código y hay que estar conectado a él; si falla, nadie trabaja. Ejemplo: SVN. Distribuido: cada desarrollador tiene una copia completa del repositorio con todo el historial y puede trabajar sin conexión. Ejemplo: Git.

El problema

Un software nunca queda quieto: el cliente pide cosas nuevas, aparecen errores y varias personas tocan el mismo código a la vez. Si eso no se ordena, los cambios se pisan, nadie sabe qué versión es la buena y no se puede volver atrás.

Los cuatro conceptos de la unidad

ConceptoEn una línea
Gestión de cambiosIdentificar, documentar, evaluar y controlar los cambios propuestos: decide si un cambio se hace y con qué impacto.
Gestión de la configuraciónControlar todos los artefactos del proyecto (código, documentación, entornos).
Control de cambiosEl proceso formal para aprobar o rechazar cambios. Es un subconjunto de la gestión de la configuración.
Control de versionesEl proceso técnico que guarda las distintas versiones del código. Ejemplo: Git.
a y b) Qué es y qué se gana

El sistema de control de versiones anota cada modificación: quién la hizo, cuándo y para qué. Si se comete un error, se puede "ir hacia atrás en el tiempo" y comparar con una versión anterior. De ahí salen los tres beneficios: varios trabajan en paralelo sin interferir (con ramas), queda el historial de cada cambio y se puede revertir lo que salió mal.

c) Los problemas de no usarlo

El apunte da nueve y con cuatro alcanza. Los de la respuesta son los cuatro primeros, que son los beneficios dados vuelta: se pisa o se borra el trabajo de otro, cuesta trabajar de a varios, no queda historial y no se puede volver atrás. Los otros cinco: problemas con el lanzamiento de versiones, complicaciones para resolver conflictos, ausencia de trazabilidad y auditoría, falta de seguridad en el código y dificultad para implementar entornos de pruebas.

EjemplosCVS, SVNGit, Mercurial

Git y GitHub

Git es el sistema de control de versiones distribuido: el programa que guarda el historial en tu computadora. GitHub es una plataforma que aloja el repositorio remoto, la copia que comparte el equipo, y donde se hacen los pull requests.

Trampas

  • Gestión de cambios no es control de versiones: la primera decide si un cambio se hace; el segundo guarda cómo quedó el código.
  • Los beneficios son tres y los problemas son nueve: no mezclar las dos listas.
  • El ejemplo va con su tipo: SVN y CVS son centralizados; Git y Mercurial, distribuidos.
