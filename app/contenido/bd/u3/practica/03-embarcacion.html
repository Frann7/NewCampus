Guía 10 · Una tabla con sus claves

La tabla de Embarcaciones

Utilizando lenguaje SQL, crear la tabla de Embarcaciones del club náutico, con sus atributos y claves correspondientes.

Socio (DNI (PK), Nombre, Direccion, FechaIngreso)
TipoEmbarcacion (Codigo (PK), Descripcion)
Amarre (Numero (PK), LecturaAgua, LecturaLuz, Mantenimiento, LetraZona (FK),
        DNIPropietario (FK), FechaAdquisicion)
Embarcacion (Matricula (PK), Nombre, Dimension, CodigoTipo (FK), DNISocio (FK),
             NumeroAmarre (FK), FechaAsignacion)
Paso 1 — Desarme de la tabla
ColumnaQué esTipoClave
MatriculaIdentifica la embarcación; tiene letras y númerosVARCHAR(20) NOT NULLPK
NombreTextoVARCHAR(50)
DimensionMetros de eslora, con decimalesDECIMAL(5,2)
CodigoTipoApunta a TipoEmbarcacionINT NOT NULL (como TipoEmbarcacion.Codigo)FK
DNISocioEl dueño; apunta a SocioVARCHAR(13) NOT NULL (como Socio.DNI)FK
NumeroAmarreEl amarre que ocupa; apunta a AmarreINT NOT NULLFK, y además UNIQUE
FechaAsignacionCuándo se le asignó el amarreDATE
Paso 2 — Por qué UNIQUE en NumeroAmarre

La interrelación con Amarre es 1:1: un amarre lo ocupa una sola embarcación. Una FK común se puede repetir (dos embarcaciones con el mismo amarre); con UNIQUE, SQL Server lo impide.

Resolución 
CREATE TABLE Embarcacion (
  Matricula        VARCHAR(20)   NOT NULL,
  Nombre           VARCHAR(50),
  Dimension        DECIMAL(5,2),
  CodigoTipo       INT           NOT NULL,
  DNISocio         VARCHAR(13)   NOT NULL,
  NumeroAmarre     INT           NOT NULL,
  FechaAsignacion  DATE,
  CONSTRAINT PK_Embarcacion PRIMARY KEY (Matricula),
  CONSTRAINT UQ_Embarcacion_NumeroAmarre UNIQUE (NumeroAmarre),
  CONSTRAINT FK_Embarcacion_TipoEmbarcacion FOREIGN KEY (CodigoTipo) REFERENCES TipoEmbarcacion(Codigo),
  CONSTRAINT FK_Embarcacion_Socio FOREIGN KEY (DNISocio) REFERENCES Socio(DNI),
  CONSTRAINT FK_Embarcacion_Amarre FOREIGN KEY (NumeroAmarre) REFERENCES Amarre(Numero)
);

Las tablas TipoEmbarcacion, Socio y Amarre tienen que estar creadas antes.

Errores y trampas
  • Si la consigna pide una tabla, se crea esa sola, pero con todas sus FK: son parte de "sus claves correspondientes".
  • El tipo de cada FK se copia del de la PK a la que apunta: si Socio.DNI es VARCHAR(13), DNISocio también.
