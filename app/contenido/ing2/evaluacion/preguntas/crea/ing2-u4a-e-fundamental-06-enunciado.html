A partir del siguiente enunciado identifique cuáles serían los patrones de diseño que utilizaría y justifique por qué eligió los mismos.

La cadena Hoteles Ñandubay administra sus doce hoteles con un mismo sistema de reservas. Los precios de cada noche, por tipo de habitación y por temporada, están en un tarifario que se carga desde la base de datos, y esa carga es lenta. La recepción, la página web y la facturación consultan precios todo el tiempo, y todos tienen que ver los mismos. Por motivos de performance, se desea que exista un único tarifario para todo el sistema, al que todos los módulos accedan.

Las habitaciones se abren con tarjeta. Para habilitar la tarjeta de un huésped, el sistema de reservas ya trabaja con la interfaz Cerradura y su método habilitar(), que cumplen todas las cerraduras instaladas hasta ahora. En los dos hoteles que la cadena sumó este año las cerraduras son de otro fabricante, Abrix, que entrega su propia clase ya programada, AbrixLock, con otros métodos y otros parámetros (para habilitar una tarjeta se llama a grantAccess()). Esa clase se debe incorporar sin modificarla y sin que afecte la lógica del sistema de reservas.

Por último, al confirmar una reserva el sistema crea el comprobante que recibe el huésped. Hay comprobantes de distintos tipos: impreso, para las reservas que se toman en el mostrador, y digital, para las que entran por la página web. La confirmación sigue siempre los mismos pasos y tiene que trabajar con cualquier comprobante de manera transparente, sin saber de antemano de qué tipo es el que se crea. Además, se quiere poder agregar nuevos tipos de comprobante en el futuro (por ejemplo, uno para las reservas hechas por agencia) sin modificar la confirmación.

Singleton (primer párrafo):

  1. Qué patrón y por qué: "Singleton, un patrón creacional, para el tarifario. Se usa cuando una clase debe tener una única instancia disponible para todo el sistema. El enunciado lo dice: "se desea que exista un único tarifario para todo el sistema, al que todos los módulos accedan"."
  2. Cómo se aplica: "La clase Tarifario oculta su constructor (lo declara privado, para que nadie más pueda crear otro tarifario) y ofrece un método estático (se llama sobre la clase, sin tener un objeto), obtenerInstancia(), que crea el tarifario la primera vez y devuelve siempre el mismo."
  3. Qué se gana: "Todo el sistema (la recepción, la página web y la facturación) usa el mismo tarifario, a través de un único punto de acceso."

Adapter (segundo párrafo):

  1. Qué patrón y por qué: "Adapter, un patrón estructural, para las cerraduras de Abrix. Se usa cuando hay que hacer trabajar juntas dos clases con interfaces incompatibles, sin modificar ninguna: acá, el sistema de reservas y la clase de Abrix. El enunciado lo dice: la clase viene "con otros métodos y otros parámetros" y "se debe incorporar sin modificarla y sin que afecte la lógica del sistema de reservas"."
  2. Cómo se aplica: "Se agrega una clase en el medio, el adaptador (la clase que traduce), que cumple la interfaz que el sistema de reservas ya usa, Cerradura, y por dentro traduce cada llamada a AbrixLock, que es el servicio (la clase que ya existe y no se puede modificar): cuando le piden habilitar(), llama a grantAccess()."
  3. Qué se gana: "El sistema de reservas usa las cerraduras de Abrix igual que a las que ya conocía."

Factory Method (tercer párrafo):

  1. Qué patrón y por qué: "Factory Method, un patrón creacional, para los comprobantes. Se usa cuando una clase no puede saber de antemano qué tipo exacto de objeto tiene que crear: acá, la confirmación no sabe qué tipo de comprobante le toca. El enunciado lo dice: la confirmación trabaja "sin saber de antemano de qué tipo es el que se crea", y se quiere "poder agregar nuevos tipos de comprobante en el futuro"."
  2. Cómo se aplica: "La creación se saca a un método, el método fábrica, crearComprobante(): lo declara la clase base, la confirmación, que es el creador (la clase que necesita el comprobante pero no decide cuál se crea), y lo sobrescribe cada subclase, un creador concreto (la confirmación de mostrador y la de la web), para devolver su comprobante, que es el producto (el objeto que se crea: el impreso o el digital)."
  3. Qué se gana: "Se agregan tipos nuevos de comprobante (el de agencia) sin modificar la confirmación, que es el código que los usa."
