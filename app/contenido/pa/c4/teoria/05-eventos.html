5. Eventos

Para qué sirve

Un evento es algo que pasa en la página: un clic, que el usuario salga de un campo, que elija otra opción de una lista, que se envíe un formulario, que la página termine de cargar. Con addEventListener le decís al navegador: "cuando pase esto, ejecutá esta función". Es la forma de que el código corra cuando el usuario hace algo, y no una sola vez al cargar.

Sintaxis

elemento.addEventListener('nombreDelEvento', () => {
    // lo que se ejecuta cada vez que pasa el evento
});

// con el objeto del evento, para frenar lo que el navegador haría solo
formulario.addEventListener('submit', (event) => {
    event.preventDefault();
});

Qué es cada parte

PiezaQué es
elementoEl objeto que escucha (un botón, un campo, un formulario, window)
addEventListener"Agregar un escuchador": registra la función. No la ejecuta ahora; la guarda para cuando pase el evento
'nombreDelEvento'Texto con el evento, sin el "on" de adelante: 'click', no 'onclick'
() => { ... }La función que se ejecuta cada vez. Puede recibir el objeto del evento (event) con información de lo que pasó
event.preventDefault()Cancela lo que el navegador haría por su cuenta. En un submit: no envía el formulario

Los eventos que usan los ejemplos de la cátedra

Por qué se espera a que cargue

Seleccionar un elemento que el navegador todavía no leyó devuelve null (sección 3). Si todo el código arranca dentro de un load o un DOMContentLoaded, cuando corre ya existen todos los elementos. Para lo que hacen los ejemplos, los dos sirven igual.

Ejemplo 1 — Un contador

Enunciado

La página tiene <button id="btSumar">+1</button> y <span id="total">0</span>. El usuario hace tres clics en el botón. ¿Qué se ve en el span, y cuántas veces corrió cada línea? 

let clics = 0;
const boton = document.getElementById('btSumar');
const total = document.getElementById('total');
boton.addEventListener('click', () => {
    clics = clics + 1;
    total.textContent = clics;
});
LíneaQué haceCómo quedan las variables
let clics = 0;Corre una vez, al cargar el scriptclics = 0
const boton = ..., const total = ...Una vez: agarra los dos elementos—
boton.addEventListener('click', ...)Una vez: registra la función. Todavía no la ejecutaclics = 0
1er clic → cuerpo de la funciónSuma 1 y escribe el número en el spanclics = 1; se ve 1
2do clicOtra vez el cuerpoclics = 2; se ve 2
3er clicOtra vezclics = 3; se ve 3
Respuesta

Se ve 3. Las tres primeras líneas y el addEventListener corrieron una vez; el cuerpo de la función, tres (una por clic).

Por qué: clics está declarada afuera de la función, así que sobrevive entre un clic y otro. Si estuviera adentro (let clics = 0; dentro de las llaves), cada clic arrancaría de cero y siempre se vería 1.

Ejemplo 2 — ¿De qué color queda? (blur)

Enunciado

El usuario hace clic en el campo, escribe tres espacios y sale con Tab. Después vuelve, escribe "Ana" y sale de nuevo. ¿De qué color queda el borde cada vez? 

const txtNombre = document.getElementById('txtNombre');
txtNombre.addEventListener('blur', () => {
    if (txtNombre.value.trim() === '') {
        txtNombre.style.borderColor = 'red';
    } else {
        txtNombre.style.borderColor = 'green';
    }
});
MomentoQué haceCómo queda
CargaRegistra la función para blurBorde normal
Sale con Tab (1ra vez)value es " "; trim() lo deja en ""; "" === '' es trueBorde rojo
Sale (2da vez)value es " Ana" (los espacios siguen); trim() da "Ana", que no es vacíoBorde verde
Respuesta

Primero rojo, después verde. Sin el trim(), los tres espacios habrían contado como "algo escrito" y el primer borde habría quedado verde.

Ejemplo 3 — Frenar el envío (submit)

Enunciado

Un formulario <form id="form" action="proceso.php" method="post"> tiene un campo correo y un botón type="submit". El usuario deja el correo vacío y aprieta el botón. ¿Llega algo a proceso.php? ¿Y si lo completa? 

const form = document.getElementById('form');
form.addEventListener('submit', (event) => {
    event.preventDefault();
    if (document.getElementById('correo').value.trim() !== '') {
        form.submit();
    }
});
LíneaQué haceQué pasa
form.addEventListener('submit', (event) => {Escucha el intento de envío; event trae los datos del evento—
event.preventDefault();Cancela el envío automático: el navegador ya no va a proceso.php por su cuentaPor ahora no se envía nada
if (... !== '')!== es "distinto en valor o tipo". Pregunta si el correo tiene algoVacío: false. Completo: true
form.submit();Envía el formulario a mano, a su action con su methodSolo si el correo tenía algo
Respuesta

Vacío: no llega nada, la página queda igual. Completo: se envía y el navegador pasa a proceso.php, que recibe el correo en $_POST.

Por qué no se repite el evento: form.submit() envía directo, sin disparar otra vez el evento submit. Si lo disparara, la función se llamaría a sí misma para siempre. Este es el esquema del ejemplo 10 de la práctica.

Errores y trampas

Pasar la función, no ejecutarla

boton.addEventListener('click', this.validoDatos()) (con paréntesis) ejecuta validoDatos en ese momento, al cargar, y registra lo que devuelve. Por eso la cátedra siempre envuelve la llamada en una flecha: () => { this.validoDatos(); }.

'click', no 'onclick'

Con addEventListener el evento va sin "on". 'onclick' no da error: simplemente nunca pasa, y el botón no hace nada.

Un botón fuera del <form> no envía

El evento submit lo dispara un botón type="submit" adentro del formulario. Si el botón está afuera, el clic no envía nada: o se lo mete en el <form>, o se escucha su click y se llama a form.submit() (lo que hace la práctica, ejemplo 5).
