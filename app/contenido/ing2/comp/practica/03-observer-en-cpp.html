Ejercicio 3 · Observer

Reconocer el patrón en un código C++

Guía N°3, ejercicio 4. Identifique qué patrón de comportamiento se está siendo implementado en el siguiente código en C++, mencione ventajas y desventajas del mismo, y realice el diagrama correspondiente: 

#include <iostream>
#include <list>
#include <string>

class Ialarma {
 public:
  virtual ~Ialarma(){};
  virtual void Update(const std::string &message_from_subject) = 0;
};
class ISubject {
 public:
  virtual ~ISubject(){};
  virtual void Attach(Ialarma *alarma) = 0;
  virtual void Detach(Ialarma *alarma) = 0;
  virtual void Notify() = 0;
};
class Subject : public ISubject {
 public:
  virtual ~Subject() {
    std::cout << "Goodbye, I was the Subject.\n";
  }
    void Attach(Ialarma *alarma) override {
    list_alarma_.push_back(alarma);
  }
  void Detach(Ialarma *alarma) override {
    list_alarma_.remove(alarma);
  }
  void Notify() override {
    std::list<Ialarma *>::iterator iterator = list_alarma_.begin();
    HowManyalarma();
    while (iterator != list_alarma_.end()) {
      (*iterator)->Update(message_);
      ++iterator;
    }
  }
  void CreateMessage(std::string message = "Empty") {
    this->message_ = message;
    Notify();
  }
  void HowManyalarma() {
    std::cout << "There are " << list_alarma_.size() << " alarmas in the list.\n";
  }
  void SomeBusinessLogic() {
    this->message_ = "change message message";
    Notify();
    std::cout << "I'm about to do some thing important\n";
  }
 private:
  std::list<Ialarma *> list_alarma_;
  std::string message_;
};
class alarma : public Ialarma {
 public:
  alarma(Subject &subject) : subject_(subject) {
    this->subject_.Attach(this);
    std::cout << "Hi, I'm the alarma \"" << ++alarma::static_number_ << "\".\n";
    this->number_ = alarma::static_number_;
  }
  virtual ~alarma() {
    std::cout << "Goodbye, I was the alarma \"" << this->number_ << "\".\n";
  }
  void Update(const std::string &message_from_subject) override {
    message_from_subject_ = message_from_subject;
    PrintInfo();
  }
  void RemoveMeFromTheList() {
    subject_.Detach(this);
    std::cout << "alarma \"" << number_ << "\" removed from the list.\n";
  }
  void PrintInfo() {
    std::cout << "alarma \"" << this->number_ << "\": a new message is available --> " << this->message_from_subject_ << "\n";
  }
 private:
  std::string message_from_subject_;
  Subject &subject_;
  static int static_number_;
  int number_;
};
int alarma::static_number_ = 0;
void ClientCode() {
  Subject *subject = new Subject;
  alarma *alarma1 = new alarma(*subject);
  alarma *alarma2 = new alarma(*subject);
  alarma *alarma3 = new alarma(*subject);
  alarma *alarma4;
  alarma *alarma5;
  subject->CreateMessage("Hello World! :D");
  alarma3->RemoveMeFromTheList();
  subject->CreateMessage("The weather is hot today! :p");
  alarma4 = new alarma(*subject);
  alarma2->RemoveMeFromTheList();
  alarma5 = new alarma(*subject);
  subject->CreateMessage("My new car is great! ;)");
  alarma5->RemoveMeFromTheList();
  alarma4->RemoveMeFromTheList();
  alarma1->RemoveMeFromTheList();
  delete alarma5;
  delete alarma4;
  delete alarma3;
  delete alarma2;
  delete alarma1;
  delete subject;
}
int main() {
  ClientCode();
  return 0;
}
Paso 1 — Es largo: leer solo lo que importa

Con cien líneas adelante, lo que hay que mirar son cuatro cosas:

  1. Las líneas class ...: qué clases hay y de quién heredan.
  2. Los nombres de los métodos de cada una.
  3. Los atributos (están al final de cada clase, debajo de private:).
  4. Los bucles: qué recorren y a qué llaman.

Todos los std::cout y los destructores (~) se pueden saltear.

Paso 3 — Las cuatro preguntas
  1. ¿static y constructor no público? Hay un static int static_number_, pero es un contador para numerar las alarmas, y los constructores son públicos. No es Singleton.
  2. ¿Alguna clase hereda? Sí. No es Facade.
  3. ¿Métodos que devuelven un new? No. No es una fábrica.
  4. ¿Qué guarda la clase del medio? Subject guarda una lista de punteros a la interfaz Ialarma, que es otra interfaz (no la suya), y tiene métodos para agregar, quitar y avisar → Observer.

La línea que resume el patrón es el bucle de Notify():

while (iterator != list_alarma_.end()) {
  (*iterator)->Update(message_);
  ++iterator;
}

Es el recorrido "a la antigua" de la Unidad 0, sección 4: para cada alarma de la lista, llamale Update con el mensaje. Y CreateMessage() es el hecho que dispara el aviso: guarda el mensaje y llama a Notify().

Paso 5 — Comprobarlo con lo que imprime

Las primeras líneas de la salida:

Hi, I'm the alarma "1".
Hi, I'm the alarma "2".
Hi, I'm the alarma "3".
There are 3 alarmas in the list.
alarma "1": a new message is available --> Hello World! :D
alarma "2": a new message is available --> Hello World! :D
alarma "3": a new message is available --> Hello World! :D
alarma "3" removed from the list.
There are 2 alarmas in the list.
alarma "1": a new message is available --> The weather is hot today! :p
alarma "2": a new message is available --> The weather is hot today! :p
  • Se crean tres alarmas y cada una se anota sola.
  • CreateMessage("Hello World! :D"): el sujeto les avisa a las tres.
  • La alarma 3 se da de baja.
  • CreateMessage("The weather..."): ahora les avisa solo a dos.

Es la tienda de la teoría con otros nombres: suscribirse, recibir el aviso, darse de baja.

Paso 6 — El diagrama
  • El rombo con * de Subject a Ialarma es la lista list_alarma_.
  • La flecha de alarma a Subject es el atributo subject_: cada alarma conoce al sujeto para poder anotarse y borrarse sola. (Subject & es una referencia: para leer el código, lo mismo que un puntero.)
Respuesta

Es el patrón Observer (de comportamiento). Subject es el notificador: guarda una lista de Ialarma y tiene Attach para suscribir, Detach para desuscribir y Notify, que recorre la lista llamando a Update. Ialarma es la interfaz suscriptora y alarma el suscriptor concreto, que se registra en el sujeto al crearse y recibe cada mensaje nuevo.

Ventajas:

  • Principio de abierto/cerrado: se agregan suscriptores nuevos sin cambiar el notificador.
  • Las relaciones entre objetos se establecen en tiempo de ejecución (se suscriben y se dan de baja mientras corre).

Desventaja: los suscriptores son notificados en un orden aleatorio.
