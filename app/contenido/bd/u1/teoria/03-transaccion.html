Definiciones

3. Transacción y sus propiedades

Para escribir en la hoja

Transacción: es una unidad de ejecución de un programa, que puede incluir varios accesos a la base (consultas, actualizaciones, procedimientos almacenados, vistas). Empieza con BEGIN TRAN y termina con COMMIT (se confirma) o ROLLBACK (se cancela).

Propiedades:

  • Atomicidad: la transacción se ejecuta completa (todas sus operaciones) o no se ejecuta ninguna.
  • Consistencia: una transacción ejecutada sola (sin otras al mismo tiempo) deja la base en un estado consistente.
  • Aislamiento: si se ejecutan varias transacciones al mismo tiempo, el SGBD las aísla para que no generen inconsistencias entre ellas. Los cambios de cada una se hacen efectivos recién con su COMMIT.

Es la definición de las diapositivas "Transacciones y concurrencia" de la cátedra (clase del 15/09), que traen esas tres propiedades. Otros libros agregan una cuarta, durabilidad (lo confirmado con COMMIT queda guardado aunque después falle el sistema), y juntas forman la sigla ACID. Nombrarla al final no está mal, pero lo de la cátedra son las tres de arriba.

Ejemplo: con el caso del parcial

En la clínica veterinaria, cuando un turno se atiende hay que hacer dos cosas: registrar la consulta y pasar el turno a "Atendido".

BEGIN TRAN;
INSERT INTO Consulta (Numero, Diagnostico, Observaciones, Fecha, NumeroTurno)
VALUES (501, 'Otitis', 'Control en 7 días', '2026-10-14', 3020);
UPDATE Turno SET Estado = 'Atendido' WHERE Numero = 3020;
COMMIT;
  • Atomicidad: si el UPDATE falla, el INSERT se deshace; no queda una consulta para un turno que sigue "Pendiente".
  • Aislamiento: mientras no llega el COMMIT, el resto de los usuarios no ve el cambio a medias.
Errores y trampas
  • La consigna pide definición y propiedades: nombrar las propiedades sin explicar cada una deja la respuesta a medias.
  • Un INSERT con varias filas en un solo VALUES ya es una transacción: si falla una fila, no entra ninguna (clase del 13/08). Tres INSERT separados, no.
