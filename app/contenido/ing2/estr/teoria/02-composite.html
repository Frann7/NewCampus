Estructural

2. Composite

También llamado Objeto compuesto u Object Tree.

Para qué sirve

El problema, con el ejemplo del apunte: un sistema de pedidos.

  • Hay productos y hay cajas.
  • Una caja puede tener productos y otras cajas más chicas, que a su vez tienen productos y más cajas.
  • ¿Cuánto cuesta un pedido? Habría que abrir todas las cajas, saber cuántos niveles hay y de qué clase es cada cosa.

Esa forma, donde algo contiene cosas de su mismo tipo, es un árbol: carpetas con carpetas adentro, un organismo con organismos hijos, un menú con submenús. Composite hace que el producto suelto y la caja cumplan la misma interfaz, con el mismo método precio():

  • el producto devuelve su precio;
  • la caja le pregunta el precio a cada cosa que tiene adentro y devuelve la suma. Si adentro hay otra caja, esa hace lo mismo con lo suyo.

Quien pregunta el precio no necesita saber si le está preguntando a un producto o a una caja con diez niveles: llama a precio() y listo.

Analogía del apunte: un ejército. Está formado por divisiones, que son grupos de brigadas, que son grupos de pelotones, hasta llegar a los soldados. La orden se da arriba y baja sola por todos los niveles.

Propósito

Composite es un patrón estructural que permite componer objetos en estructuras de árbol y trabajar con esas estructuras como si fueran objetos individuales.

Estructura

ParteQué esEn el ejemplo de las cajas
Componente (Component)La interfaz común a los elementos simples y a los compuestos. Declara la operación que todos saben hacer.Articulo, con precio()
Hoja (Leaf)El elemento simple: no tiene nada adentro. Hace el trabajo real.Producto
Compuesto o Contenedor (Composite)El elemento que tiene hijos. Guarda una lista de Componentes (no sabe si son hojas u otros compuestos), tiene métodos para agregar y quitar, y delega el trabajo en sus hijos.Caja
ClienteTrabaja con todos a través de la interfaz Componente.main

Cómo dibujarlo de memoria: un triángulo y una vuelta.

  • Arriba la interfaz Componente; abajo, Hoja y Compuesto, los dos cumpliéndola.
  • Del Compuesto sale un rombo vacío que vuelve al Componente, con un *: el compuesto tiene muchos componentes. Esa flecha que vuelve hacia arriba es la firma del patrón: es lo que permite cajas dentro de cajas.
  • Solo el Compuesto tiene agregar() y eliminar().

Ejemplo 1 — En C++: productos y cajas

El programa, en 6 partes. Los números de la izquierda son los renglones del programa completo; los renglones resaltados son los que hay que mirar.

1Las bibliotecas

#include <iostream>
#include <string>
#include <vector>

2Lo que tienen en comúnComponente

class Articulo {
 public:
  virtual ~Articulo() {}
  virtual double precio() const = 0;
};

Todo artículo sabe decir su precio().

3El elemento simpleHoja

class Producto : public Articulo {
 private:
  std::string nombre_;
  double precio_;

 public:
  Producto(std::string nombre, double precio) : nombre_(nombre), precio_(precio) {}

  double precio() const override {
    return precio_;
  }
};

Devuelve el precio que guarda.

4El que contiene a otrosCompuesto

class Caja : public Articulo {
 private:
  std::vector<Articulo*> contenido_;

 public:
  void agregar(Articulo* articulo) {
    contenido_.push_back(articulo);
  }

  double precio() const override {
    double total = 0;
    for (Articulo* a : contenido_) {
      total = total + a->precio();
    }
    return total;
  }
};

También es un Articulo, y guarda una lista de Articulo: por eso una caja puede ir dentro de otra. Su precio es la suma de lo que tiene adentro.

5El programa: se arma el árbol

int main() {
  Producto* celular = new Producto("Celular", 1000);
  Producto* cargador = new Producto("Cargador", 200);
  Producto* funda = new Producto("Funda", 50);

  Caja* cajaChica = new Caja;
  cajaChica->agregar(cargador);
  cajaChica->agregar(funda);

  Caja* cajaGrande = new Caja;
  cajaGrande->agregar(celular);
  cajaGrande->agregar(cajaChica);

Tres productos, una caja chica con dos de ellos, y una caja grande con el tercero y la caja chica.

6El programa: se pregunta el precio

  std::cout << funda->precio() << "\n";
  std::cout << cajaChica->precio() << "\n";
  std::cout << cajaGrande->precio() << "\n";

  delete celular;
  delete cargador;
  delete funda;
  delete cajaChica;
  delete cajaGrande;
  return 0;
}

La misma llamada sobre una hoja, una caja y una caja con otra caja adentro.

cajaGrande                 1250

Que un método se resuelva llamándose a sí mismo en los niveles de abajo se llama recursión; el apunte lo nombra en las ventajas.

Cómo reconocerlo

DóndeQué lo delata
En un enunciadoAlgo que contiene cosas de su mismo tipo: "una carpeta es un tipo de archivo que contiene más archivos", "un organismo puede tener organismos hijos y organismos padres", "estructura de jerarquía", "colecciones de archivos que a su vez pueden contener otras colecciones", "arrays (y los arrays a su vez en otros arrays)", "una expresión válida estará formada o bien por un número o bien por la suma/resta/división/multiplicación de dos expresiones". Y la otra mitad: poder operar "sin importar si el usuario está trabajando con un solo archivo o con una colección completa".
En un código
  1. una clase base con add/remove (o agregar/eliminar) y una operación común;
  2. una subclase sin hijos (la hoja: Leaf);
  3. otra subclase con una lista de punteros a la clase base (children), cuya operación es un bucle que llama a la misma operación en cada hijo;
  4. en el código de prueba, un "árbol" al que se le agregan "ramas" que tienen "hojas".

Ventajas y desventajas

VentajasDesventajas
  • Se trabaja con estructuras de árbol complejas con comodidad, usando polimorfismo y recursión.
  • Principio de abierto/cerrado: se agregan tipos nuevos de elementos sin romper el código existente, que funciona con el árbol.
  • Puede ser difícil dar una interfaz común a clases cuya funcionalidad es muy distinta. A veces hay que generalizarla demasiado y se vuelve difícil de entender.

Dónde se usa

  • Archivos y carpetas: una carpeta contiene archivos y otras carpetas; el tamaño de una carpeta es la suma de lo que tiene.
  • Organigramas: departamentos con empleados y subdepartamentos; el sueldo total de un departamento.
  • Pedidos con cajas, menús con submenús, expresiones matemáticas (una suma de dos expresiones).

El apunte lo resume en dos casos: cuando hay que implementar una estructura con forma de árbol, y cuando se quiere que el cliente trate igual a los elementos simples y a los complejos.

Ejemplo 2 — Con formato de parcial: dibujarlo y explicarlo

Inventado · con la forma del Parcial 2024, ejercicio 2

"Realice el diagrama (mediante UML) del patrón Composite, dé una breve descripción de su usabilidad y mencione 2 ejemplos."

La consigna pide tres cosas; la respuesta tiene que tener las tres:

  1. El diagrama: la interfaz Componente arriba; debajo, la Hoja y el Compuesto, que la cumplen los dos; y el rombo del Compuesto que vuelve a Componente: su lista de hijos.
  2. La descripción: "Composite es un patrón estructural que se usa cuando los objetos forman una estructura de árbol: elementos simples y contenedores que agrupan elementos simples u otros contenedores. Todos comparten una interfaz, de modo que el cliente trata igual a un elemento solo que a un grupo entero."
  3. Dos ejemplos: no alcanza con nombrarlos. A cada uno se le suma una línea que diga por qué ahí va el patrón:
    • Las carpetas y los archivos de un sistema de archivos. "Una carpeta contiene archivos y otras carpetas. El archivo es la hoja y la carpeta el compuesto: para saber cuánto ocupa una carpeta se le pide el tamaño, y ella lo suma pidiéndoselo a todo lo que tiene adentro."
    • Un pedido con productos sueltos y cajas. "Una caja trae productos y también otras cajas. El precio se le pide igual a un producto que a una caja: la caja devuelve la suma de su contenido."

Ejemplo 3 — Con formato de parcial: aplicarlo a un enunciado

Práctica 03 · ejercicio 3

"Crea una estructura de árbol que represente una organización jerárquica de empleados en una empresa, donde los nodos hoja son empleados individuales y los nodos compuestos son departamentos. Implementa el patrón Composite para calcular el salario total de la organización."

"Se solicita un diagrama UML y una mínima explicación de por qué aplica el patrón."

Frase del enunciadoQué significaParte del patrón
"una estructura de árbol (...) una organización jerárquica"Unos elementos contienen a otros, en varios nivelesLa situación para la que existe Composite
"los nodos hoja son empleados individuales"El elemento simple, que no contiene a nadieLa Hoja: Empleado
"los nodos compuestos son departamentos"El elemento que agrupa: tiene empleados y también otros departamentosEl Compuesto: Departamento, con su lista miembros
"calcular el salario total de la organización"La operación que se le pide igual a un empleado que a un departamentoEl método de la interfaz Componente (Unidad): salario()

Justificación, en tres partes: qué patrón y qué frase lo pide, cómo queda armado en este caso y qué se gana.

  1. Qué patrón y por qué: "Se aplica Composite, un patrón estructural, porque la organización es un árbol: hay elementos simples (los empleados) y elementos que agrupan a otros (los departamentos, que tienen empleados y otros departamentos)."
  2. Cómo se aplica: "Unidad es el componente: la interfaz común, con salario(). Empleado es la hoja y devuelve su sueldo. Departamento es el compuesto: guarda una lista de Unidad, así que puede tener empleados u otros departamentos, y su salario() suma el de todos sus miembros."
  3. Qué se gana: "El salario total se obtiene pidiéndole salario() al departamento de más arriba, sin distinguir qué hay adentro, y la empresa puede reorganizarse en los niveles que quiera sin cambiar ese cálculo."

El enunciado ya nombra el patrón y sus partes ("nodos hoja", "nodos compuestos"): lo que se evalúa es el diagrama, con el rombo de Departamento volviendo a la interfaz y no a Empleado.

Ejemplo 4 — Con formato de parcial: identificar los patrones de un enunciado

Inventado · con la forma del Parcial 2025, Práctica 1

"A partir del siguiente enunciado identifique cuáles serían los patrones de diseño que utilizaría y justifique por qué eligió los mismos."

"La plataforma educativa EduPlus organiza sus cursos en módulos. Un módulo puede contener lecciones individuales y también otros módulos, que a su vez contienen más lecciones. La plataforma necesita calcular la duración total de un curso y mostrar su contenido tratando de igual forma a una lección suelta que a un módulo completo."

"Al finalizar cada curso, el sistema genera el certificado del alumno. Existen distintos tipos de certificado (de asistencia, de aprobación y de honor) y cada tipo de curso tiene su propio procedimiento para generar el que le corresponde, sin que el módulo de inscripciones deba conocer cómo se arma cada uno. Se espera poder agregar nuevos tipos de certificado más adelante sin modificar lo ya desarrollado."

"Además, cada vez que un docente publica una nueva lección, todos los alumnos inscriptos en el curso deben ser notificados automáticamente. Los alumnos pueden activar o desactivar estos avisos cuando lo deseen."

El enunciado mezcla Composite con otros dos patrones, como en el parcial. El método: un párrafo, una necesidad, un patrón. En cada párrafo se busca qué se necesita y la frase que lo dice.

PárrafoLa necesidadLa frase que lo delataPatrón
1. Los módulosTratar igual a una lección que a un módulo, que contiene lecciones y más módulos"Un módulo puede contener lecciones individuales y también otros módulos (...) tratando de igual forma"Composite (estructural)
2. Los certificadosCrear distintos tipos de certificado sin que inscripciones sepa cómo, y poder sumar tipos"distintos tipos de certificado (...) cada tipo de curso tiene su propio procedimiento para generar el que le corresponde"Factory Method (creacional)
3. Los avisosQue los alumnos se enteren solos de cada lección nueva"cada vez que un docente publica (...) deben ser notificados automáticamente (...) activar o desactivar estos avisos"Observer (de comportamiento)
Cómo quedaría escrita la respuesta

Composite, para la estructura de los cursos. "Un módulo puede contener lecciones individuales y también otros módulos": es un árbol. La lección es la hoja y el módulo el compuesto, con una interfaz común. La duración total se le pide al módulo raíz, que suma la de todo lo que contiene, y la plataforma trata "de igual forma" a una lección que a un módulo.

Factory Method, para los certificados. Hay "distintos tipos de certificado" y "cada tipo de curso tiene su propio procedimiento para generar el que le corresponde", sin que inscripciones sepa cómo se arma. El certificado es el producto; hay un creador con un método fábrica y un creador concreto por cada tipo. Un tipo nuevo se agrega con clases nuevas, "sin modificar lo ya desarrollado".

Observer, para los avisos. "Cada vez que un docente publica una nueva lección" los alumnos inscriptos "deben ser notificados automáticamente", y pueden "activar o desactivar estos avisos". El curso es el notificador y los alumnos son los suscriptores, que se suscriben o se dan de baja cuando quieren.

Cada justificación tiene las mismas tres partes: el patrón y para qué parte del sistema, la frase del enunciado que lo pide (entre comillas) y cómo queda armado, con lo que se gana.

Las trampas de este enunciado
  • Los párrafos 1 y 3 tienen los dos una lista. En el 1, lo que hay adentro del módulo es del mismo tipo (otros módulos) y se le pide un resultado: Composite. En el 3, la lista es de alumnos y solo se les avisa: Observer.
  • Hay "tipos" de certificado, no familias que tengan que combinar: es Factory Method y no Abstract Factory.

Ejemplo 5 — Con formato de parcial: reconocerlo en un código

Inventado · con la forma de la Guía N°1, ejercicio 2

"Dado el siguiente código identifique qué tipo de patrón se implementa. Justifique."

Los renglones resaltados son los que lo delatan:

#include <iostream>
#include <list>
#include <string>

class Tarea {
 public:
  virtual ~Tarea() {}
  virtual void Add(Tarea* tarea) {}
  virtual void Remove(Tarea* tarea) {}
  virtual std::string Operation() const = 0;
};

class TareaSimple : public Tarea {
 public:
  std::string Operation() const override {
    return "Tarea";
  }
};

class Proyecto : public Tarea {
 protected:
  std::list<Tarea*> children_;

 public:
  void Add(Tarea* tarea) override {
    this->children_.push_back(tarea);
  }
  void Remove(Tarea* tarea) override {
    children_.remove(tarea);
  }
  std::string Operation() const override {
    std::string result;
    for (const Tarea* c : children_) {
      if (c == children_.back()) {
        result += c->Operation();
      } else {
        result += c->Operation() + "+";
      }
    }
    return "Proyecto(" + result + ")";
  }
};

int main() {
  Tarea* sitio = new Proyecto;
  Tarea* disenio = new Proyecto;
  Tarea* t1 = new TareaSimple;
  Tarea* t2 = new TareaSimple;
  Tarea* t3 = new TareaSimple;
  disenio->Add(t1);
  disenio->Add(t2);
  sitio->Add(disenio);
  sitio->Add(t3);
  std::cout << sitio->Operation() << "\n";
  delete sitio;
  delete disenio;
  delete t1;
  delete t2;
  delete t3;
  return 0;
}
Proyecto(Proyecto(Tarea+Tarea)+Tarea)
RenglónLo que se veQué parte del patrón es
5La clase base, con el método virtual puro Operation().El Componente: la interfaz común
13No guarda a nadie: hace el trabajo ella misma.La Hoja
22Una lista de punteros a su propia clase base.Los hijos del Compuesto (Proyecto)
25Métodos para sumar y sacar hijos (Add, Remove).El armado del árbol
33Recorre los hijos, le pide lo mismo a cada uno y junta los resultados.La delegación en los hijos
52Se mete un Proyecto adentro de otro.El árbol

Respuesta: "Es el patrón Composite (estructural). Tarea es el componente: la interfaz común, con Operation(). TareaSimple es la hoja. Proyecto es el compuesto: guarda una lista de Tarea* (children_), así que puede contener tareas simples u otros proyectos, y su Operation() recorre los hijos y combina sus resultados. El cliente llama a Operation() sobre el proyecto raíz igual que sobre una tarea suelta."

No es Observer

También hay una lista y un bucle. La diferencia: acá la lista es del mismo tipo que la clase que la tiene (Proyecto es una Tarea y guarda Tareas) y del bucle vuelve un resultado. En Observer la lista es de otra interfaz y solo se avisa.

Ejemplo 6 — Con formato de parcial: agregarlo a un diagrama

Inventado · con la forma de la Guía N°1, ejercicio 1

"Dado el siguiente diagrama de un reproductor de música: una Playlist tiene canciones y calcula su duración sumando la de cada una. Ahora se pide que una playlist pueda contener también otras playlists, y que la duración total se siga calculando de la misma manera. Modifique el diagrama aplicando el patrón de diseño que corresponda. Justifique."

Qué hay en el diagrama. La lista de Playlist es de Cancion (canciones: Cancion[]) y el rombo va a Cancion: adentro de una playlist solo entran canciones. Las dos clases ya tienen un método con el mismo nombre, duracion(): es el que van a compartir.

Qué se cambia, en orden:

  1. Crear la interfaz Componente. Elemento, con el método que comparten: duracion(): int.
  2. Hacer que las dos clases la cumplan. Cancion (la hoja) y Playlist (el compuesto), con línea punteada y triángulo hacia Elemento.
  3. Cambiar el tipo de la lista. En Playlist, canciones: Cancion[] pasa a elementos: Elemento[], y agregar(c: Cancion) a agregar(e: Elemento).
  4. Mover el rombo. Ya no va de Playlist a Cancion, sino de Playlist a Elemento.
  5. Apuntar el cliente a la interfaz. Reproductor pasa a conocer a Elemento: puede reproducir una canción o una playlist.

El diagrama modificado:

Justificación: "Se aplica Composite porque las playlists pasan a formar un árbol: una playlist contiene canciones y otras playlists. Elemento es la interfaz común; Cancion es la hoja y Playlist el compuesto, que guarda una lista de Elemento. Su duracion() suma la de cada elemento, sea una canción o una playlist entera, y el reproductor trata igual a las dos."

A tener en cuenta al modificar el diagrama
  • El rombo va a la interfaz, no a la hoja. Si queda en Cancion, una playlist no puede contener otra y no hay patrón.
  • Playlist termina con dos líneas hacia Elemento: la punteada (es un elemento) y la del rombo (tiene elementos).
  • El método compartido se llama igual en las tres cajas.
  • agregar() va solo en el compuesto: una canción no tiene a quién agregar.

Errores y trampas

Una lista de cosas no es Composite

Que una clase tenga una lista de otra (un curso con alumnos) es una agregación común. Es Composite cuando el que contiene y lo contenido cumplen la misma interfaz, y por eso se pueden anidar: un curso no puede contener cursos; una carpeta sí puede contener carpetas.

El rombo va al Componente, no a la Hoja

Si el Compuesto guardara una lista de Hojas, no podría contener otros Compuestos y no habría árbol. La lista es del tipo de arriba.
