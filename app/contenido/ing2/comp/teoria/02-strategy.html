Comportamiento

2. Strategy

También llamado Estrategia.

Para qué sirve

El problema, con el ejemplo del apunte: una aplicación de navegación.

  • La primera versión calculaba rutas en auto.
  • Después se agregaron las rutas a pie, y más tarde en transporte público, para ciclistas, turísticas...
  • Cada forma nueva se metía en la misma clase, que duplicaba su tamaño. Tocar un algoritmo podía romper los otros, y la clase era imposible de mantener.

Todas esas formas hacen lo mismo (calcular una ruta) de manera distinta. Strategy saca cada forma a su propia clase, todas con la misma interfaz, y la clase original se queda con una referencia a una de ellas y le pasa el trabajo. Para cambiar de forma se le cambia el objeto, incluso mientras el programa corre.

  • Cada forma de hacer la tarea es una estrategia.
  • La clase original, la que usa la estrategia, es el contexto.

Analogía del apunte: llegar al aeropuerto. Se puede ir en colectivo, en taxi o en bicicleta: son estrategias de transporte, y se elige una según el presupuesto o el tiempo que haya.

Propósito

Strategy es un patrón de comportamiento que permite definir una familia de algoritmos, colocar cada uno en una clase separada y hacer sus objetos intercambiables.

Un algoritmo, acá, es simplemente "una forma de hacer algo": de ordenar, de calcular un precio, de frenar, de armar una ruta.

Estructura

ParteQué esEn el ejemplo del navegador
Contexto (Context)La clase que necesita hacer la tarea. Guarda una referencia a una estrategia y le delega el trabajo. Tiene un método para cambiarla. No sabe cuál estrategia concreta tiene.Navegador
Estrategia (Strategy)La interfaz común a todas las formas de hacer la tarea. Un solo método: el que ejecuta el algoritmo.EstrategiaRuta, con calcularRuta()
Estrategias ConcretasCada variante del algoritmo.RutaEnAuto, RutaAPie
ClienteElige la estrategia concreta y se la pasa al contexto.main

Cómo dibujarlo de memoria:

  • A la izquierda el Contexto, con el atributo estrategia y el método para cambiarla.
  • Un rombo vacío del Contexto a la interfaz Estrategia (también se acepta una flecha simple): el contexto tiene una estrategia. Sin asterisco: es una sola por vez.
  • Debajo de la interfaz, las estrategias concretas, con línea punteada.
Se parece mucho al diagrama de Observer

Los dos son "una clase con un rombo hacia una interfaz, y clases concretas debajo". La diferencia está en el rombo y en los métodos: Observer tiene una lista (*) y los métodos suscribir, desuscribir y notificar; Strategy tiene una sola referencia y un método para cambiarla.

Ejemplo 1 — En C++: el navegador

#include <iostream>
#include <string>

class EstrategiaRuta {
 public:
  virtual ~EstrategiaRuta() {}
  virtual std::string calcularRuta(std::string origen, std::string destino) const = 0;
};

class RutaEnAuto : public EstrategiaRuta {
 public:
  std::string calcularRuta(std::string origen, std::string destino) const override {
    return "En auto de " + origen + " a " + destino + ": por la ruta, 20 minutos";
  }
};

class RutaAPie : public EstrategiaRuta {
 public:
  std::string calcularRuta(std::string origen, std::string destino) const override {
    return "A pie de " + origen + " a " + destino + ": por el camino costero, 3 horas";
  }
};

class Navegador {
 private:
  EstrategiaRuta* estrategia_;

 public:
  Navegador(EstrategiaRuta* estrategia) : estrategia_(estrategia) {}

  void cambiarEstrategia(EstrategiaRuta* estrategia) {
    estrategia_ = estrategia;
  }

  void mostrarRuta(std::string origen, std::string destino) const {
    std::cout << estrategia_->calcularRuta(origen, destino) << "\n";
  }
};

int main() {
  EstrategiaRuta* enAuto = new RutaEnAuto;
  EstrategiaRuta* aPie = new RutaAPie;

  Navegador navegador(enAuto);
  navegador.mostrarRuta("Parana", "Oro Verde");

  navegador.cambiarEstrategia(aPie);
  navegador.mostrarRuta("Parana", "Oro Verde");

  delete enAuto;
  delete aPie;
  return 0;
}

Qué imprime y por qué

En auto de Parana a Oro Verde: por la ruta, 20 minutos
A pie de Parana a Oro Verde: por el camino costero, 3 horas

Mismo navegador, misma llamada, mismos datos: cambió el resultado porque cambió la estrategia. Para agregar la ruta en bicicleta se escribe una clase RutaEnBici, y Navegador no se toca.

Es el mismo esqueleto del Duenio y su mascota de la Unidad 0, sección 4: una clase que guarda un puntero a una interfaz, lo recibe por constructor, lo puede cambiar y le delega.

Cómo reconocerlo

DóndeQué lo delata
En un enunciadoVarias formas de hacer una misma cosa, entre las que se elige: "el sistema aplique automáticamente la estrategia de configuración más adecuada según sus elecciones", distintas formas de calcular un precio, un descuento, un envío, un ordenamiento; "poder cambiar de un algoritmo a otro". Suele aparecer junto a "según..." (según el cliente, según el tipo, según la opción elegida).
En un código
  1. una clase (Context) con un atributo que es un puntero a una interfaz, recibido en el constructor;
  2. un método para reemplazarlo (set_strategy, setStrategy);
  3. un método que le delega el trabajo: llama al único método de la interfaz (DoAlgorithm, execute);
  4. varias clases que cumplen la interfaz y hacen lo mismo de distinta forma (una ordena de menor a mayor, la otra al revés);
  5. en el código de prueba, el mismo contexto usado dos veces, cambiándole la estrategia en el medio.

Ventajas y desventajas

VentajasDesventajas
  • Se pueden intercambiar algoritmos dentro de un objeto durante la ejecución.
  • Se aíslan los detalles de un algoritmo del código que lo usa.
  • Se puede sustituir la herencia por composición (en vez de una subclase por cada variante, un objeto intercambiable).
  • Principio de abierto/cerrado: se agregan estrategias nuevas sin cambiar el contexto.
  • Si hay un par de algoritmos que casi no cambian, no se justifica complicar el programa con clases e interfaces nuevas.
  • Los clientes deben conocer las diferencias entre estrategias para elegir la adecuada.
  • Muchos lenguajes modernos permiten lo mismo con funciones anónimas, sin tantas clases.

Dónde se usa

  • Cuando se quieren usar distintas variantes de un algoritmo dentro de un objeto y poder cambiar de una a otra en ejecución: rutas, formas de ordenar, formas de pago.
  • Cuando hay muchas clases parecidas que solo difieren en cómo hacen cierta cosa: se saca esa cosa a una jerarquía aparte y las clases se unifican. Es el ejemplo de la guía: coches que solo difieren en cómo frenan.
  • Para separar la lógica de negocio de una clase de los detalles de un algoritmo: cálculo de envío, de impuestos, de descuentos.

Ejemplo 2 — Con formato de parcial: reconocerlo en un enunciado

Parcial 2025 · Práctica 1 (primer párrafo)

"La empresa Muebles Express S.A. se dedica a la fabricación y comercialización de muebles personalizados a través de su plataforma web. Los clientes pueden ingresar al sitio, navegar por el catálogo de productos y seleccionar los muebles que desean comprar, teniendo la posibilidad de personalizar cada artículo según diferentes parámetros: tipo de material, color, tamaño y estilo de ensamblaje. Cada cliente debe poder elegir su combinación preferida de estas opciones, de manera que el sistema aplique automáticamente la estrategia de configuración más adecuada según sus elecciones y genere un presupuesto final."

"el sistema aplique automáticamente la estrategia de configuración más adecuada"Hay varias formas de configurar y se usa una. El enunciado usa la palabra del patrónEstrategia: EstrategiaConfiguracion
"según sus elecciones"Cuál se usa se decide en el momento, por lo que elige el clienteLa estrategia se le pasa al contexto en ejecución

Respuesta: "Para la personalización usaría Strategy. El enunciado dice que el sistema aplica la estrategia de configuración más adecuada según las elecciones del cliente: hay varias formas de configurar un mueble y calcular su presupuesto, y se elige una en tiempo de ejecución. Cada forma es una estrategia concreta que implementa una interfaz común; el configurador (contexto) guarda la estrategia elegida y le delega el cálculo. Se pueden agregar formas nuevas sin modificar el configurador."

El ejercicio 4 de Patrones de Diseño Parte 2 da un diagrama y pregunta qué patrón es: un Coche con un rombo hacia la interfaz IComportamientoFrenos, que tiene debajo FrenadoNormal y FrenadoABS. Errores y trampas

El contexto no elige

Si la clase tiene un if que decide "si es en auto, hago esto; si es a pie, esto otro", no hay patrón: es el problema original. En Strategy la estrategia llega desde afuera y el contexto solo la usa.

Con qué se confunde
  • Con Factory Method: los dos tienen una interfaz con variantes. Factory Method resuelve qué objeto se crea (hay un método que devuelve un new); Strategy resuelve cómo se hace una tarea (hay un método que hace el trabajo, y nadie crea nada).
  • Con Observer: en el diagrama, una lista con * y métodos de suscripción es Observer; una sola referencia y un método para cambiarla es Strategy.
