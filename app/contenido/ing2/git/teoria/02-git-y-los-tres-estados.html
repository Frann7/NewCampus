Git

2. Git y los tres estados

Para qué sirve

Antes de aprender comandos hay que tener claro dónde están los archivos en cada momento. Todos los comandos de Git hacen lo mismo: mover cambios de un lugar a otro. Si se entiende el mapa, los comandos salen solos; si no, se memorizan sin entenderlos. El propio apunte lo avisa: los tres estados son "lo más importante que debes recordar acerca de Git".

Qué es Git

Git es un sistema de control de versiones distribuido, diseñado para rastrear y gestionar cambios en el código fuente. Lo creó Linus Torvalds en 2005 para mejorar el desarrollo colaborativo, permitiendo que varias personas trabajen en el mismo proyecto sin sobrescribir el trabajo de los demás. Es libre y de código abierto.

Puntos clave de Git

  • Control de versiones: guarda distintas versiones del proyecto y permite revisarlas y restaurarlas.
  • Distribuido: cada copia del proyecto es un repositorio completo; se puede trabajar sin conexión y confirmar cambios en local.
  • Trabajo en equipo: con ramas (branches), cada uno trabaja sin afectar la versión principal y los cambios se integran al final.
  • Historial detallado: queda registrado cada cambio.

Cómo guarda los datos: fotos, no diferencias

  • Los otros sistemas (CVS, Subversion) guardan, para cada archivo, la lista de cambios que tuvo a lo largo del tiempo.
  • Git guarda copias instantáneas (snapshots): cada vez que se confirma un cambio, toma una foto de cómo están todos los archivos en ese momento. Si un archivo no cambió, no lo guarda de nuevo: guarda un enlace al que ya tenía.

Dos consecuencias que el apunte destaca:

  • Casi todas las operaciones son locales: como toda la historia está en el disco propio, ver el historial o comparar versiones no necesita conectarse al servidor. Por eso es rápido.
  • Tiene integridad: Git calcula una suma de comprobación de todo lo que guarda, y no se puede perder información ni corromper un archivo sin que lo detecte.

Los tres estados de un archivo

EstadoEn inglésQué significa
ModificadomodifiedEl archivo se cambió, pero todavía no se confirmó en la base de datos.
PreparadostagedEl archivo modificado se marcó para que vaya en la próxima confirmación.
ConfirmadocommittedLos datos están guardados de manera segura en la base de datos local.

El flujo de trabajo básico
  1. Modificás archivos en el directorio de trabajo.
  2. Preparás los archivos, agregándolos al área de preparación.
  3. Confirmás los cambios: Git toma lo que está en el área de preparación y guarda esa foto de manera permanente en el directorio de Git.

Hay un cuarto lugar, fuera de la computadora: el repositorio remoto (en GitHub o GitLab), la copia compartida con el equipo. Un commit queda primero en el repositorio local; para que lo vean los demás hay que subirlo (sección 3).

Ejemplo 1 — Seguir un archivo por los tres estados

En un proyecto con index.html ya confirmado, se le cambia el título y se crea un archivo nuevo, estilos.css. El comando git status --short muestra el estado de cada archivo en una línea.

Después de editar (nada preparado todavía):

 M index.html
?? estilos.css
  • M en la segunda columna: index.html está modificado en el directorio de trabajo.
  • ??: estilos.css es nuevo y Git todavía no lo sigue.

Después de git add .:

A  estilos.css
M  index.html
  • Las letras pasaron a la primera columna: los dos están preparados. A es "agregado"; M, "modificado".

Después de git commit, git status --short no muestra nada: todo está confirmado y el directorio de trabajo quedó igual a la última foto.

Errores y trampas

Guardar el archivo no es confirmar

Guardar en el editor deja el archivo modificado. Para Git faltan dos pasos: prepararlo (add) y confirmarlo (commit).

Confirmar no es subir

Un commit guarda en el repositorio local: nadie más lo ve. La pregunta del parcial pedía que las ramas quedaran "actualizadas en el remoto": eso es un paso aparte, git push.

Los nombres, en los dos idiomas

El parcial escribió Working Directory en inglés. Conviene saberlos de las dos formas: directorio de trabajo / working directory, área de preparación / staging area, repositorio / repository.
