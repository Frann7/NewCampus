Ejercicio 4: Utilizando lenguaje SQL, crear la tabla de Reservas, con sus atributos y claves correspondientes.

CREATE TABLE Reserva (
  Numero       INT          NOT NULL,
  FechaHora    DATETIME     NOT NULL,
  Estado       VARCHAR(20)  NOT NULL,
  DNI          VARCHAR(13)  NOT NULL,
  CodigoClase  INT          NOT NULL,
  CONSTRAINT PK_Reserva PRIMARY KEY (Numero),
  CONSTRAINT FK_Reserva_Socio FOREIGN KEY (DNI) REFERENCES Socio(DNI),
  CONSTRAINT FK_Reserva_Clase FOREIGN KEY (CodigoClase) REFERENCES Clase(Codigo)
);

Las tablas Socio y Clase tienen que estar creadas antes.

Qué evalúa

El CREATE TABLE de la Unidad 3, con la PK y las dos FK. Sale de la tabla del ejercicio 3:

Reserva (Numero (PK), FechaHora, Estado, DNI (FK), CodigoClase (FK))
Socio (DNI (PK), Nombre, Direccion, IdCiudad (FK), CodigoMembresia (FK))
Clase (Codigo (PK), Nombre, Dia, Hora, Legajo (FK))
ColumnaTipoPor qué
NumeroINT NOT NULLEntero, es la PK
FechaHoraDATETIME NOT NULLFecha y hora juntas
EstadoVARCHAR(20) NOT NULLPendiente, Asistida o Cancelada
DNIVARCHAR(13) NOT NULLMismo tipo que Socio.DNI; obligatoria, Reserva tiene (1,1)
CodigoClaseINT NOT NULLMismo tipo que Clase.Codigo; obligatoria
Resolución 
CREATE TABLE Reserva (
  Numero       INT          NOT NULL,
  FechaHora    DATETIME     NOT NULL,
  Estado       VARCHAR(20)  NOT NULL,
  DNI          VARCHAR(13)  NOT NULL,
  CodigoClase  INT          NOT NULL,
  CONSTRAINT PK_Reserva PRIMARY KEY (Numero),
  CONSTRAINT FK_Reserva_Socio FOREIGN KEY (DNI) REFERENCES Socio(DNI),
  CONSTRAINT FK_Reserva_Clase FOREIGN KEY (CodigoClase) REFERENCES Clase(Codigo)
);

Trampas

  • Dos FK, cada una con su FOREIGN KEY ... REFERENCES.
  • Se podría poner DEFAULT 'Pendiente' en Estado: no es obligatorio, pero muestra que se conoce.
