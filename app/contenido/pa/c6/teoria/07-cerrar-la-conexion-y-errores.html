7. Cerrar la conexión y los errores

Para qué sirve

Según la cátedra, una vez que se accedió a los datos y se trabajó con ellos hay que cerrar la conexión, para que se liberen los datos de la memoria y se borren los apuntadores creados. Y mientras la conexión está abierta, cualquier consulta puede fallar (una tabla mal escrita, un SQL con un error): la guía trae funciones para saber qué pasó.

Sintaxis

$mysqli = new mysqli('Host', 'usuarioDB', 'contraseñaDB', 'BasedeDatos');

// conjunto de acciones

$mysqli->close();

En estilo procedural: mysqli_close($conexion);

Qué es cada parte: las herramientas para los errores

ObjetosProceduralQué daPara qué error
$mysqli->connect_errnomysqli_connect_errno()El número del error al conectar (0 si no hubo)De conexión (sección 3)

Las de conexión no necesitan la conexión como parámetro (justamente, puede no haberla). Las de consulta sí: hay que decirles de qué conexión es el último error.

Ejemplo 1 — El orden completo de un script

Enunciado

Listar apellido y nombres de la tabla de ejemplo, de principio a fin, cerrando la conexión.

<?php
$mysqli = new mysqli('127.0.0.1', 'root', '', 'Personal');

$resultado = $mysqli->query('SELECT * FROM personas');

while ($persona = $resultado->fetch_assoc()) {
    echo $persona['apellido'] . ", " . $persona['nombres'] . "<br>";
}

$mysqli->close();
?>
LíneaQué haceCómo quedan las variables
21. Conectar$mysqli = la conexión
42. Consultar$resultado = apuntador a 3 filas
6-83. Recorrer: una vuelta por fila, imprimiendo dos columnas$persona = García, Bonnet, Aramburu, y al final null
104. Cerrar: libera la memoria y los apuntadores$mysqli ya no sirve para consultar

Qué imprime, con la tabla de ejemplo (verificado armando esas filas):

García, Gabriel<br>Bonnet, Federico<br>Aramburu, Exequiel<br>

En pantalla, un nombre por renglón. El close() va al final, cuando ya no se usa más la base.

Ejemplo 2 — ¿Qué muestra si la tabla está mal escrita?

Enunciado

La tabla se llama personas, pero el SQL dice persona. Con el comportamiento viejo de mysqli (el de la cátedra), ¿qué imprime? 

<?php
mysqli_report(MYSQLI_REPORT_OFF);
$mysqli = new mysqli('127.0.0.1', 'root', '', 'Personal');

$resultado = $mysqli->query('SELECT * FROM persona');

if (!$resultado) {
    echo "Error " . $mysqli->errno . ": " . $mysqli->error;
}

$mysqli->close();
?>
LíneaQué haceCómo quedan las variables
2Apaga las excepciones: los errores quedan guardados en vez de cortar el script
3Conecta (bien: la base existe)connect_errno = 0
5La consulta falla: no existe la tabla persona$resultado = false
7!false es verdadero: entra
8Muestra el número y el texto del error de la última función, que fue el query()errno = 1146
11Cierra igual: la conexión sí estaba abierta

Qué imprime. Este necesita la base para correr; el mensaje es el que arma MariaDB para una tabla que no existe:

Error 1146: Table 'personal.persona' doesn't exist

El texto lo escribe el servidor (en inglés, y con el nombre de la base en minúsculas en Windows). Con el comportamiento de fábrica de PHP 8.2, sin la línea 2, el mismo error aparece como Fatal error: Uncaught mysqli_sql_exception en la línea 5, salvo que la consulta esté adentro de un try / catch como el de la sección 3.

Errores y trampas
  • errno es de la última función. Si después del query() fallido hacés otra cosa con la conexión que anda bien, el error anterior se pierde: hay que mirarlo enseguida.
  • Después de close() la conexión no se puede usar. Cualquier query() posterior da error. Si hay que volver a consultar, se abre otra.
  • Mostrar el error en pantalla sirve para practicar; en un sitio real se le muestra al usuario un mensaje genérico, porque el texto del error cuenta cómo son las tablas.
