Normalizar: la biblioteca

Normalizar el siguiente conjunto de datos de una biblioteca.

Libros (ID Libro, Título, ID Autor, Año Publicación, ID Editor, Género)
Autores (ID Autor, Nombre, Nacionalidad)
Editorial (ID Editorial, Nombre, Dirección)
Prestamos (ID Préstamo, ID Libro, ID Miembro, Nombre, Dirección, Teléfono, Fecha Préstamo,
           Fecha Devolución)
Reserva (ID Reserva, ID Libro, ID Miembro, Nombre, Dirección, Teléfono, Fecha Reserva)
Multas (ID Multa, ID Préstamo, Monto, Fecha)
Comentarios (ID Comentario, ID Libro, Nombre Autor, ID Miembro, Nombre Miembro, Comentario, Fecha)
Tabla por tabla

El método de la Unidad 2, sección 2: poner la PK, sacar lo que se repite, sacar lo que describe a otra cosa y borrar lo que ya se obtiene por otra FK.

TablaQué está malQué se hace
LibrosNada: los datos del autor y de la editorial ya están en sus tablasPK IdLibro; IdAutor e IdEditorial quedan como FK
Autores, EditorialNadaQuedan igual, con su PK
PrestamosNombre, Dirección y Teléfono son del miembro, no del préstamo: dependen de IdMiembro (transitiva)Tabla nueva Miembro; en Préstamo queda IdMiembro como FK
ReservaLos mismos datos del miembro, repetidosSe sacan; queda IdMiembro como FK
MultasNadaIdPrestamo queda como FK
ComentariosNombre Autor ya se obtiene por el libro (IdLibro → Libro → Autor); Nombre Miembro, por IdMiembroSe borran los dos nombres

Variante: un libro con varios autores

En clase un alumno preguntó qué pasa si un libro tiene varios autores. No es un "multivaluado": es una relación N:M entre libro y autor, y va a una tabla intermedia. Libro deja de tener IdAutor: 

Libro (IdLibro (PK), Titulo, AnioPublicacion, Genero, IdEditorial (FK))
Libro_Autor (IdLibro (PK)(FK), IdAutor (PK)(FK))
Errores y trampas
  • El error más común: dejar el nombre del miembro en Préstamo "para tenerlo a mano". Se obtiene con un JOIN.
  • Si al normalizar sale una tabla nueva (Miembro), hay que agregarla también al DER.
