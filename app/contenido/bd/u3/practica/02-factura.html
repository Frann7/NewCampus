Apunte de Normalización · Cabecera y detalle

Factura con su detalle

Crear con SQL las tablas de la factura (cabecera y detalle), con sus atributos y claves. Es el ejemplo en 3FN del apunte de la cátedra:

Cliente (Codigo_cliente (PK), Nombre_cliente, Direccion_cliente, Localidad_cliente)
Articulo (Codigo_articulo (PK), Descripcion)
Factura (Codigo_factura (PK), Codigo_cliente (FK), Fecha_factura, Forma_pago, Tipo_IVA)
Detalle_Factura (Codigo_factura (PK)(FK), Codigo_articulo (PK)(FK), Cantidad, Importe)
Paso 1 — Qué es cabecera y qué es detalle
  • Cabecera (Factura): lo que se escribe una vez por factura: número, cliente, fecha, forma de pago.
  • Detalle (Detalle_Factura): un renglón por artículo facturado. Su PK es el par (factura, artículo), y las dos partes son FK.
Paso 2 — El orden

Cliente y Articulo primero (no tienen FK); después Factura (apunta a Cliente); al final Detalle_Factura (apunta a Factura y a Articulo).

Resolución 
CREATE TABLE Cliente (
  Codigo_cliente     INT           NOT NULL,
  Nombre_cliente     VARCHAR(100)  NOT NULL,
  Direccion_cliente  VARCHAR(150),
  Localidad_cliente  VARCHAR(50),
  CONSTRAINT PK_Cliente PRIMARY KEY (Codigo_cliente)
);

CREATE TABLE Articulo (
  Codigo_articulo  INT           NOT NULL,
  Descripcion      VARCHAR(100)  NOT NULL,
  CONSTRAINT PK_Articulo PRIMARY KEY (Codigo_articulo)
);

CREATE TABLE Factura (
  Codigo_factura  INT          NOT NULL,
  Codigo_cliente  INT          NOT NULL,
  Fecha_factura   DATE         NOT NULL,
  Forma_pago      VARCHAR(30),
  Tipo_IVA        VARCHAR(30),
  CONSTRAINT PK_Factura PRIMARY KEY (Codigo_factura),
  CONSTRAINT FK_Factura_Cliente FOREIGN KEY (Codigo_cliente) REFERENCES Cliente(Codigo_cliente)
);

CREATE TABLE Detalle_Factura (
  Codigo_factura   INT            NOT NULL,
  Codigo_articulo  INT            NOT NULL,
  Cantidad         INT            NOT NULL,
  Importe          DECIMAL(10,2)  NOT NULL,
  CONSTRAINT PK_Detalle_Factura PRIMARY KEY (Codigo_factura, Codigo_articulo),
  CONSTRAINT FK_Detalle_Factura_Factura FOREIGN KEY (Codigo_factura) REFERENCES Factura(Codigo_factura),
  CONSTRAINT FK_Detalle_Factura_Articulo FOREIGN KEY (Codigo_articulo) REFERENCES Articulo(Codigo_articulo)
);
Errores y trampas
  • El total de la factura no se guarda en la cabecera: se calcula sumando el detalle (Unidad 4, SUM). Guardarlo sería repetir un dato.
  • El precio va en el detalle: es el precio de ese día, y el del artículo puede cambiar después.
