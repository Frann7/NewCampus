Administración de datos desde PHP

8. Recibir los datos: $_GET y $_POST

Para qué sirve

Lo primero que tiene que hacer el script del action es recuperar los datos que mandó el formulario. Para eso PHP crea solo, antes de ejecutar el script, unos arreglos con los datos recibidos:

  • $_GET: los pares que llegaron en la URL (formulario con method="get", o un enlace con ?).
  • $_POST: los pares que llegaron en el cuerpo de una solicitud POST (formulario con method="post").
  • $_REQUEST: los dos juntos (sección 9).

Son arreglos asociativos (Clase 2): cada elemento tiene una clave de texto y un valor. Acá la clave es el name del control y el valor es lo que cargó el usuario. Se los llama superglobales: los arma PHP, empiezan con $_ y se pueden usar en cualquier parte del script sin declararlos.

La regla de la cátedra

Si en el formulario definiste method="get", los datos se recuperan desde $_GET.

Si en el formulario definiste method="post", los datos se recuperan desde $_POST.

Sintaxis

$variable = $_GET['nombreDelControl'];
$variable = $_POST['nombreDelControl'];

Qué es cada parte

ParteQué es
$_GET / $_POSTEl arreglo que armó PHP. Cuál usar depende del method del formulario
['nombreDelControl']La clave: tiene que ser exactamente el name del control, con las mismas mayúsculas
El valorSiempre un string (cadena de texto), aunque el usuario haya escrito un número: "25", no 25

a) La URL codificada

PHP decodifica solo: el + vuelve a ser un espacio y %C3%AD vuelve a ser í. 

Array

    [apellido] => Paz

b) password y hidden

La clave llega legible (el password solo la tapaba en pantalla), y el hidden llega con el valor que le puso el programador. El botón no aparece porque no tiene name. Las dos salidas, verificadas mandando esos datos al servidor de PHP.

Ejemplo 4 — La pregunta 7 del parcial

Enunciado (Parcial PHP, preg. 7)

Indique la correcta opción para cada definición (opciones: $_SESSION, $_GET, $_POST):

  1. Es un array asociativo que contiene variables de sesión disponibles para el script actual.
  2. Es un array asociativo de variables pasado al script actual vía parámetros URL.
  3. Es un array asociativo de variables pasadas al script actual a través del método HTTP POST.
DefiniciónLa pistaArreglo
1. "variables de sesión"La palabra sesión. No viene de un formulario: lo guarda el propio servidor entre página y página (Clase 5)$_SESSION
2. "vía parámetros URL"Los datos en la URL son los de GET (sección 5)$_GET
3. "a través del método HTTP POST"Lo dice con todas las letras$_POST
Respuesta

1 → $_SESSION; 2 → $_GET; 3 → $_POST.

Qué imprime

Verificado con el PHP de XAMPP (8.2). No imprime Federico: el dato está en $_POST, no en $_GET. PHP avisa con un Warning (advertencia) que la clave no existe y sigue; el echo no muestra nada. En el navegador el aviso aparece en negrita, con la ruta completa del archivo.

Errores y trampas

Lo que suele salir mal
  • Leer del arreglo equivocado (ejemplo 5): el método del formulario y el arreglo del script tienen que coincidir.
  • La clave no coincide con el name. $_POST['Nombre'] no encuentra name="nombre": las claves distinguen mayúsculas. Da el mismo Undefined array key.
  • Abrir el script directamente (escribiendo su dirección en la barra, sin pasar por el formulario): los arreglos llegan vacíos y aparece un Undefined array key por cada dato. Para preguntar antes si la clave existe está isset(), de la Clase 2: if (isset($_POST['nombre'])) { ... }.
  • $_SESSION no viene del formulario. Es la opción que se mezcla en la pregunta 7; se ve en la Clase 5.
