Ejercicio 1 · Flujo con ramas

De una rama de función a develop y a main

Variante del parcial 2025, Teoría 3. Un desarrollador tiene que agregar el formulario de login. El equipo trabaja con una rama main, una rama develop y una rama por cada función nueva. Indique los pasos para: crear la rama de la función a partir de develop, registrar los cambios, integrarlos en develop y luego en main, dejando todo actualizado en el remoto.

Paso 1 — Qué cambia respecto del parcial

En el parcial los cambios se confirmaban directo en develop. Acá hay una rama más, así que hay un merge más: función → develop → main. La lógica es la misma: confirmar en una rama, subirla, cambiar a la siguiente, fusionar, subir.

Paso 2 — La secuencia 
git checkout develop
git pull origin develop
git checkout -b feature-login

git add .
git commit -m "Agrega el formulario de login"
git push -u origin feature-login

git checkout develop
git merge feature-login
git push origin develop

git checkout main
git merge develop
git push origin main

Paso 4 — Comprobarlo

Lo que respondió Git en las líneas clave:

$ git checkout -b feature-login
Switched to a new branch 'feature-login'

$ git commit -m "Agrega el formulario de login"
[feature-login c44bc36] Agrega el formulario de login
 1 file changed, 1 insertion(+)

$ git push -u origin feature-login
 * [new branch]      feature-login -> feature-login
branch 'feature-login' set up to track 'origin/feature-login'.

$ git merge feature-login
Updating aaf0999..c44bc36
Fast-forward
 login.html | 1 +

$ git push origin develop
   aaf0999..c44bc36  develop -> develop

$ git push origin main
   aaf0999..c44bc36  main -> main

Y el estado final, con git log --oneline -1 --decorate:

c44bc36 (HEAD -> main, origin/main, origin/feature-login, origin/develop, develop) Agrega el formulario de login

Las tres ramas del remoto (origin/main, origin/develop, origin/feature-login) apuntan al mismo commit: todo actualizado.

Respuesta
  1. Actualizar develop y crear la rama de la función: git checkout develop, git pull origin develop, git checkout -b feature-login.
  2. Registrar los cambios en esa rama: git add . y git commit -m "...".
  3. Subirla: git push -u origin feature-login.
  4. Integrarla en develop y subir: git checkout develop, git merge feature-login, git push origin develop.
  5. Integrar en main y subir: git checkout main, git merge develop, git push origin main.
Con pull request

Si el equipo revisa el código antes de integrar, los pasos 4 y 5 no se hacen con git merge en la computadora: después de subir la rama se abre un pull request en GitHub o GitLab, alguien lo revisa y lo aprueba, y la plataforma hace la fusión. Después, cada uno actualiza su copia con git pull.

Al terminar, la rama de la función se puede borrar

git branch -d feature-login la elimina en local y git push origin --delete feature-login en el remoto. Los commits no se pierden: ya están en develop y en main.
