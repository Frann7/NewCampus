2. CMMI: en qué nivel está la empresa

Unidad 5 · CMMI

La empresa NovaSis desarrolla sistemas de gestión y aplicaciones web para clínicas y sanatorios. En la actualidad presenta las siguientes características:

  • Utiliza Git y GitHub para el control de versiones del código y Jira para la gestión de los proyectos.
  • Cuenta con una metodología de desarrollo documentada para toda la organización, que establece cómo se planifican, se prueban y se liberan los proyectos, y todos los equipos la aplican de la misma manera.
  • Los procedimientos y las plantillas están en un repositorio común, y el personal nuevo recibe capacitación en la metodología.
  • Cada líder puede adaptar alguna actividad a las características de su proyecto, pero tiene que dejar justificado el cambio.
  • No realiza mediciones cuantitativas del desempeño de sus procesos: los plazos se estiman según la experiencia de cada líder.
  • La dirección quiere incorporar Inteligencia Artificial (IA) para predecir retrasos y detectar errores antes de cada entrega.
  • No posee rangos de comportamiento esperados ni un mecanismo de mejora continua de sus procesos.

¿En qué nivel de madurez del modelo CMMI se encuentra NovaSis? Justifique con las características del enunciado. ¿Qué riesgos o limitaciones enfrenta si no avanza al siguiente nivel?

Lo que hay que tener de la pregunta 1

Los cinco niveles, con la palabra que resume a cada uno:

NivelEn una frase
Nivel 1 InicialNo hay proceso: depende de las personas
Nivel 2 GestionadoCada proyecto se planifica y se controla, pero cada uno a su manera
Nivel 3 DefinidoUn proceso escrito, igual para toda la organización (estandarizado)
Nivel 4 Cuantitativamente gestionadoEl proceso se mide, y los números se usan para controlar y predecir
Nivel 5 En optimización continuaLos números se usan para mejorar el proceso, siempre

Diagnosticar es leer las características de una empresa y decir hasta qué escalón llegó.

Git, GitHub y Jira: por qué no definen el nivel

  • Git: programa de control de versiones; guarda el historial de cambios del código.
  • GitHub: el sitio donde se sube ese historial para compartirlo con el equipo.
  • Jira: herramienta de gestión de proyectos; un tablero con las tareas y los errores, cada uno con responsable y fecha.

Son herramientas, y aparecen ya en el Nivel 2. Lo que define el nivel es cómo se trabaja, no qué programas se usan: con el mismo Jira, cada equipo puede trabajar a su manera (Nivel 2) o todos seguir el mismo proceso (Nivel 3).

Paso 3 — Los riesgos

El riesgo no se inventa: es lo que le falta para el nivel siguiente, dicho como problema. Se arma en una oración con esta forma:

"Como no [lo que define al nivel siguiente], [qué le pasa por no tenerlo]."

NovaSis está en el 3, y lo que define al 4 es medir. Entonces: "Como no mide sus procesos, decide por experiencia y no con datos: no puede anticipar problemas y sigue estimando 'a ojo'." La primera mitad sale de la definición del nivel; la segunda, de las características del enunciado (ahí dice que los plazos se estiman "según la experiencia de cada líder").

Trampas

  • Usar Git y Jira no sube de nivel: las herramientas ya aparecen en el 2; no hay que justificar el nivel con ellas.
  • Adaptar con justificación no es "cada uno a su manera": sería Nivel 2 si cada equipo tuviera sus propios procedimientos.
  • Lo que la empresa "quiere" hacer no cuenta para el nivel actual: es el paso al siguiente.
