Los ocho juntos

3. ¿Qué patrón es?

Para qué sirve

La Práctica del parcial son dos preguntas: qué patrones usarías en este enunciado y qué patrón implementa este código, las dos justificando. Esta sección junta los ocho patrones en tablas para decidir rápido y sin mezclarlos.

Paso 1 — De qué habla la necesidad

La frase habla de...GrupoCandidatos
Crear objetos: cuántos hay, de qué tipo, quién los instanciaCreacionalSingleton, Factory Method, Abstract Factory
Cómo encajan o se arman las clases: algo no encaja, algo contiene a algo, algo es muy complicado de usarEstructuralAdapter, Composite, Facade
Cómo se comunican o cómo se hace una tarea: avisar, elegir entre formas de hacer algoDe comportamientoObserver, Strategy

Las señales en un código

Primero mirar quién hereda de quién; después, en la clase "del medio" (la que guarda a otras), qué guarda. Con eso alcanza para los ocho.

Lo que se vePatrónNombres típicos en el código
Una clase con constructor privado o protegido, un atributo static que apunta a ella misma y un método static con if (... == nullptr)SingletonGetInstance
Una clase base con un método virtual que devuelve un puntero a otra clase base; subclases que lo resuelven con return new ...; y otro método que lo usaFactory MethodCreator, FactoryMethod, Product
Una interfaz con varios métodos de creación que devuelven distintas clases base; dos o más jerarquías de productosAbstract FactoryAbstractFactory, CreateProductA, CreateProductB
Una clase que hereda de la interfaz del cliente y guarda un puntero a una clase suelta, a la que le traduce las llamadasAdapterTarget, Adaptee, SpecificRequest
Una clase que hereda de una base y guarda una lista de esa misma base; su operación es un bucle sobre los hijos; hay Add/RemoveCompositeComponent, Leaf, children
Ninguna herencia. Varias clases sueltas y una que guarda una de cada una y las llama en orden desde un métodoFacadeSubsystem1, Subsystem2, Operation

Los nombres van a estar cambiados

La cátedra reemplaza los nombres originales para que no delaten al patrón: Facade fue Operador y Pantalla; Adapter fue conversor; Singleton, Inicio_Serie; Observer, alarma; Strategy, dispositivo; Composite, molecula. Los que suelen quedar son los nombres de los métodos (GetInstance, Attach, Notify, Update, SpecificRequest, Operation1) y los textos entre comillas ("initializes subsystems", "Adaptee"). Sirven de confirmación, pero la respuesta se justifica con la forma.

Los que más se confunden

ParLa pregunta que los separa
Factory Method / Abstract Factory¿Se crea un tipo de cosa (FM) o varias que combinan (AF)?
Adapter / Facade¿Se envuelve una clase para darle una interfaz que ya existía (Adapter) o varias para dar una interfaz nueva y simple (Facade)?
Composite / ObserverLos dos tienen lista y bucle. ¿La lista es del mismo tipo que la clase que la tiene y el resultado vuelve (Composite), o es de otra interfaz y solo se avisa (Observer)?
Strategy / Observer¿Guarda una y la puede cambiar (Strategy) o guarda muchas y les avisa (Observer)?
Strategy / Factory Method¿Las variantes son formas de hacer una tarea (Strategy) o de crear un objeto (Factory Method)?
Singleton / FacadeNo se excluyen: Singleton dice cuántos objetos hay; Facade, qué hace esa clase. Una fachada puede ser Singleton.

Ejemplo 1 — Con formato de parcial: un enunciado con tres patrones

Parcial 2025 · Práctica 1

"A partir del siguiente enunciado identifique cuáles serían los patrones de diseño que utilizaría y justifique por qué eligió los mismos."

(El enunciado de Muebles Express S.A., de tres párrafos, está en las secciones 1 y 2 de esta unidad y en la Unidad 4A, sección 2.)

El método: un párrafo, una necesidad, un patrón.

PárrafoLa necesidadLa frasePatrón
1. La compraHay varias formas de configurar un mueble y se elige una según lo que pide el cliente"el sistema aplique automáticamente la estrategia de configuración más adecuada según sus elecciones"Strategy (comportamiento)
2. La producciónCrear distintos tipos de mueble sin que ventas conozca los detalles, y poder agregar tipos"para cada tipo de mueble (...) existe un procedimiento de fabricación específico que permite instanciar los objetos correspondientes"Factory Method (creacional)
3. Los avisosCuando el pedido cambia, el cliente se entera solo"el cliente puede suscribirse para recibir actualizaciones (...) se comunique de forma inmediata y automática"Observer (comportamiento)
Cómo quedaría escrita la respuesta

Strategy, para la personalización: el cliente elige material, color, tamaño y estilo de ensamblaje, y el sistema aplica la estrategia de configuración más adecuada. Cada forma de configurar y presupuestar es una estrategia intercambiable, que se elige en tiempo de ejecución sin modificar el código que la usa.

Factory Method, para la producción: cada tipo de mueble (silla, mesa, estantería, escritorio) tiene su procedimiento de fabricación, que instancia el objeto sin que ventas conozca los detalles. Hay un creador con un método fábrica y un creador concreto por tipo de mueble; agregar un tipo nuevo no afecta la lógica de compra.

Observer, para las notificaciones: el cliente se suscribe a su pedido y el sistema le notifica automáticamente cada cambio de estado, por correo o por la web. El pedido es el notificador y los clientes son los suscriptores.

Las dos trampas de este enunciado
  • "Fabricación" y "muebles" tientan a Abstract Factory, porque su ejemplo de libro es una mueblería. Pero acá no hay familias que deban combinar (estilos): hay tipos de mueble, cada uno con su creador. Es Factory Method.
  • "Personalizar según diferentes parámetros" podría sonar a creación, pero la frase que decide es "la estrategia (...) más adecuada": se elige cómo configurar.

Ejemplo 2 — Reconocer un código en cuatro preguntas

El orden importa: cada pregunta descarta patrones.

  1. ¿Hay algo static y un constructor que no es público?
    Sí → Singleton. No → sigo.
  2. ¿Alguna clase hereda de otra?
    Ninguna → Facade. Alguna → sigo.
  3. ¿Hay métodos cuyo trabajo es devolver un new de otra clase?
    Sí, uno → Factory Method. Sí, varios que devuelven cosas de distinto tipo → Abstract Factory. No → sigo.
  4. La clase que guarda a otras, ¿qué guarda?
    • Un objeto de una clase suelta, de nombre "raro" → Adapter.
    • Una lista de su propio tipo → Composite.
    • Una lista de otra interfaz, con métodos para agregar, quitar y avisar → Observer.
    • Un solo objeto de una interfaz, que se puede cambiar → Strategy.

Probándolo con el código del parcial 2024 (Facturacion, Compras, Operador):

PreguntaRespuestaResultado
1. ¿static y constructor no público?No hay ningún static; el constructor de Operador es públicoNo es Singleton
2. ¿Alguna clase hereda de otra?Ninguna tiene : public ...Facade

Dos preguntas. Después se confirma con el resto: Operador guarda un puntero a cada una de las otras dos y Operation() las llama en orden.

Errores y trampas

La respuesta tiene tres partes

Qué patrón, qué lo delata (la frase del enunciado o los elementos del código) y qué resuelve ahí. Las consignas dicen "justifique" y "explique qué elementos ayudaron a identificarlo": nombrar el patrón solo es media respuesta.

No forzar un patrón por párrafo

El método "un párrafo, una necesidad" sirve para buscar, no es una regla: puede haber un párrafo de contexto sin ningún patrón, o dos necesidades en el mismo. Lo que manda es que cada patrón tenga su frase.
