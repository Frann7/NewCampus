Tenés cambios sin confirmar en el directorio de trabajo. Hay que registrarlos en la rama develop, integrarlos en main y dejar las dos ramas actualizadas en el remoto. ¿Qué secuencia es la correcta?

Inventada · estilo Parcial 2025, Teoría 3

  • git checkout develop → git commit -m "..." → git add . → git push origin develop → git checkout main → git merge develop → git push origin main
  • git checkout develop → git add . → git commit -m "..." → git push origin develop → git checkout main → git merge develop → git push origin main
  • git checkout develop → git add . → git commit -m "..." → git push origin develop → git merge main → git push origin main
  • git checkout main → git add . → git commit -m "..." → git merge develop → git push origin main

Primero se prepara y después se confirma (add antes de commit), parado en develop; se sube develop. Para integrar hay que pararse en la rama que recibe: git checkout main y recién ahí git merge develop. Por último se sube main. La primera invierte add y commit; la tercera hace el merge parado en develop (traería main a develop, al revés); la cuarta confirma directamente en main y nunca sube develop.
