Reconocer varios patrones en un enunciado: la plataforma multimedia

Guía N°2, ejercicio 5. Dado el siguiente enunciado identifique qué patrones se pueden implementar. Una vez identificado, represente el patrón mediante el diagrama de clases implementando los mismos para cada caso.

Una empresa de gestión de contenidos multimedia desea desarrollar una plataforma que permita a sus usuarios organizar, editar y publicar diferentes tipos de archivos digitales (imágenes, videos, documentos, audios). Los usuarios pueden crear colecciones de archivos que a su vez pueden contener otras colecciones, formando una estructura jerárquica que facilita la organización y manejo de grandes cantidades de contenido.

Para simplificar la interacción con el sistema, se requiere una interfaz única que permita realizar operaciones comunes como reproducir, pausar, renombrar o eliminar archivos, sin importar si el usuario está trabajando con un solo archivo o con una colección completa. Además, esta interfaz debe manejar internamente las particularidades de cada tipo de archivo y gestionar la estructura jerárquica de colecciones.

Por otro lado, la plataforma debe integrarse con varias bibliotecas externas para procesamiento y conversión de formatos multimedia (por ejemplo, una biblioteca para edición de imágenes, otra para edición de video y otra para procesamiento de audio). Cada biblioteca tiene una interfaz diferente e incompatible con la del sistema principal.

Finalmente, la empresa quiere que el sistema sea fácil de mantener y ampliar en el futuro, permitiendo agregar nuevos tipos de archivos y servicios externos sin impactar la experiencia del usuario ni la estructura general del código.

Es el enunciado de las guías que más se parece al del parcial 2025: varios párrafos, sin numerar, un patrón escondido en cada uno. Está en la guía de estructurales, así que los tres son estructurales.

Paso 1 — Párrafo por párrafo
PárrafoLa frase que decidePatrón
1"colecciones de archivos que a su vez pueden contener otras colecciones, formando una estructura jerárquica"Composite
2"para simplificar la interacción con el sistema, se requiere una interfaz única que permita realizar operaciones comunes (...) debe manejar internamente las particularidades"Facade
3"integrarse con varias bibliotecas externas (...) cada biblioteca tiene una interfaz diferente e incompatible con la del sistema principal"Adapter
4"agregar nuevos tipos de archivos y servicios externos sin impactar (...) la estructura general del código"No pide un patrón nuevo: es la ventaja de los tres (abierto/cerrado) y sirve para justificar
El segundo párrafo tiene dos pistas mezcladas

"Sin importar si el usuario está trabajando con un solo archivo o con una colección completa" es la otra mitad de Composite (tratar igual a la pieza y al grupo), no un patrón distinto. Lo propio del párrafo 2 es "simplificar" e "interfaz única": Facade.

Paso 2 — Composite: archivos y colecciones
Parte del patrónEn el enunciado
ComponenteElementoMultimedia, con las "operaciones comunes": reproducir, pausar, renombrar, eliminar
HojasImagen, Video, Documento, Audio
CompuestoColeccion, que guarda una lista de ElementoMultimedia (archivos u otras colecciones)

Coleccion.reproducir() recorre sus elementos y le llama reproducir() a cada uno; lo mismo con las otras operaciones.

Paso 3 — Facade y Adapter: la interfaz única y las bibliotecas
PatrónParteEn el enunciado
FacadeFachadaPlataformaMultimedia: la "interfaz única" con las operaciones comunes
SubsistemaLos elementos multimedia y las conversiones, que maneja "internamente"

Respuesta

Composite, porque las colecciones pueden contener archivos y otras colecciones (estructura jerárquica) y las operaciones se aplican igual a un archivo que a una colección completa.

Facade, porque se pide una interfaz única que simplifique la interacción y maneje internamente las particularidades de cada tipo de archivo: el usuario usa solo la fachada.

Adapter, porque cada biblioteca externa tiene una interfaz diferente e incompatible con la del sistema: un adaptador por biblioteca las hace cumplir la interfaz que el sistema espera, sin modificarlas.

Con los tres se cumple el último párrafo: un tipo de archivo nuevo es otra hoja y un servicio externo nuevo es otro adaptador, sin tocar el código existente.

Facade y Adapter, juntos y sin pisarse

Es el mejor ejemplo para ver la diferencia. Los adaptadores miran hacia afuera: cada uno envuelve una biblioteca ajena para que encaje. La fachada mira hacia el usuario: junta todo el sistema detrás de unas pocas operaciones simples.
