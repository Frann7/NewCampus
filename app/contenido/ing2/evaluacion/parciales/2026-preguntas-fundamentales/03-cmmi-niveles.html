Qué es

CMMI (Capability Maturity Model Integration, del Software Engineering Institute) es un modelo de madurez: una herramienta para evaluar y mejorar los procesos de una organización. Se dibuja como una escalera de cinco escalones, porque cada nivel se construye sobre el anterior y no se saltea ninguno.

La regla para acordarse del orden

Cada escalón agrega una sola cosa, y el orden no puede ser otro: ordenar → igualar → medir → mejorar.

PasoQué apareceEl nombre lo dicePor qué va en ese lugar
1 → 2Ordenar cada proyecto: plan, responsables, seguimientoGestionado: el proyecto se gestionaEs lo primero: antes no hay nada, cada uno hace lo que puede
2 → 3Igualar: un proceso común, documentado, para toda la organizaciónDefinido: el proceso está definido por escritoPara que todos trabajen igual, primero cada proyecto tiene que estar ordenado
3 → 4Medir: métricas del proceso, para controlar y predecirCuantitativo: con cantidades, con númerosNo se puede medir "el proceso" si cada equipo tiene el suyo
4 → 5Mejorar: los datos se analizan para innovar y optimizarOptimización continua: mejorar siempreSin números no se sabe qué mejorar ni si la mejora sirvió

"Existe una metodología organizacional y se capacita a los integrantes en ella."Nivel 3
"Se establecieron rangos de comportamiento esperados a partir de datos históricos."Nivel 4
"Un grupo analiza las causas de los problemas recurrentes y propone cambios a los procedimientos."Nivel 5

El 2 y el 3, que son los que más se confunden

En los dos hay orden. La pregunta que los separa es: ¿todos los equipos trabajan de la misma manera? Si cada equipo usa sus propios procedimientos, es Nivel 2, por más ordenado que esté cada proyecto. Si hay una forma de trabajar documentada para toda la empresa, y se capacita a la gente en ella, es Nivel 3.

Trampas

  • Tener datos no es estar en el Nivel 4: juntar indicadores en un informe no alcanza; es Nivel 4 cuando los números se usan para controlar y predecir (rangos esperados, alertas).
  • El 4 no es el 5: en el 4 los datos sirven para volver a lo esperado; en el 5, para cambiar el proceso y mejorarlo.
  • Usar Git y Jira no es un nivel: las herramientas ya aparecen en el 2; el nivel lo define cómo se trabaja.
