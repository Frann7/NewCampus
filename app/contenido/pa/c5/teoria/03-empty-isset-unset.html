Sesiones

3. empty, isset y unset: preguntar, borrar y cerrar

Para qué sirve

Los ejemplos de la cátedra hacen todo el tiempo dos cosas con la sesión:

  • Preguntar si un dato está antes de usarlo: if (!empty($_SESSION['rand_code'])).
  • Borrar un dato que ya no sirve: unset($_SESSION['rand_code']);.

Estas son las tres funciones que lo hacen.

Sintaxis

Las tres 
empty($_SESSION['clave'])   // true si no existe o está "vacía"
isset($_SESSION['clave'])   // true si existe y no es null
unset($_SESSION['clave']);  // borra esa clave del arreglo

Qué es cada parte

FunciónQué devuelve o hace
empty($x)true si $x no existe o vale algo "vacío": "", "0", 0, null, false o un arreglo sin elementos. Si la variable no existe no da Warning: por eso se usa para preguntar.
!empty($x)El ! (no, Clase 1) da vuelta el resultado: true si hay algo.
isset($x)true si $x existe y no es null, aunque valga "" o 0 (Clase 2).
unset($x)Borra la variable o la clave. No devuelve nada. Después, isset da false y empty da true.

Dónde se separan empty e isset

Se probó cada valor con las dos funciones:

Valor de $xempty($x)isset($x)
no existetruefalse
"" (texto vacío)truetrue
"0"truetrue
0truetrue
array() (vacío)truetrue
" " (un espacio)falsetrue

Regla corta: isset pregunta "¿existe?"; empty pregunta "¿hay algo que sirva?". Para un formulario, empty es la útil: un campo que llegó en blanco existe, pero está vacío.

Cerrar la sesión entera

El material de la clase solo borra claves sueltas con unset. Para terminar la sesión completa (por ejemplo, un botón "Salir") PHP tiene session_destroy(), que borra el archivo de la sesión en el servidor. Se probó que no vacía $_SESSION en el script donde se llama: los datos siguen ahí hasta que el script termina, y recién el próximo pedido encuentra la sesión vacía. Por eso se lo acompaña con $_SESSION = array();: 

<?php
session_start();
$_SESSION = array();   // vacía el arreglo ya mismo
session_destroy();     // borra el archivo de la sesión en el servidor
?>

Ejemplo 1 — Un contador de visitas

Enunciado

contador.php tiene el código de abajo. ¿Qué muestra la primera, la segunda y la tercera vez que el mismo navegador lo abre?

<?php
session_start();
if (isset($_SESSION['visitas'])) {
    $_SESSION['visitas'] = $_SESSION['visitas'] + 1;
} else {
    $_SESSION['visitas'] = 1;
}
echo 'Visita número ' . $_SESSION['visitas'];
?>

Ejemplo 2 — ¿Cuál es la salida? (formato del parcial)

Enunciado

¿Cuál es la salida del siguiente script PHP, si la sesión empieza vacía?

<?php
session_start();
$_SESSION['a'] = 'uno';
$_SESSION['b'] = 'dos';
unset($_SESSION['a']);
echo count($_SESSION) . ' ';
var_dump(empty($_SESSION['a']));
?>

Qué hace cada línea

LíneaQué haceCómo queda $_SESSION
$_SESSION['a'] = 'uno';Crea 'a'.['a' => 'uno']
$_SESSION['b'] = 'dos';Crea 'b'.['a' => 'uno', 'b' => 'dos']
unset($_SESSION['a']);Borra la clave 'a' con su valor.['b' => 'dos']
echo count($_SESSION) . ' ';Queda un elemento: imprime 1 y un espacio.sin cambios
var_dump(empty($_SESSION['a']));'a' ya no existe, así que empty da true (sin Warning). var_dump muestra el tipo y el valor: bool(true).sin cambios

Qué imprime y por qué

1 bool(true)

unset no deja la clave "vacía": la saca del arreglo. Por eso count da 1 y no 2.

Errores y trampas

Lo que más se confunde
  • "0" cuenta como vacío. Si alguien escribe 0 en un campo, empty da true. Si el 0 es un dato válido, usá isset o compará con "".
  • unset no es session_destroy. unset borra una clave y la sesión sigue; session_destroy borra la sesión entera.
  • session_destroy() no vacía $_SESSION al instante: en el mismo script los datos siguen leyéndose. Por eso va con $_SESSION = array();.
