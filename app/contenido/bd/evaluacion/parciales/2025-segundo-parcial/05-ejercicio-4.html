Ejercicio 4: Utilizando lenguaje SQL, crear la tabla de Animales, con sus atributos y claves correspondientes.

✓ ResultadosSolo la respuesta 
CREATE TABLE Animal (
  NumeroHC   INT           NOT NULL,
  Nombre     VARCHAR(50)   NOT NULL,
  Raza       VARCHAR(50),
  Sexo       CHAR(1),
  FechaNac   DATE,
  Peso       DECIMAL(5,2),
  Documento  VARCHAR(13)   NOT NULL,
  PRIMARY KEY (NumeroHC),
  FOREIGN KEY (Documento) REFERENCES Propietario(Documento)
);

La tabla Propietario tiene que estar creada antes.

✎ Explicación detalladaColumna por columna, las claves y las trampas

Qué evalúa

Escribir un CREATE TABLE (Unidad 3) con tipos razonables y, sobre todo, con sus claves: la PK y la FK al propietario. Sale de la tabla del ejercicio 3: 

Animal (NumeroHC (PK), Nombre, Raza, Sexo, FechaNac, Peso, Documento (FK))
Propietario (Documento (PK), Nombre, Direccion, IdCiudad (FK))
Paso 1 — El tipo de cada columna
ColumnaDel enunciadoTipo
NumeroHC"número de historia clínica (único)": entero, y es la PKINT NOT NULL
NombreTexto; todo animal tiene nombreVARCHAR(50) NOT NULL
RazaTextoVARCHAR(50)
SexoUna letra: M o HCHAR(1)
FechaNac"fecha de nacimiento": fecha sin horaDATE
PesoKilos con decimales (hasta 999,99)DECIMAL(5,2)
DocumentoEl propietario. "DNI o CUIT": texto, para que entren los guiones. Mismo tipo que Propietario.Documento, y obligatorio: el animal tiene (1,1) en "es dueño"VARCHAR(13) NOT NULL
Paso 2 — Las claves 
  PRIMARY KEY (NumeroHC),
  FOREIGN KEY (Documento) REFERENCES Propietario(Documento)
  • PRIMARY KEY (NumeroHC): no se repite y no queda vacía.
  • FOREIGN KEY ... REFERENCES Propietario(Documento): no se puede cargar un animal de un dueño que no existe.
Resolución 
CREATE TABLE Animal (
  NumeroHC   INT           NOT NULL,
  Nombre     VARCHAR(50)   NOT NULL,
  Raza       VARCHAR(50),
  Sexo       CHAR(1),
  FechaNac   DATE,
  Peso       DECIMAL(5,2),
  Documento  VARCHAR(13)   NOT NULL,
  PRIMARY KEY (NumeroHC),
  FOREIGN KEY (Documento) REFERENCES Propietario(Documento)
);

Trampas

  • "Con sus claves correspondientes": sin la FOREIGN KEY la respuesta queda incompleta.
  • El tipo de Documento tiene que ser el mismo que el de la PK de Propietario.
  • El peso en INT pierde los decimales; el sexo como VARCHAR(20) no está mal, pero CHAR(1) es lo justo.
