2. Las claves y las restricciones

Una restricción (constraint) es una regla que el SGBD hace cumplir solo: si un INSERT o un UPDATE la viola, lo rechaza. En la clase del 13/08 la definieron como las características o modificadores adicionales de una tabla: la PK, las FK, el valor por defecto.

La forma de la cátedra: cada clave con su nombre 
CONSTRAINT PK_Tabla PRIMARY KEY (Columna)
CONSTRAINT FK_Tabla_Otra FOREIGN KEY (Columna) REFERENCES Otra(SuPK)
  • Van al final del CREATE TABLE, después de las columnas, separadas por coma.
  • CONSTRAINT nombre le pone nombre propio a la clave. Los profes lo prefieren: si se deja que el motor lo invente, sale un nombre con números al azar y después cuesta cambiarla con un ALTER. Se usa PK_ + la tabla y FK_ + las dos tablas.
  • En clase lo escriben PRIMARY KEY CLUSTERED (Columna): CLUSTERED se puede omitir, porque en SQL Server la PK ya es así por defecto.
  • Escribir Codigo INT NOT NULL PRIMARY KEY en la misma columna también funciona ("no va a estar mal"), pero no deja ponerle nombre ni armar una clave compuesta.
RestricciónCómo se escribeQué hace cumplir
NOT NULLAl lado del tipo: Nombre VARCHAR(50) NOT NULL. Si no se pone, la columna admite nulosLa columna no puede quedar vacía
Clave primariaCONSTRAINT PK_Zona PRIMARY KEY (Codigo)No se repite y no queda vacía
Clave primaria compuestaCONSTRAINT PK_Cuidador_Especie PRIMARY KEY (Legajo, CodigoEspecie)No se repite el par (cada columna sola sí puede repetirse)

DEFAULTAl lado del tipo: Activo SMALLINT DEFAULT 0El valor que toma si en el INSERT no se lo carga
IDENTITY(1,1)Al lado del tipo: Id INT IDENTITY(1,1)El SGBD numera solo: 1, 2, 3... (no se carga a mano)

Cómo se lee una FOREIGN KEY

CONSTRAINT FK_Especie_Zona FOREIGN KEY (CodigoZona) REFERENCES Zona(Codigo)
  • (CodigoZona): la columna de esta tabla.
  • REFERENCES Zona(Codigo): la tabla a la que apunta, y su PK entre paréntesis.
  • Se lee: "CodigoZona tiene que ser un Codigo que ya exista en Zona". Las dos columnas tienen que ser del mismo tipo.
  • La tabla a la que apunta tiene que estar creada antes (sección 3). Por eso el script de Northwind de la cátedra agrega las FK al final con ALTER TABLE ... ADD CONSTRAINT; los profes aclararon que también se pueden poner adentro del CREATE TABLE, sin el ALTER.

Ejemplo 1: una tabla con FK

Especie (Codigo (PK), Nombre, NombreCientifico, Descripcion, CodigoZona (FK)) — la FK apunta a Zona (Codigo (PK), Nombre, Extension).

CREATE TABLE Especie (
  Codigo            INT           NOT NULL,
  Nombre            VARCHAR(50)   NOT NULL,
  NombreCientifico  VARCHAR(100),
  Descripcion       VARCHAR(250),
  CodigoZona        INT           NOT NULL,
  CONSTRAINT PK_Especie PRIMARY KEY (Codigo),
  CONSTRAINT FK_Especie_Zona FOREIGN KEY (CodigoZona) REFERENCES Zona(Codigo)
);
  • CodigoZona es INT porque Zona.Codigo es INT.
  • Es NOT NULL porque en el DER la especie tiene (1,1): siempre está en una zona.

Ejemplo 2: una tabla intermedia (PK compuesta)

Cuidador_Especie (Legajo (PK)(FK), CodigoEspecie (PK)(FK), FechaDesde) — apunta a Cuidador (Legajo) y a Especie (Codigo).

CREATE TABLE Cuidador_Especie (
  Legajo         INT   NOT NULL,
  CodigoEspecie  INT   NOT NULL,
  FechaDesde     DATE  NOT NULL,
  CONSTRAINT PK_Cuidador_Especie PRIMARY KEY (Legajo, CodigoEspecie),
  CONSTRAINT FK_Cuidador_Especie_Cuidador FOREIGN KEY (Legajo) REFERENCES Cuidador(Legajo),
  CONSTRAINT FK_Cuidador_Especie_Especie FOREIGN KEY (CodigoEspecie) REFERENCES Especie(Codigo)
);
  • Una sola PRIMARY KEY con las dos columnas: no son dos claves primarias, es una compuesta.
  • Y dos FOREIGN KEY, una por cada tabla a la que apunta.

Ejemplo 3: una PK numerada sola

Pais (IdPais (PK), Nombre), donde el código no viene de ningún lado y se quiere que SQL Server lo asigne.

CREATE TABLE Pais (
  IdPais  INT  IDENTITY(1,1)  NOT NULL,
  Nombre  VARCHAR(50)  NOT NULL,
  CONSTRAINT PK_Pais PRIMARY KEY (IdPais),
  CONSTRAINT UQ_Pais_Nombre UNIQUE (Nombre)
);

IDENTITY(1,1) = empieza en 1 y suma de a 1. UNIQUE (Nombre) evita cargar "Argentina" dos veces (el TP final lo usó igual).

Errores y trampas
  • Si la consigna dice "con sus claves correspondientes", la FK no es opcional: sin el FOREIGN KEY ... REFERENCES, la tabla queda suelta.
  • Una PK compuesta se escribe PRIMARY KEY (A, B), no dos veces PRIMARY KEY.
  • Después de REFERENCES va el nombre de la tabla y, entre paréntesis, su columna PK.
  • No se pone IDENTITY en una FK: la FK copia un valor que ya existe en otra tabla.
