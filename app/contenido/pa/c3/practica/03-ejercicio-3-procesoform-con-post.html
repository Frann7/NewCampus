Ejercicio 3 · $_POST

Mostrar los datos recibidos: procesoForm.php

Escriba el código HTML y PHP necesario para mostrar los datos recibidos del formulario del punto 2. Guarde el script con el nombre procesoForm.php y asegúrese de ser el mismo nombre declarado en el campo "action" declarado en el formulario. Utilice para recuperar los datos el arreglo $_POST de PHP.

La captura muestra el título "Datos enviados desde el Formulario de Contacto", los cuatro rótulos con lo que se cargó (federico, consulta, federico@gugler.com.ar, Este es el comentario) y el enlace "Volver".

Paso 1 — Qué piden
  • El nombre del archivo tiene que coincidir con el action del ejercicio 2: procesoForm.php, en la misma carpeta (ruta relativa, sección 7).
  • Como el formulario usa method="post", los datos están en $_POST (sección 8). Las claves son los name del formulario: nombre, asunto, correo, comentario.
  • "Código HTML y PHP": la página es HTML, y PHP solo pone los datos en su lugar. Es el funcionamiento de la Clase 1: lo que está fuera de <?php ?> sale tal cual y lo de adentro se ejecuta.
  • Lo que muestra lo escribió el usuario, así que se pasa por htmlspecialchars() (sección 10) antes de imprimirlo.
Paso 2 — El código 
<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Datos enviados</title>

<body>
  <h1>Programación Avanzada</h1>
  <h2>Taller de PHP</h2>

  <?php
    $nombre     = $_POST['nombre'];
    $asunto     = $_POST['asunto'];
    $correo     = $_POST['correo'];
    $comentario = $_POST['comentario'];
  ?>

  <table>
    <tr><td>Nombre:</td><td><?php echo htmlspecialchars($nombre); ?></td></tr>
    <tr><td>Asunto:</td><td><?php echo htmlspecialchars($asunto); ?></td></tr>
    <tr><td>Correo:</td><td><?php echo htmlspecialchars($correo); ?></td></tr>
    <tr><td>Comentario:</td><td><?php echo htmlspecialchars($comentario); ?></td></tr>
  </table>

  <p><a href="index.php">Volver</a></p>

  <p>Facultad de Ciencia y Tecnología</p>
</body>
</html>
Paso 3 — Qué hace cada línea

Con los datos de la captura. Antes de la primera línea, PHP ya armó $_POST con el cuerpo de la solicitud (y decodificó el %40 y los +): $_POST = ['nombre' => 'federico', 'asunto' => 'consulta', 'correo' => 'federico@gugler.com.ar', 'comentario' => 'Este es el comentario'].

Fijate que las etiquetas <?php ... ?> desaparecieron: el navegador nunca ve el código PHP, solo lo que imprimió. Donde estaba el bloque de las líneas 13 a 18 quedó un renglón en blanco, porque no imprimía nada.

Qué se ve en el navegador

El encabezado, el título "Datos enviados desde el Formulario de Contacto", la tabla con Nombre: federico, Asunto: consulta, Correo: federico@gugler.com.ar, Comentario: Este es el comentario, y el enlace Volver. Es la captura de la guía.

Si abrís procesoForm.php directamente

Escribiendo http://localhost/clase3/procesoForm.php en la barra, sin pasar por el formulario, la solicitud es un GET sin datos: $_POST está vacío. Verificado: PHP muestra cuatro avisos, uno por línea 14 a 17, del tipo 

Warning: Undefined array key "nombre" in ...\procesoForm.php on line 14

y la tabla sale con las celdas vacías. No es un error del código: el script espera que lo llame el formulario. Si se quisiera evitar, se pregunta antes con if ($_SERVER["REQUEST_METHOD"] == "POST") (sección 10), como hace el sitio de ejemplo de la cátedra.

Por qué htmlspecialchars

Con estos datos, la salida es la misma con o sin htmlspecialchars(). La diferencia aparece si alguien escribe etiquetas en el comentario: sin la función, un <b> pondría el texto en negrita y un <script> se ejecutaría en la página (sección 10). El ejercicio no lo pide; el sitio de ejemplo de la cátedra lo usa en cada dato que muestra.

Resultado

procesoForm.php recupera los cuatro datos de $_POST y los muestra en una tabla, igual que la captura de la guía. La cátedra no publicó una resolución para comparar.
