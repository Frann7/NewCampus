6. Altas, bajas y modificaciones

Para qué sirve

La guía dice que en esta clase se ven las funciones para hacer altas, bajas y modificaciones de los datos (en la jerga, un ABM): agregar una fila, borrarla o cambiarla. Se hace con el mismo query() de la sección 4; lo que cambia es la instrucción SQL. Y cuando los datos vienen de un formulario, hay una forma más segura: las consultas preparadas, que son las que usa el sitio de ejemplo de la cátedra.

Sintaxis: las tres instrucciones SQL

INSERT INTO personas (documento, apellido, nombres) VALUES (33444555, 'Pérez', 'Ana')

UPDATE personas SET nombres = 'Fede' WHERE idPersona = 2

DELETE FROM personas WHERE idPersona = 3
InstrucciónQué haceQué es cada parte
INSERT INTOAlta: agrega una filaEntre paréntesis, las columnas; después de VALUES, los valores en el mismo orden. El id autoincremental no se manda: lo pone la base
UPDATE ... SETModificación: cambia columnas de las filas que cumplen el WHERESET columna = valor, separados por coma si son varios
DELETE FROMBaja: borra las filas que cumplen el WHERESin WHERE borra todas

Con estas, query() devuelve true si anduvo, y la conexión deja dos datos útiles:

PropiedadQué tiene
$mysqli->affected_rowsCuántas filas agregó, cambió o borró la última instrucción
$mysqli->insert_idEl id que la base le puso a la última fila agregada

Sintaxis: consulta preparada

En vez de pegar los datos adentro del texto SQL, se dejan signos ? en su lugar y los datos se mandan aparte: 

$stmt = $mysqli->prepare("INSERT INTO personas (documento, apellido, nombres) VALUES (?, ?, ?)");
$stmt->bind_param("iss", $documento, $apellido, $nombres);
$stmt->execute();
$stmt->close();
ParteQué es
prepare(sql)Le manda a la base la instrucción con los huecos. Devuelve un objeto sentencia (en inglés, statement; de ahí $stmt), o false si el SQL está mal escrito
?Un hueco donde va un dato. Sin comillas, aunque el dato sea texto
bind_param(tipos, vars...)"Ata" una variable a cada hueco, en orden. El primer parámetro es un string con una letra por hueco
las letras de tipoi = entero, d = número con decimales, s = string, b = datos binarios. "iss" = un entero y dos strings
execute()Ejecuta la instrucción con los datos. Devuelve true o false
$stmt->affected_rowsIgual que en la conexión: cuántas filas tocó
$stmt->close()Libera la sentencia (la conexión sigue abierta)

Ejemplo 1 — Un alta con query()

Enunciado

Agregar a Ana Pérez, documento 33444555, a la tabla de ejemplo, y mostrar qué id le tocó.

<?php
$mysqli = new mysqli('127.0.0.1', 'root', '', 'Personal');

$sql = "INSERT INTO personas (documento, apellido, nombres) VALUES (33444555, 'Pérez', 'Ana')";

if ($mysqli->query($sql))
{
    echo "Filas agregadas: " . $mysqli->affected_rows . "<br>";
    echo "Id nuevo: " . $mysqli->insert_id;
}

$mysqli->close();
?>
LíneaQué haceCómo quedan las variables
2Abre la conexión$mysqli = la conexión
4Arma el INSERT. El número va sin comillas; los textos, con comillas simples$sql = la instrucción
6La ejecuta. Un INSERT que anduvo devuelve true: entrala tabla pasa a tener 4 filas
8Muestra cuántas filas agregóaffected_rows = 1
9Muestra el id que puso la baseinsert_id = 4 (venía de 1, 2, 3)
12Cierra la conexión

Qué imprime, con la tabla de ejemplo recién creada:

Filas agregadas: 1<br>Id nuevo: 4

En pantalla, dos renglones. Si antes se habían borrado filas, el id puede ser mayor: el autoincremento no reutiliza números.

Ejemplo 2 — ¿Cuál es la salida? Modificar y borrar

Enunciado

Con la tabla de ejemplo de la sección 2 (sin Ana Pérez) y la conexión abierta, ¿cuál es la salida?

<?php
$id = 2;
$nuevo = 'Fede';

$stmt = $mysqli->prepare("UPDATE personas SET nombres = ? WHERE idPersona = ?");
$stmt->bind_param("si", $nuevo, $id);
$stmt->execute();
echo $stmt->affected_rows . " - ";
$stmt->close();

$apellido = 'Gómez';
$stmt = $mysqli->prepare("DELETE FROM personas WHERE apellido = ?");
$stmt->bind_param("s", $apellido);
$stmt->execute();
echo $stmt->affected_rows;
$stmt->close();
?>
LíneaQué haceCómo quedan las variables
2-3Los datos$id = 2; $nuevo = 'Fede'
5Prepara un UPDATE con dos huecos$stmt = la sentencia
6Primer hueco: $nuevo como string (s); segundo: $id como entero (i)
7Ejecuta: UPDATE personas SET nombres = 'Fede' WHERE idPersona = 2Federico pasa a Fede
8Imprime cuántas filas cambióaffected_rows = 1
11-14Prepara y ejecuta un DELETE de los apellido Gómezno hay ningún Gómez: no borra nada
15Imprime cuántas borróaffected_rows = 0
Respuesta (con la tabla de ejemplo) 
1 - 0

Un DELETE que no encuentra nada no es un error: anduvo y borró cero filas. Para saber si de verdad borró algo, se mira affected_rows.

Ejemplo 3 — Por qué no pegar los datos en el SQL

Enunciado

Un buscador arma el SQL pegando lo que el usuario escribió en el formulario. ¿Qué texto SQL se arma si escribe Bonnet? ¿Y si escribe x' OR '1'='1? 

<?php
$apellido = $_GET['apellido'];
$sql = "SELECT * FROM personas WHERE apellido = '" . $apellido . "'";
echo $sql;
?>
LíneaQué haceCómo quedan las variables
2Toma lo que vino del formulario (los arreglos $_GET/$_POST de la Clase 3)$apellido = lo que escribió
3Concatena: comilla de apertura, el dato, comilla de cierre$sql = el texto armado

Qué imprime (verificado) con Bonnet:

SELECT * FROM personas WHERE apellido = 'Bonnet'

Y con x' OR '1'='1:

SELECT * FROM personas WHERE apellido = 'x' OR '1'='1'

La comilla que escribió el usuario cerró el texto antes de tiempo, y lo que sigue pasó a ser SQL: "apellido es x, o 1 es igual a 1". Como 1 siempre es igual a 1, la condición se cumple en todas las filas y la consulta trae la tabla entera. Esto se llama inyección SQL: el usuario mete instrucciones propias por un campo de texto. Con un DELETE armado igual, podría borrar todo.

Con una consulta preparada no pasa: el dato viaja aparte del SQL, así que la base busca literalmente a alguien de apellido x' OR '1'='1 y no encuentra a nadie. La Clase 5 atacaba el mismo problema desde el otro lado, validando con las funciones ctype_ antes de guardar; las dos cosas se combinan.

Errores y trampas
  • UPDATE o DELETE sin WHERE cambia o borra todas las filas, y no hay papelera.
  • Los tipos de bind_param van en el orden de los ?, uno por hueco. Si sobran o faltan letras, da error.
  • Los ? van sin comillas: '?' sería el texto "signo de pregunta", no un hueco.
  • Un UPDATE que pone el mismo valor que ya había da affected_rows = 0: la base no cuenta como cambiada una fila que quedó igual.
