Para muchas aplicaciones, un proceso necesita acceso exclusivo no sólo a un recurso, sino a varios. Si tenemos dos procesos, A y B, y el proceso A esta usando el recurso W y el proceso B esta usando el recurso X; Posteriormente, el proceso A solicita permiso al SO para usar el recurso X y el proceso B pide permisos para usar el recurso W.
En este punto ambos procesos están bloqueados y permanecerán así para siempre. A esta situación se le conoce como interbloqueo.

Qué evalúa

Qué es un interbloqueo, con el ejemplo de Tanenbaum (en el libro, un escáner y una grabadora de CD).

Por qué es verdadero

Es el ejemplo clásico: A tiene W y espera X; B tiene X y espera W. Ninguno suelta lo que tiene, así que los dos esperan para siempre.

Se cumplen las cuatro condiciones de Coffman (pregunta 5): cada recurso es de uno solo (exclusión mutua), cada uno retiene un recurso mientras pide otro (contención y espera), nadie les quita el recurso (no apropiativa) y la espera forma un ciclo A → X → B → W → A (espera circular).
